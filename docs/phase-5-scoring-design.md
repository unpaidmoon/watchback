# 第五阶段评分与标签设计

本文档整理第五阶段的正式产品设计。目标是基于现有 preset/open 对局数据，为战绩列表、对局详情、赛季回顾、好友组排分析提供一套偏正向、可解释、可缓存的评分与标签体系。

## 设计目标

- 让用户在战绩列表里快速看到本局表现结论。
- 用等级和标签取代裸露的 0-100 分，降低压力感。
- 优先寻找合理的正向解释，产品目标是取悦用户和帮助复盘，不是严格裁判。
- 让标签能进入列表筛选、赛季回顾和好友组排分析。
- 评分结果缓存到 SQLite，保证列表读取稳定且便于后续规则版本重算。

## 范围

当前阶段只分析 preset/open 模式。

不纳入当前阶段：

- stadium/fight 模式评分。
- 公开排行榜或跨玩家排名。
- 完整五人阵容默认分析。
- AI 生成长文本复盘。
- 0-100 分公开展示。

preset/open 第一版使用同一套评分规则，但评分缓存保留 `mode`，以后可以拆分 preset 和 open 的规则。

## 数据来源

评分使用现有原始字段和投影数据：

- `matches.entries[]`: 对局摘要。
- `matches.details[]`: 对局详情。
- `match_players`: 从 `match_details` 重建的玩家行投影。
- `friendBnetIds`: 好友身份来源。

关键字段：

- 对局身份：`matchId`, `season`, `gameMode`, `beginTs`
- 地图和英雄：`mapGuid`, `mapName`, `heroGuid`, `heroName`
- 结果：`matchRet`, `teamScore`, `opponentScore`
- 玩家统计：`kill`, `assist`, `death`, `heroDamage`, `cure`, `resistDamage`, `targetCompetingTime`

胜负判断必须使用导入器归一化后的结果，不直接依赖原始 `matchRet`。好友身份只能来自 `friendBnetIds`，不能根据重复队友推断。

## 展示模型

战绩列表默认展示：

- 等级：`S`, `A`, `B`, `C`
- 一个主标签
- 最多两个证据标签

详情页第一版只展示标签，不展示完整评分原因。后端仍保存内部 `reasons`，用于测试、调试和后续扩展。

未评分对局隐藏评分区域，不显示“未评分”。

平局或结果未知不显示评分标签。

## 主标签规则

每局最多一个主标签。

主标签由胜负结果和个人数据强弱决定：

| 条件 | 主标签 |
| --- | --- |
| 赢 + 自己数据好 | 带飞局 |
| 赢 + 自己数据差 | 躺赢局 |
| 输 + 自己数据好 | 尽力局 |
| 输 + 自己数据差 | 背锅局 |
| 赢 + 中间态 | 顺风局 |
| 输 + 中间态 | 惜败局 |

数据不足时降级：

| 条件 | 降级标签 |
| --- | --- |
| 胜利但无法做本队排名 | 胜利局 |
| 失败但无法做本队排名 | 失败局 |
| 平局或结果未知 | 不显示评分标签 |

`躺赢局` 和 `背锅局` 可以直接显示，但必须由更强证据触发。负面标签应少于正向标签。

## 数据好坏判定

第一版只使用本队内排名判断个人数据强弱，不强依赖个人历史均值、同英雄均值或同地图均值。

核心指标：

- `heroDamage`: 伤害
- `kill`: 击杀
- `cure`: 治疗
- `resistDamage`: 格挡
- KDA: `(kill + assist) / max(death, 1)`

死亡为 0 时，KDA 按死亡为 1 计算。

数据好：

- 任一核心指标本队第一，即可视为数据好。

数据差：

- 没有任何核心指标本队第一。
- 且死亡数是本队唯一最高。

这个规则有意让正向标签更容易出现，让负面标签更少触发。

## 证据标签

证据标签用于解释主标签，但不覆盖主标签。第一版最多展示两个证据标签。

个人荣誉证据标签：

- `KDA最高`
- `击杀最多`
- `伤害最高`
- `治疗最高`
- `格挡最多`

这些标签只和本队队友比较，不做全场比较。

展示优先级：

1. `KDA最高`
2. `击杀最多`
3. `伤害最高`
4. `治疗最高`
5. `格挡最多`
6. `翻盘局`
7. `伯仲局`

后端可以计算并保存更多证据标签，UI 第一版只显示优先级最高的两个。

## 比赛性质标签

比赛性质标签作为附加标签展示，不覆盖个人表现主标签。

### 翻盘局

判定条件：

- 本局胜利。
- 己方总击杀低于敌方总击杀。

展示方式：

- 作为附加证据标签显示。
- 不作为主标签。

### 伯仲局

判定条件：

- 双方总击杀差不超过 2。
- 双方总伤害差距不超过 10%。

展示方式：

- 低优先级附加标签。
- 只有在没有更强附加标签或列表不拥挤时展示。

## 等级规则

第一版不公开 0-100 分。等级由主标签和核心证据数量决定。

| 条件 | 等级 |
| --- | --- |
| 带飞局或尽力局，且核心证据标签不少于 2 个 | S |
| 带飞局或尽力局，且核心证据标签为 1 个 | A |
| 顺风局或惜败局 | B |
| 躺赢局或背锅局 | C |
| 胜利局或失败局 | B |

内部后续可以增加数值分，用于排序、趋势和阈值调优，但第一版 UI 不展示。

## 连胜与连败

连胜/连败不作为单局标签。

规则：

- 3 场及以上连续胜利显示连胜。
- 3 场及以上连续失败显示连败。

战绩列表按时间倒序时，连胜/连败标签放在连续段最上方，语义是“下面这些对局组成这一段连胜/连败”，不强调被上一局终结。

文案只写结果：

- `3连胜`
- `5连败`

## 列表筛选

战绩列表第一版只支持主标签单选筛选。

筛选项：

- 带飞局
- 尽力局
- 躺赢局
- 背锅局

不进入筛选：

- 顺风局
- 惜败局
- 胜利局
- 失败局
- KDA最高、击杀最多等证据标签
- 翻盘局、伯仲局

## 缓存设计

评分结果缓存到 SQLite，不只在读取时临时计算。

计算时机：

- 导入数据时计算评分缓存。
- 导入不应因为评分失败而失败。
- 评分失败的对局标记为未评分，列表隐藏评分区域。

规则版本：

- 缓存必须包含评分规则版本。
- 打开战绩页时检测旧版本评分，并在后台重算。
- UI 可以先展示旧缓存或基础战绩，重算完成后刷新。

第一版缓存字段：

- `match_id`
- `mode`
- `rule_version`
- `grade`
- `primary_tag`
- `evidence_tags_json`
- `reasons_json`
- `confidence`
- `computed_at`

缓存保存内部 `reasons`，即使第一版 UI 不展示完整原因。

## 好友常用英雄

好友组排分析只统计 preset/open。

每个好友聚合：

- 好友 `bnetId`
- 好友名称
- 代表英雄
- 组排场次
- 胜率
- 最近使用时间

展示规则：

- 好友按组排场次排序。
- 最多显示 5 个好友。
- 好友至少 3 场组排才展示。
- 每个好友只显示 1 个代表英雄。
- 代表英雄按出场次数选择。
- 如果多个英雄出场次数并列，选最近使用的英雄。
- 胜率只作为辅助信息展示，不作为排序主依据。

示例：

```text
好友A：安娜 18场 61%胜率
```

## 阵容搭配

阵容搭配只统计当前玩家和已识别好友的英雄组合。

第一版展示范围：

- 当前玩家 + 一个已识别好友。
- 当前玩家 + 多个已识别好友。
- 优先展示包含多个已识别好友的组合。
- 不默认展示完整五人阵容。

排序和样本：

- 按出现次数排序。
- 胜率作为辅助展示。
- 至少 3 场才进入榜单。
- 如果没有任何组合达到 3 场，隐藏阵容搭配模块。

组合 key 应使用稳定 ID，例如当前玩家英雄 GUID、好友 bnetId、好友英雄 GUID。展示 label 使用玩家名和英雄名。

示例：

```text
你：源氏 + 好友A：安娜，12场，58%胜率
你：温斯顿 + 好友A：安娜 + 好友B：卢西奥，5场，60%胜率
```

## 赛季回顾接入

赛季回顾应消费评分标签，但默认只突出正向统计。

展示项：

- 带飞局次数
- 尽力局次数
- S 级场次
- 最长连胜
- 最常高光

负面标签如 `躺赢局` 和 `背锅局` 不在赛季回顾中默认突出展示。

`最常高光` 只统计个人荣誉证据标签：

- `KDA最高`
- `击杀最多`
- `伤害最高`
- `治疗最高`
- `格挡最多`

不统计比赛性质标签：

- `翻盘局`
- `伯仲局`

## 降级与异常

- 详情缺失：只能做结果兜底标签，置信度降低。
- 队友行不足：跳过本队排名和阵容分析。
- 好友身份缺失：不推断好友，不进入好友模块。
- 英雄名缺失：使用英雄 GUID 兜底。
- 评分失败：导入成功，对局保持可见，评分区域隐藏。
- token、cookie、credential 等敏感字段不得展示或日志输出。

## 验收标准

- preset/open 对局导入后生成评分缓存。
- 战绩列表显示等级、一个主标签、最多两个证据标签。
- 平局或未知结果不显示评分标签。
- 未评分对局隐藏评分区域。
- 主标签筛选支持单选，且只包含带飞局、尽力局、躺赢局、背锅局。
- 连胜/连败以列表分隔标签展示，3 场起算。
- 好友常用英雄最多显示 5 个好友，每人 1 个代表英雄。
- 阵容搭配只展示当前玩家和已识别好友组合，3 场起入榜。
- 赛季回顾展示带飞局、尽力局、S 级场次、最长连胜、最常高光。
- 评分失败不影响基础战绩导入。
- 缓存包含规则版本，并支持打开战绩页后的后台重算。

## 后续扩展

- stadium/fight 模式单独规则。
- preset/open 分规则。
- 同英雄、同地图、个人历史均值参与更精细评分。
- 完整五人阵容分析。
- 详情页展示完整评分原因。
- 0-100 内部分数用于趋势图和排序。
