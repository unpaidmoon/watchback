# 指挥台参考图视觉精修设计

- 日期：2026-07-14
- 状态：已确认
- 适用范围：`apps/owstats-desktop` 指挥台及其视觉基础令牌
- 上位设计：`2026-07-14-ui-architecture-visual-redesign-design.md`
- 视觉参考：用户提供的 `屏幕截图 2026-06-28 055101.png`

## 1. 背景与目标

上一轮 UI 架构重构已经完成导航、页面框架和主要模块重组，但指挥台与参考图之间仍存在明显的视觉质感差距：画布偏平、卡片边界偏实、模块层级偏厚，尚未形成参考图中柔和渐变画布、乳白半透明表面和宽阔横向数据布局共同构成的轻盈感。

本设计选择“先把指挥台做成视觉标杆，再扩散经过验证的视觉基础”方案。第一阶段只精修指挥台，不重新设计账号、同步、数据健康或工具行为；完成三档视口和状态验收后，才允许在后续独立切片中将稳定的令牌和共享组件应用到其他页面。

目标不是逐像素复制参考图的业务内容，而是准确还原其视觉原则：连续的柔和画布、克制的毛玻璃质感、清晰的横向阅读顺序、低对比边界、深炭黑主操作，以及紫色和冷蓝绿色的数据强调。

## 2. 已确认决策

- 采用参考图还原度较高的视觉方向，不采用仅替换颜色的保守方案，也不采用高对比 Bento 仪表盘方案。
- 指挥台作为视觉标杆，先完成并验收，再决定其他页面的扩散切片。
- 背景不是纯色：使用低对比、静态、多层灰绿色渐变，并叠加很淡的冷蓝绿和暖白光晕。
- 模块使用轻毛玻璃质感：半透明乳白表面、轻度背景模糊、半透明内边线和大范围低浓度阴影。
- 毛玻璃强调克制和可读性，不使用高透明、强反光、霓虹描边或持续流动背景。
- 主工作区、次级模块和状态小组件使用不同透明度与边界强度，避免所有区域成为同样厚重的玻璃卡片。
- 深炭黑继续承担主要操作；紫色和冷蓝绿色只承担数据、选中、进度和必要强调。
- 不改变 BattleTag 自动识别、目标切换确认、保留原目标、重试、同步禁用或账号聚合行为。
- 不新增远程字体、远程运行时资源、开发机绝对路径或后端请求。

## 3. 非目标

- 不修改 Rust、SQLite schema、同步协议、统计口径或数据持久化。
- 不增加新的指标、微图表数据接口或后台查询。
- 不恢复 BattleTag 手工输入、任意目标搜索或旧绑定流程。
- 不增加“同步全部赛季”或全局赛季状态。
- 不在本阶段重新调整对局、战报、生涯 MMR 或排行的信息架构。
- 不用动画制造背景流动、玻璃折射或持续光效。
- 不把真实玩家数据、凭据、浏览器 profile 或隐私 ID 用于截图与视觉验收。

## 4. 视觉结构

### 4.1 页面阅读顺序

```text
指挥台标题与说明                              [检查更新] [同步数据]

登录状态 | 本地对局 | 详情覆盖 | 最近同步

┌────────────────────────────────┬──────────────────┐
│ 赛季数据与同步                  │ 当前账号与数据健康 │
│ 约 2/3                          │ 约 1/3            │
└────────────────────────────────┴──────────────────┘

[日志] [数据路径] [版本] [GitHub]

退出登录说明                                      [退出登录]
```

- 标题与页面操作处于同一横向层级。
- 四项核心指标是由细分隔线组织的横向数据带，不为每项添加厚重外卡。
- 同步工作区是首要内容；账号与数据健康是右侧辅助栏。
- 工具区视觉降级；退出登录与普通工具分离，但不使用大面积危险色背景。
- 页面以一个主要纵向滚动容器为主，不制造卡片内部的多重嵌套滚动。

### 4.2 页面头部

- 主标题使用 `32-34px`、`500` 字重；说明文字使用 `13-14px`。
- “检查更新”使用浅色次按钮；主要同步操作使用深炭黑按钮。
- 操作高度统一为 `44px`，圆角约 `12px`，不使用渐变按钮。
- 标题、说明和操作在空间不足时允许自然换行，不压缩核心字号。

### 4.3 核心指标带

- 固定表达登录状态、本地对局、详情覆盖和最近同步四类已有信息。
- 每项由短标签、`30-36px` 核心值和一句简短说明构成。
- 宽屏四列，较窄视口两列；分隔线替代四张独立卡片。
- 只允许用现有数据制作轻量视觉提示，例如短条、覆盖刻度、状态点或时间刻度；不得因此新增请求或统计。
- 数字使用等宽数字特性，场数与百分比显示明确单位，不使用模糊缩写。

### 4.4 赛季数据与同步

- S21、S22、S23 使用紧凑分段控件选择，不新增突出数字输入。
- 当前赛季作为主数据面板，继续展示本地对局、详情数、普通对局、角斗对局、待补详情和最近同步六项事实。
- 六项事实使用紧凑横向行；可用宽度不足时按既有规则折为三列。
- 详情覆盖使用紫色进度表达，同时保留百分比和文本说明。
- 同步按钮位于区域右下侧，其附近展示当前同步状态、失败恢复或禁用原因。
- 不提供一键同步全部赛季；同步中仍遵守现有串行与禁用规则。

### 4.5 当前账号与数据健康

- 使用 `48-56px` 中性头像、首字或轮廓占位，不保留压迫感较强的大块深色头像背景。
- 玩家显示名作为主标题；称号、游玩时间等已有信息降为次级说明。
- 账号识别、同步目标确认和数据健康以分组状态行呈现。
- 状态行使用图标、文字和细语义边线，不堆叠大量胶囊标签。
- 完整保留自动识别、相同目标、等待切换确认、保留原目标、重新绑定、重新识别和同步禁用等既有状态及操作。

### 4.6 工具与危险操作

- 日志、数据路径、版本和 GitHub 组织为四列次级工具行。
- 图标统一使用仓库已有图标体系，建议视觉尺寸 `16-18px`、相同描边粗细。
- 退出登录放在页面底部独立行，使用说明文字和危险操作按钮。
- 危险语义仅使用红色文字、图标与浅色边线，不使用大面积红色填充。

## 5. 画布与毛玻璃系统

### 5.1 建议令牌

```css
--canvas-base: #e3e8e2;
--canvas-glow-cool: rgba(198, 224, 222, 0.52);
--canvas-glow-light: rgba(250, 249, 241, 0.72);

--glass-primary: rgba(244, 246, 240, 0.68);
--glass-secondary: rgba(250, 251, 247, 0.52);
--glass-border: rgba(255, 255, 255, 0.58);
--glass-shadow: 0 18px 48px rgba(45, 54, 48, 0.08);
--glass-blur: 16px;

--text-primary: #202220;
--action-primary: #303030;
--data-primary: #4b22d1;
--data-secondary: #2f8c95;
```

最终实现可以在视觉验收中微调透明度和阴影浓度，但不得改变色彩方向或提高整体饱和度。

### 5.2 画布渐变

- 以 `--canvas-base` 为底色，使用两个或三个大范围径向渐变叠加冷色与暖白光晕。
- 渐变中心避开完全对称的中央位置，形成自然环境光，但不得形成明显彩色斑块。
- 渐变跨度必须足够大，目标视口中不可看到突兀边界或色带。
- 默认使用静态背景；不设置持续位移、循环缩放或颜色动画。

### 5.3 玻璃层级

1. 主工作区：较高不透明度、`16px` 左右模糊、最完整的浅色内边线和环境阴影。
2. 次级模块：更高透明度、较弱阴影，依靠间距和标题而不是重边框分层。
3. 状态小组件：淡色表面、语义细边线或状态点，不额外叠加明显阴影。

禁止三层以上玻璃卡片嵌套。必要的数据行优先使用分隔线、背景明度差和留白，而不是继续增加圆角容器。

### 5.4 回退与性能

- 使用 `@supports` 或等价方式为不支持 `backdrop-filter` 的 WebView 提供半透明度更低的实体浅色背景。
- 文字对比度不能依赖背景模糊才能成立；模糊关闭后仍需清晰可读。
- 不在长列表的每一行使用独立背景模糊层。
- 不对模糊半径、阴影或渐变位置做连续动画。
- Windows WebView 中如发现滚动掉帧，优先减少模糊层数量，不取消整体层级或改回厚重实色卡片。

## 6. 交互、状态与可访问性

- 悬停只改变明度、边框或产生 `1-2px` 的轻微位移，不放大组件。
- 常规过渡为 `160-220ms`，仅用于 `opacity`、`transform` 和颜色。
- 键盘焦点使用清晰的紫色双层焦点环，不能只改变背景颜色。
- 所有操作命中区至少 `44px`。
- 加载状态保持模块尺寸稳定，使用低对比骨架，避免布局跳动。
- 空状态说明原因，并只提供一个最明确的下一步操作。
- 错误状态在所属模块中显示中文摘要和恢复动作，不用整页红色警告。
- 禁用状态同时降低对比度、阻止交互并显示原因，不能只依赖灰色。
- 状态不能只依赖颜色，必须同时存在文字或图标。
- `prefers-reduced-motion` 下取消位移和非必要过渡，保留即时状态反馈。

## 7. 响应式规则

### 7.1 `2540x1344`

- 保持宽阔横向构图，四项指标单行。
- 主体使用约 `2:1` 双栏，同步区与账号健康区在首屏形成稳定视觉重心。
- 页面最大宽度允许充分利用窗口，但不能让文本行无限拉长。

### 7.2 `1920x1080`

- 保持四项指标和主体双栏。
- 适当压缩外围留白与模块间距，不降低页面标题和核心数据字号。
- 工具区仍优先保持四列。

### 7.3 `1440x900`

- 指标允许改为 `2x2`。
- 主体优先保持双栏；当账号区内容造成明显拥挤时，将右栏移到同步区下方。
- 工具区允许折为两列。
- 不通过内部滚动或极小字号强行维持宽屏排列。

## 8. 实施切片与测试策略

实现阶段遵循 TDD，每个切片先增加会失败的结构、状态或样式契约测试，再做最小实现并运行对应测试。每个可独立验证切片单独提交。

### 切片一：视觉基线与令牌契约

- 为画布渐变、玻璃层级、模糊回退、焦点和 reduced-motion 建立源码或组件契约测试。
- 新增或调整视觉令牌，不改变页面数据流。
- 验证现有页面不会重新出现橙色主色或蓝橙渐变。

### 切片二：标题与核心指标带

- 重排指挥台标题、说明、检查更新和主要同步操作。
- 将四项指标改为横向数据带并覆盖窄宽折行。
- 保持所有指标来源和含义不变。

### 切片三：同步主工作区

- 精修赛季分段控件、六项数据事实、覆盖率和同步状态。
- 覆盖可同步、同步中、同步失败、无目标和目标不一致时的禁用状态。
- 不新增同步入口或请求。

### 切片四：账号与数据健康

- 重排账号摘要、身份识别、目标确认和健康状态行。
- 用组件测试覆盖 BattleTag 自动识别设计中的主要状态，确保没有手工输入或任意目标绑定入口。

### 切片五：工具与退出登录

- 精修底部工具行和危险操作分隔。
- 保持日志、路径、版本、GitHub 和退出登录行为不变。

### 切片六：视觉与交互验收

- 在 `2540x1344`、`1920x1080`、`1440x900` 下截图检查。
- 覆盖导航、页面滚动、同步状态、空状态、错误状态、禁用状态、键盘焦点和 reduced-motion。
- 检查 WebView 模糊回退与滚动性能。
- 使用匿名 fixture 或合成数据，不截图真实玩家隐私信息。
- 若视觉仍明显偏离参考图，继续调整透明度、渐变范围、间距、字号和表面层级，不能仅凭测试通过结束。

### 后续扩散阶段

指挥台验收通过后，只允许在新的独立设计或实施切片中扩散以下稳定内容：

- 画布渐变与玻璃表面令牌。
- 页面标题栏与页面操作布局。
- 按钮、焦点、加载、空、错误和禁用状态。
- 卡片边界、阴影、圆角和间距。

其他页面独有的信息架构和业务交互不因本设计自动获得修改授权。

## 10. 验收标准

- 指挥台在三个目标尺寸下都呈现柔和渐变画布，而不是纯色背景或明显色带。
- 主模块具有克制的乳白半透明毛玻璃质感，且回退模式仍清晰可读。
- 标题、指标、同步区、账号健康区和工具区形成明确的视觉阅读顺序。
- 页面不再依赖厚重嵌套卡片、拥挤状态胶囊或大面积高饱和填充。
- 深炭黑、紫色和冷蓝绿色的职责符合本设计，没有橙色主色或蓝橙渐变回归。
- BattleTag、同步、数据健康、工具和退出登录行为保持不变。
- 键盘焦点、加载、空、错误、禁用和 reduced-motion 均有验证证据。
- Windows WebView 中滚动和模糊效果可接受；不支持模糊时具有可靠回退。
- 所有自动化测试、构建和 Tauri 打包通过。
- 视觉验收不读取、显示、记录或提交任何真实凭据、浏览器 profile、真实数据 dump 或原始玩家隐私 ID。
