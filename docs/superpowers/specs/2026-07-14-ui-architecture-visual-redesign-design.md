# OWStatsLocal UI 功能架构与视觉重构设计

## 1. 背景

当前桌面端已经具备指挥台、对局、战报、生涯 MMR、排行和好友分析等实际功能，但页面是按历史开发阶段逐步扩展的，导航顺序、页面标题、赛季选择、空状态、跨页上下文和视觉层级并未形成统一系统。

本设计在不推翻现有 Tauri、React、Rust、SQLite 数据链路的前提下，围绕用户已经确认的日常路径重组 UI：先查看本地对局，再进入战报、MMR 和排行深挖；指挥台继续作为一级页面，但移到导航最右侧。

视觉风格参考用户提供的 `屏幕截图 2026-06-28 055101.png`。参考重点是柔和灰绿色画布、深炭色导航与主操作、低阴影卡片、横向指标带、宽松模块留白和紧凑数据区。OWStatsLocal 不保留原有橙色品牌依赖，数据强调改用紫色和冷蓝绿色。

## 2. 已确认决策

- 默认入口由指挥台改为对局页。
- 一级导航顺序固定为：`对局 | 战报 | 生涯 MMR | 排行 | 指挥台`。
- 保留“战报”名称，不改为“赛季复盘”。
- 指挥台继续作为一级页面，并位于导航最右侧。
- 重做对局筛选、对局列表和左右详情布局。
- 统一页面标题、赛季选择、加载/空/错误状态和跨页上下文。
- 生涯 MMR 删除“近期单场解释”模块，不新增图标式筛选。
- 排行功能、评分、排序和聚合逻辑不变，只统一页面框架和视觉样式。
- 不保留橙色主色或蓝橙渐变。
- BattleTag 主流程由其他工作树处理，本设计不重复实现或修改该流程。
- 各页面继续独立维护赛季，不新增全局赛季状态。

## 3. 非目标

- 不修改 Rust 查询、SQLite schema、同步协议或导入逻辑。
- 不修改排行评分算法、默认排序、可排序字段或数据契约。
- 不重新设计生涯 MMR 模型或重新计算历史 MMR。
- 不新增“同步全部赛季”。
- 不新增全局 `currentSeason`、全局赛季 store 或由指挥台驱动的页面筛选。
- 不新增在线字体、在线图标库、开发机绝对资源路径或安装版外部依赖。
- 不读取、展示或记录 token、customerToken、cookie、authorization、credential、浏览器 profile 或原始玩家隐私 ID。

## 4. 用户主路径

```text
启动应用
  -> 默认进入对局
  -> 浏览最近对局
  -> 筛选或打开某场详情
  -> 进入战报查看赛季汇总
  -> 进入生涯 MMR 查看长期趋势
  -> 进入排行查看英雄和地图聚合
  -> 需要登录、同步或诊断时进入最右侧指挥台
```

同步是数据准备动作，不再占据默认入口；对局是日常高频入口。

## 5. 全局信息架构

### 5.1 顶部导航

```text
[OWStatsLocal]        [对局][战报][生涯 MMR][排行][指挥台]        [本地数据][设置/账号]
```

- `/` 重定向到 `/matches`。
- 激活项使用深炭背景和白色文字。
- “指挥台”位于导航胶囊最右侧。
- 右上角“本地数据”采用可点击状态入口；点击后进入指挥台的数据区，并保留明确的键盘焦点与可访问名称。
- 没有实际通知能力时移除通知铃铛；不得保留看似可用但没有行为的按钮。
- 深页面仍保留一级导航，浏览器返回必须恢复上一页面的筛选、选中项和滚动状态。

### 5.2 页面头部

对局、战报、生涯 MMR 和排行统一使用 `PageHeader`：

```text
页面标题
页面用途说明                                      页面级赛季选择
```

- 页面标题使用 `h1`。
- 赛季选择固定在右侧相同位置。
- 对局页的赛季不再在高级筛选中重复出现。
- 指挥台的“同步赛季”属于操作目标，不套用分析页面的 `PageSeasonSelect`。
- 排行保持现有可用赛季来源与行为，本轮只统一控件位置和样式。

### 5.3 页面级赛季状态

- 每个页面继续使用自己的 URL query 和本地状态。
- 战报、排行和好友详情之间跳转时显式携带 `season`。
- 对局列表、当前选中对局、筛选、缓存和详情必须处于同一赛季上下文。
- 本轮不让指挥台选择的同步赛季影响其他页面。

### 6.1 色彩令牌

|---|---:|---|

| `--surface-primary` | `#F0F1EA` | 一级模块 |
| `--surface-secondary` | `#F6F7F2` | 列表项和数据子卡 |
| `--surface-control` | `#ECEEE9` | 输入、弱按钮和工具栏 |
| `--text-primary` | `#202220` | 标题和核心数据 |
| `--text-secondary` | `#60645F` | 正文和字段说明 |
| `--text-tertiary` | `#8A8F89` | 时间和补充信息 |
| `--border-subtle` | `#D8DED8` | 边框和分隔线 |
| `--action-primary` | `#303030` | 主按钮和激活导航 |
| `--action-on-primary` | `#FFFFFF` | 深色按钮文字 |
| `--data-primary` | `#4B22D1` | 选中态和主趋势线 |
| `--data-secondary` | `#2F8C95` | 第二趋势和辅助统计 |
| `--data-neutral` | `#A5AAA4` | 基准线和历史线 |

| `--status-success-bg` | `#E2F3E7` | 成功标签背景 |
| `--status-danger` | `#E54848` | 失败和错误 |
| `--status-danger-bg` | `#F8E7E5` | 错误标签背景 |
| `--status-warning` | `#B58A16` | 数据缺失和待处理 |
| `--status-warning-bg` | `#F4EFD8` | 警告标签背景 |

规则：

- 不定义橙色品牌令牌，不使用蓝橙渐变。
- 深炭黑表达主要操作，紫色表达选中和分析重点。
- 绿、红和金色只表达语义状态，不能作为普通装饰。
- 状态不能只依赖颜色，必须同时显示文字或图标。
- 主画布可使用非常轻微的灰绿、灰蓝径向变化，但不得形成高对比装饰渐变。

### 6.2 字体

不引入在线字体，使用系统字体栈：

```css
"Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", "Segoe UI", sans-serif
```

| 层级 | 字号 | 字重 | 用途 |
|---|---:|---:|---|
| 页面主标题 | `30-34px` | `500` | 对局、战报、MMR、排行、指挥台 |
| 核心数据 | `38-44px` | `500` | MMR、场数、覆盖率 |
| 模块标题 | `18-20px` | `600` | 趋势、队伍、同步区 |
| 卡片标题 | `15-16px` | `600` | 玩家、地图、英雄 |
| 正文 | `14px` | `400` | 描述和解释 |
| 控件文字 | `13-14px` | `500` | 导航、按钮、筛选器 |
| 辅助标签 | `12px` | `400-500` | 时间、单位和状态说明 |

- 页面标题依靠字号和留白建立层级，不使用 `800/900` 超粗字重。
- 正文行高约 `1.5`。
- 数据列和统计数字使用 `font-variant-numeric: tabular-nums`。
- 次要文字通过颜色和字重降级，不使用低于 `12px` 的正文。

### 6.3 间距

统一使用 `4 / 8 / 12 / 16 / 24 / 32 / 40` 的间距体系：

- 窗口外沿：`8px`。
- 应用画布内边距：`24-32px`。
- 页面头部与正文：`24px`。
- 一级模块之间：`16-24px`。
- 一级卡片内边距：`16px`。
- 紧凑数据卡内边距：`12px`。
- 控件间距：`8px`。
- 图标与文字间距：`8px`。
- 表格行高：`48-56px`。
- 对局列表卡片最小高度：`72-88px`。

模块之间保留呼吸感；列表、表格和筛选区保持紧凑，不通过放大每一张卡片制造留白。

### 6.4 圆角、阴影和边框

- 应用外壳圆角：`28-32px`。
- 一级卡片圆角：`18-20px`。
- 二级卡片圆角：`14-16px`。
- 导航项和按钮圆角：`11-12px`。
- 状态标签可使用完全胶囊圆角。
- 卡片边框：`1px solid rgba(48, 52, 48, 0.06)`。
- 卡片阴影：`0 8px 24px rgba(35, 40, 35, 0.035)`。
- 禁止三层以上圆角卡片嵌套。
- 选中状态优先使用背景、边框和文字变化，不使用强发光或大幅浮起。

### 6.5 动效与可访问性

- 导航、按钮、展开和选中变化控制在 `150-200ms`。
- 只动画 `transform` 和 `opacity`，避免触发布局抖动。
- 支持 `prefers-reduced-motion`。
- 所有交互命中区至少 `44px`。
- 键盘焦点使用可见的紫色 `2px` 外环。
- 正文对比度至少满足 `4.5:1`。
- 图表数据颜色与背景至少满足 `3:1`，并提供文本标签或表格替代。

## 7. 共享组件

### 7.1 页面组件

- `PageHeader`：标题、用途说明和页面级操作。
- `PageSeasonSelect`：统一的页面级赛季控件。
- `PageLoadingState`：保留稳定布局的骨架屏。
- `PageEmptyState`：说明原因并提供一个恢复动作。
- `PageErrorState`：说明原因并提供重试动作。
- `StatusPill`：成功、失败、警告和中性状态。

### 7.2 对局组件

- `MatchFilterToolbar`：高频筛选和“更多筛选”入口。
- `ActiveFilterChips`：当前筛选摘要和单项移除。
- `MatchListPane`：列表滚动、选中和恢复位置。
- `MatchListCard`：紧凑对局摘要。
- `MatchDetailHeader`：结果、地图、模式、时间、比分和前后场切换。
- `MatchTeamTable`：队友/对手统一列对齐数据表。

`MatchesPage` 继续负责 URL、缓存、请求和选中状态；展示职责下沉到上述组件，不把页面协调器扩展成新的巨型组件。

## 8. 页面设计

### 8.1 对局

#### 页面结构

```text
对局记录                                               S23
149 场本地对局

[模式] [胜负] [玩家名称] [更多筛选 3] [清除]
[英雄：飞天猫 ×] [地图：香巴里寺院 ×]

┌────────────────┬──────────────────────────────────┐
│ 对局列表 32%    │ 当前对局详情 68%                 │
└────────────────┴──────────────────────────────────┘
```

#### 筛选

高频筛选：

- 赛季由页面头部控制。
- 工具栏保留模式、胜负、玩家名称、更多筛选和清除。

更多筛选：

- 英雄。
- 地图。
- 复盘标签。
- 开始日期。
- 结束日期。

规则：

- “更多筛选”显示当前启用数量。
- 有效筛选显示为可单独移除的标签。
- “清除”仅在存在筛选时启用。
- 日期必须有可见中文标签，不能只依赖 placeholder。
- 保持现有筛选字段和值，不扩展后端查询能力。
- 筛选变化继续写入 URL。

#### 对局列表卡片

```text
胜利                         香巴里寺院 · 快速
0-1                          07-12 23:05

[英雄头像] 西格玛
K/D/A 18/1/4     伤害 11,025     承伤 15,267
```

- “胜利”和“0-1”分开显示，不拼成“胜利：0-1”。
- 不使用 `1.1w` 等缩写，显示带千位分隔的可比较数字。
- 结果同时使用文字、图标/标记和语义色。
- 选中项使用浅色背景、深色标题或紫色细边，不整卡高饱和填充。
- 连胜和评分属于次要标记。

#### 详情

详情头部：

```text
胜利 | 香巴里寺院 | 快速 | 0-1
8分56秒 | 2026-07-12 23:05                         上一场 | 下一场
```

正文顺序：

1. 本人表现。
2. 队伍对比。
3. 队友数据。
4. 对手数据。
5. 现有普通对局或角斗详情模块。

- 队友使用冷蓝绿色窄边或标题标记。
- 对手使用红色窄边或标题标记。
- 数据行使用中性浅色背景，不使用整块高饱和蓝底。
- 同一指标保持列对齐。
- 普通对局和角斗详情继续走各自已有的渲染分支，本轮只统一外层布局和视觉语言。

#### 滚动

- 页面头部和筛选栏位于工作区上方。
- 下方主从工作区占据剩余窗口高度。
- 左侧列表和右侧详情是同级滚动容器。
- 禁止页面滚动、面板滚动和卡片内部滚动形成三层嵌套。
- 返回页面时恢复筛选、选中项和列表位置。
- 小于约 `1100px` 时改为列表进入独立详情，不强行压缩双栏。

### 8.2 战报

保留“战报”页面名称。

```text
战报                                                   S23

[总场数] | [胜率] | [S级场次] | [常用职责]

[概览] [职责与英雄] [队友协作] [地图] [成就]

┌────────────────────────┬─────────────────────┐
│ 当前标签主要内容 2/3    │ 辅助摘要 1/3         │
└────────────────────────┴─────────────────────┘
```

- 顶部指标使用细分隔线组织，不拆成四张厚重卡片。
- 标签使用浅色分段控件，激活项使用深炭背景。
- 概览：赛季场数、职责摘要和核心结论。
- 职责与英雄：职责段位、胜率、KDA 和英雄池。
- 队友协作：好友亲密度、高频组合和好友分析板。
- 地图：王牌地图、翻车路段、常驻战场和稀有来客。
- 成就：现有成就墙和成就详情。
- 所有标签共享同一页面赛季。
- 地图卡片跳转排行时使用 `/ranking?tab=maps&season={season}`。
- 好友详情返回时恢复原标签、赛季和滚动位置。

### 8.3 生涯 MMR

```text
生涯 MMR                                      展示赛季：全部
本地模型估算，并非暴雪官方隐藏分

[重装] | [输出] | [支援] | [综合分摘要]

┌────────────────────────┬─────────────────────┐
│ 历史趋势 2/3            │ 模式贡献 1/3         │
└────────────────────────┴─────────────────────┘

┌──────────────────────────────────────────────┐
│ 赛季分解                                      │
└──────────────────────────────────────────────┘
```

- 删除“近期单场解释”模块及其页面请求，不保留空占位。
- 不新增图标式筛选。
- 三职责卡片承担职责切换；当前职责使用深色小标记或紫色圆点，不整卡发光。
- 综合分降为次要摘要。
- 赛季控件明确标注“展示赛季”，只改变趋势和分解展示，不重新计算当前 MMR。
- 趋势图使用紫色主线、冷蓝绿色辅线和灰色基准线。
- 置信区间使用同色 `10%-15%` 透明填充。
- 图表提供纵轴单位、日期刻度、悬停值和屏幕阅读器文本摘要。
- 模式贡献必须显示真实口径，例如“生涯累计贡献”，不能只显示孤立的 `+107.0`。
- 删除单场解释后，赛季分解使用全宽布局。

### 8.4 排行

排行功能保持现状：

- 英雄排行和地图排行。
- 搜索。
- 当前可用赛季来源。
- 现有排序字段和切换行为。
- 现有评分显示。
- 现有后端聚合。

本轮只调整：

```text
英雄与地图排行                                         S23

[英雄排行] [地图排行]                    [搜索]   38 项

┌──────────────────────────────────────────────┐
│ 表头                                          │
├──────────────────────────────────────────────┤
│ 排行行                                        │
│ 排行行                                        │
└──────────────────────────────────────────────┘
```

- 增加统一页面标题。
- 将赛季选择放入页面头部右侧。
- 英雄/地图切换使用浅色分段控件和深炭激活项。
- 表头使用浅灰绿色背景。
- 数据行改为紧凑表格行或低圆角行，不再每行使用巨型白色卡片。
- 当前排序列使用紫色文字和现有排序图标。
- 接受战报传入的 `season` 和 `tab`，但不改变排行功能契约。

### 8.5 指挥台

```text
指挥台                                      [检查更新] [同步数据]

[登录状态] | [本地对局] | [覆盖率] | [最近同步]

┌────────────────────────┬─────────────────────┐
│ 赛季数据与同步 2/3      │ 当前账号与健康 1/3   │
│ S21 / S22 / S23        │                     │
└────────────────────────┴─────────────────────┘

[日志] [数据路径] [版本] [GitHub]
```

- 指挥台保留一级页面身份，并位于导航最右侧。
- 顶部指标采用横向分隔布局。
- 同步区是页面主要内容。
- 当前账号状态和数据健康位于右侧窄栏。
- 常用英雄和成就移入战报，不占据指挥台首屏。
- 日志、路径、版本和 GitHub 放入底部次要工具区。
- 退出登录使用危险操作样式，并与普通工具分离。
- 本设计假设其他工作树完成的 BattleTag 主流程调整最终进入集成基线；本轮 UI 重构不重复修改该逻辑。

## 9. 数据流与状态

### 9.1 页面请求

- 页面组件继续调用现有 `shared/api.ts` 接口。
- `MatchesPage` 保留当前初始预加载、缓存恢复、筛选请求和详情请求流程。
- 战报的标签切换优先复用已加载的同赛季数据，不重复发起相同请求。
- 生涯 MMR 删除单场解释模块后，应同时停止对应页面请求，避免隐藏模块继续消耗查询。
- 排行请求和聚合完全不变。

### 9.2 URL 与跨页上下文

- 对局：保留 `season`、筛选字段和 `matchId`。
- 战报：保留 `season` 和当前标签；标签统一写入 `view=overview|roles|friends|maps|achievements` query，并锁定 URL 与页面状态测试。
- 排行：保留 `season` 和 `tab`。
- 好友详情：进入时携带来源赛季和返回上下文。
- 浏览器返回不得丢失上一页面的筛选和选中状态。

### 9.3 状态反馈

- 加载超过 `300ms` 时显示骨架或明确进度。
- 空状态包含原因和一个主要恢复动作。
- 筛选无结果提供“清除筛选”，不引导用户重新同步。
- 请求失败显示中文原因和“重新加载”。
- 同步中按钮禁用并显示当前进度。
- 错误和成功信息使用 `aria-live`，不抢夺键盘焦点。

## 10. 组件与代码边界

- `App.tsx` 只负责路由和全局外壳。
- `phase6Shell` 或后续等价模块维护一级导航配置和通用状态文案。
- 页面共享组件放在明确的 shared/page-shell 边界，不把业务请求写入纯展示组件。
- 对局业务展示继续位于 `features/matches/`。
- `MatchesPage` 保留协调器职责，但列表、筛选和详情渲染拆到独立组件。
- 战报、MMR 和排行只在本轮触及与页面框架、布局和已确认删除模块直接相关的代码。
- 不借 UI 重构扩大后端模块、同步协议或数据库范围。

## 11. 响应式规则

重点验证：

- `2540x1344`：用户当前宽屏环境。
- `1920x1080`。
- `1440x900`。
- 最低支持宽度约 `1024px`。

规则：

- 超宽屏普通页面最大内容宽度约 `1920px` 并居中。
- 对局工作台可使用更宽的可用区域。
- 页面左右内边距随宽度在 `24-32px` 间变化。
- 小于 `1100px` 时，对局列表和详情改为单栏进入式布局。
- 图表在窄宽度下减少刻度密度，不产生横向滚动。
- 固定导航和工具栏必须预留内容空间，不遮挡滚动内容。
