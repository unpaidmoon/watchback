# 排行页面动态赛季设计

## 目标

排行页面不再固定显示 S21、S22、S23，而是根据本地数据库中实际存在的预设对局赛季动态生成选项。已有 S15、S20 数据时，页面应自动显示 S15、S20；以后导入其他赛季后，无需修改前端代码。

## 范围

- 只修改排行页面及其 `get_rankings` 数据契约。
- 排行页面继续独立维护赛季选择，不新增全局赛季状态。
- 不修改个人战报、好友分析和指挥中心的赛季边界。
- 不新增“一键同步全部”或旧 BattleTag 绑定流程。

## 数据契约

`RankingResponse` 新增 `availableSeasons`，由后端查询 `matches` 表中 `bucket = 'preset'` 且实际存在数据的不同赛季，并按降序返回。

同一次 `get_rankings` 请求返回：

- 实际选中的 `season`；
- 动态 `availableSeasons`；
- 该赛季的英雄排行和地图排行。

若请求未指定赛季，后端选择最新的可用赛季。若请求指定的赛季没有预设对局数据，后端回退到最新可用赛季，避免页面保留一个没有对应选项的无效状态。

## 前端行为

- 赛季下拉框使用 `ranking.availableSeasons`，保持降序显示。
- URL 中的正整数赛季值可以发给后端，不再限制为 S21/S22/S23。
- 后端返回实际选中赛季后，前端同步本地状态及 URL，确保无效赛季回退可见且可刷新复现。
- 当没有任何可用赛季时，下拉框禁用，沿用现有空数据提示。
- 搜索、排序、英雄/地图标签页和名称映射行为保持不变。

## 测试

- 后端测试插入 S15、S20、S21 数据，断言 `availableSeasons` 为 `[21, 20, 15]`。
- 后端测试未指定赛季时选择最新赛季。
- 后端测试请求不存在的赛季时回退到最新赛季。
- 前端测试不再包含固定 `selectableSeasons`，并使用响应中的动态赛季列表。
- 运行完整前端测试与构建、相关 Rust 排行测试、`git diff --check`。

## 隐私与发布

赛季列表仅包含整数赛季编号，不涉及玩家 ID、凭据、token 或原始对局 JSON。本改动不新增运行时资源和开发机绝对路径。
