# 指挥台动态赛季同步与本地赛季台账设计

- 日期：2026-07-15
- 状态：已确认
- 适用范围：`apps/owstats-desktop` 指挥台“赛季数据与同步”区域
- 视觉规范：根目录 `design.md`
- 取代范围：仅取代指挥台固定 S21/S22/S23 赛季选择与单张当前赛季状态卡设计

## 1. 背景

当前指挥台使用 S21、S22、S23 三段式按钮选择同步赛季，并在右侧展开所选赛季的一张大型数据状态卡。真实同步能力并不限于这三个赛季：S15 起的赛季均可以通过现有单赛季同步协议抓取、落盘并导入 SQLite。固定三段式入口既隐藏了已有能力，也无法自然扩展到后续 S24、S25。

本设计将赛季范围改为“固定下限 S15、上限由应用当前赛季配置决定”，并重组同步工作区：左侧只负责选择和同步一个赛季，右侧以一季一行的台账集中展示本地已经同步的数据。

## 2. 目标

- 支持从 S15 到应用配置的当前赛季逐季选择和同步。
- 当前赛季升级时只修改一处后端配置，不再修改前端固定数组或布局。
- 左侧形成单一、明确的同步操作路径。
- 右侧清楚回答本地已有哪几个赛季，以及每个赛季的数据健康情况。
- 保持现有单任务串行同步、账号目标门禁、赛季隔离、脱敏和幂等行为。
- 保持其他页面独立维护自己的赛季筛选，不引入全局赛季状态。

## 3. 非目标

- 不增加“一键同步全部”或多选批量同步。
- 不并发同步多个赛季。
- 不修改上游抓取协议、分页、详情并发、限速或 429 重试策略。
- 不修改 SQLite schema、对局统计口径或详情覆盖率口径。
- 不修改登录、BattleTag 自动识别、目标切换确认或凭据存储流程。
- 不让指挥台选中赛季驱动对局、战报、排行、好友分析或生涯 MMR 页面的筛选。
- 不在台账中生成尚未同步赛季的零数据占位行。

## 4. 已确认产品决策

- 可同步范围下限固定为 S15。
- 可同步范围上限使用后端应用配置的当前赛季。
- 当前版本默认选择当前赛季。
- 赛季选择使用单一下拉框，不使用横向滚动赛季带或“近期快捷项 + 完整列表”。
- 每次只同步一个赛季。
- 左侧不显示“本地已有赛季”数量或列表；本地数据只在右侧台账表达。
- 右侧只列出真实存在本地数据的赛季，按赛季号降序排列。
- 台账每行固定展示：赛季名称、详情覆盖度、本地对局、最近同步时间。
- 点击或键盘选择台账行只切换左侧目标赛季，不自动发起同步。
- 左侧同步按钮是该区域唯一的同步入口，移除头部或状态卡中的重复同步操作。

## 5. 页面结构

### 5.1 宽屏布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 赛季数据与同步                                                       │
├──────────────────────┬───────────────────────────────────────────────┤
│ 同步一个赛季         │ 已同步数据                   按赛季从新到旧  │
│                      │                                               │
│ [ S23 · 当前赛季  v ]│ 赛季  详情覆盖度  本地对局  最近同步         │
│ 可同步：S15-S23      │ S23   82%         186 场    07-15 10:12     │
│                      │ S22   96%         428 场    07-13 18:40     │
│ [ 同步 S23 ]         │ S21  100%         564 场    07-09 10:12     │
│ 状态或恢复说明       │ S20   91%         312 场    07-02 16:05     │
│                      │ S15   76%          98 场    06-28 21:30     │
└──────────────────────┴───────────────────────────────────────────────┘
```

- 维持约 `1:2` 的左窄右宽结构。
- 左右区域使用细分隔线，不增加两张厚重嵌套卡片。
- 台账随页面主滚动容器自然增长，不增加独立内部滚动。

### 5.2 窄屏布局

- 当宽度不足以稳定容纳四列表格时，左侧控制区移到台账上方。
- 台账继续保持一季一行；最近同步可缩短为 `MM-DD HH:mm`。
- 不通过缩小正文到 12px 以下或引入横向页面滚动强行维持宽屏结构。
- 若四列无法保持可读性，覆盖度保留百分比并缩短进度条，本地对局与时间继续保持独立列。

## 6. 左侧同步控制

左侧组件建议命名为 `SeasonSyncControl`，职责仅包括：

- 展示赛季下拉框。
- 展示可同步范围和当前赛季说明。
- 发起所选单赛季同步。
- 展示同步进度、成功摘要、错误和禁用原因。

### 6.1 下拉框

- 选项来自后端 `syncableSeasons`，按当前赛季到 S15 降序排列。
- 当前赛季选项显示为 `S{n} · 当前赛季`；其他选项显示为 `S{n}`。
- 首次进入页面默认选择 `currentSeason`。
- 状态刷新、账号操作和同步完成后保留仍然有效的用户选择；只有选择值不再属于 `syncableSeasons` 时才回退到 `currentSeason`。
- 下拉框具有可见中文标签，不能只用 placeholder 表达用途。

### 6.2 同步按钮

- 文案为 `同步 S{selectedSeason}`。
- 同步中改为稳定的进度文案并禁用重复提交。
- 凭据不可用、目标未确认、账号操作进行中或已有同步任务时禁用，并在按钮附近显示中文原因。
- 页面头部和右侧台账不再提供第二个同步按钮。

### 6.3 首次同步与重新同步

- 首次同步一个尚无本地数据的赛季时，进度只在左侧控制区展示。
- 只有该赛季成功写入本地数据后，右侧才新增对应行。
- 重新同步已有赛季时，右侧对应行显示非颜色单一表达的“同步中”状态，但旧数据继续可见。
- 同步完成后原位刷新该行，不产生重复行。

## 7. 右侧已同步赛季台账

右侧组件建议命名为 `SyncedSeasonLedger`，数据源为 `seasonStatuses`。

### 7.1 行与列

每行代表一个本地确实存在数据的赛季，固定包含：

1. 赛季：`S{season}`。
2. 详情覆盖度：进度条与明确百分比文本。
3. 本地对局：`{matchCount} 场`。
4. 最近同步：宽屏显示本地化时间，紧凑布局显示 `MM-DD HH:mm`。

不在本轮显示普通对局、角斗对局、详情数和待补详情。这些字段可以继续保留在后端 DTO 中，但不进入本次台账可见列，避免右侧重新膨胀成高密度详情卡。

### 7.2 排序与选择

- 始终按赛季号降序展示。
- 点击一行会将该赛季设置为左侧下拉框选中值。
- 行选择不触发同步，也不改变其他页面的赛季筛选。
- 当前选择使用细左边线、弱背景明度和 `aria-selected` 等语义表达，不只依赖颜色。
- 行选择必须可通过键盘完成，并保留 `2px` 可见焦点环。

### 7.3 空状态

当 `seasonStatuses` 为空时，右侧保持稳定高度并显示：

> 暂无已同步赛季，请从左侧选择赛季开始同步。

空状态不重复放置同步按钮，因为左侧已经提供唯一主操作。

## 8. 数据契约

`OnboardingStatus` 增加以下字段：

```ts
type OnboardingStatus = {
  currentSeason: number;
  syncableSeasons: number[];
  availableSeasons: number[];
  seasonStatuses: SeasonDataStatus[];
  // 其他现有字段保持不变
};
```

字段语义：

- `currentSeason`：应用配置的当前赛季。
- `syncableSeasons`：从 `currentSeason` 到 S15 的完整降序整数列表。
- `availableSeasons`：数据库中真实存在数据的赛季列表，保留供现有调用方使用。
- `seasonStatuses`：仅包含数据库中真实存在数据的赛季状态，按赛季降序返回。

后端使用单一配置源定义：

```text
MIN_SYNC_SEASON = 15
CURRENT_SEASON = 当前应用支持赛季
```

前端不得再定义 `COMMAND_CENTER_SEASONS = [21, 22, 23]` 或等价固定数组。当前赛季从 S23 升到 S24 时，只更新后端配置源及对应测试期望。

## 9. 数据流

```text
进入指挥台
  -> getOnboardingStatus
  -> currentSeason + syncableSeasons + seasonStatuses
  -> 左侧默认选择 currentSeason
  -> 右侧渲染已有赛季台账

用户选择 S18
  -> 仅更新指挥台本地 selectedSeason
  -> 不请求其他页面、不自动同步

用户点击同步 S18
  -> 复用现有 syncSeason(18)
  -> 复用账号与目标门禁、上游抓取、脱敏落盘、SQLite 导入
  -> 同步成功后清理对局页缓存
  -> 重新加载 onboarding status
  -> S18 成功存在本地数据时进入右侧台账
```

## 10. 错误与并发规则

- 继续使用现有账号操作与赛季同步互斥门禁。
- 同一时刻最多一个赛季同步任务。
- 同步失败不清空或覆盖右侧旧台账数据。
- 错误在左侧所属操作附近显示中文安全摘要和恢复动作。
- 上游空赛季、网络错误、429、详情部分失败继续沿用现有后端语义；不得把 raw JSON、token、`customerToken` 或 authorization 返回前端。
- 详情部分失败时，成功导入的数据仍按现有规则更新该赛季行，覆盖率反映实际详情数量。
- 页面卸载、账号重新识别或目标切换时，不允许过期请求覆盖新状态。

## 11. 视觉与可访问性

- 沿用 `design.md` 的灰绿画布、低对比表面、深炭黑主操作和紫色数据进度。
- 左右工作区最多一层明显圆角表面，内部使用留白和细分隔线。
- 标题、表头、数值和状态只使用既有黑灰文字层级；紫色只用于覆盖度进度、选中指示和焦点。
- 所有按钮、下拉框和可选择行的命中区至少 44px。
- 正文对比度至少 4.5:1，进度图形至少 3:1，并始终附带百分比文本。
- 加载、空、错误和禁用状态保持布局稳定。
- `prefers-reduced-motion` 下取消非必要位移；同步状态变化不依赖动画才能理解。

## 13. 测试策略

### 13.1 后端

- 当前赛季为 S23 时，`syncableSeasons` 严格返回 `[23, 22, ..., 15]`。
- 数据库只有 S15、S20、S23 数据时，`seasonStatuses` 仅返回这三行且顺序为 `[23, 20, 15]`。
- 空库时 `seasonStatuses` 为空，但 `syncableSeasons` 仍完整可用。
- 不再为请求选中但无数据的赛季合成零状态行。
- 现有赛季隔离、重复同步幂等和敏感字段脱敏测试继续通过。

### 13.2 前端

- 页面不包含固定 S21/S22/S23 数组或三段式赛季控件。
- 默认选择后端 `currentSeason`。
- 下拉选项完全来自 `syncableSeasons`。
- 右侧只渲染 `seasonStatuses` 中存在的赛季。
- 点击台账行只更新左侧选择，不自动调用同步。
- 首次同步成功后新增一行；重新同步后原位刷新且不重复。
- 同步失败保留旧行并显示可恢复错误。
- 空库显示中文空状态且不重复主按钮。
- 登录、目标未确认、账号操作中和同步中的禁用原因可见。
- 键盘可以操作下拉框、同步按钮和台账行，焦点顺序与视觉顺序一致。

### 13.3 视觉验收

- 在 `2540x1344`、`1920x1080`、`1440x900` 验证左右布局、上下折叠和页面滚动。
- 验证 S15 到当前赛季的完整下拉列表不会溢出。
- 验证空台账、单行、多行、同步中、失败和禁用状态。
- 使用匿名 fixture 或合成数据，不读取或截图真实凭据、浏览器 profile、真实数据 dump 或原始玩家隐私 ID。

## 14. 验收标准

- 用户可以从 S15 到当前赛季选择任一赛季并发起单季同步。
- 页面不再显示固定 S21/S22/S23 三段式控件。
- 左侧只承担赛季选择、同步和状态反馈，不显示本地已有赛季摘要。
- 右侧以一季一行展示赛季、详情覆盖度、本地对局和最近同步时间。
- 未同步赛季不显示零数据行。
- 当前赛季升级只需要修改一处后端配置源。
- 同步入口唯一，任务串行，失败不破坏已有台账。
- 其他页面的赛季筛选、SQLite schema、上游协议和账号目标流程保持不变。
- 自动化测试、前端构建、Rust 测试和三个目标分辨率视觉验收全部通过。
- 验证过程不读取、打印、记录或提交任何真实凭据、token-like 字段、浏览器 profile 或真实数据 dump。
