# 对局详情小队分组设计

## 背景

原始对局玩家记录包含 `friendBnetIds`，但当前详情投影没有保留可供界面分组使用的匿名信息。现有对局工作台将己方和敌方玩家按原始顺序平铺，并在整张队伍表和每个玩家行左侧使用阵营色竖条。该视觉只能表示阵营，不能表示哪些玩家属于同一小队。

当前产品通过 `/matches` 工作台在列表右侧展示详情。`/matches/:matchId` 独立完整详情页没有可见 UI 入口；对局列表测试也明确要求选中对局时不得跳离工作台。独立页面及其路由属于历史遗留，应随本次变更删除。

## 目标

- 使用同阵营玩家记录中的 `friendBnetIds` 推导小队。
- 将同一小队的玩家稳定排列在相邻行。
- 每个两人及以上的小队只显示一根连续的阵营色竖条。
- 单排玩家不显示竖条。
- 普通对局、角斗总览和每个角斗回合采用相同规则。
- 删除无入口的独立完整详情页和 `/matches/:matchId` 路由。

## 非目标

- 不推断跨对局的长期好友关系。
- 不把 `friendBnetIds`、玩家 ID 列表或由玩家 ID 拼接出的标识新增到前端 DTO。
- 不修改 SQLite schema、同步协议或原始 JSON。
- 不恢复独立详情页，也不新增另一套详情展示。
- 不引入新的品牌色、字体、圆角、阴影或卡片语言。

## 数据与模块边界

后端详情查询继续以玩家原始记录中的 `friendBnetIds` 为唯一分组来源。每个阵营、每个详情切片独立计算，不允许己方与敌方之间或不同角斗回合之间串组。

`PlayerRow` 只新增匿名、局部有效的 `partyGroup`：

- 两人及以上的小队获得同一局部小队序号。
- 单排玩家的 `partyGroup` 为 `null`。
- 序号只在当前阵营的当前详情切片中有意义。
- 序号不得包含或可逆推导玩家 ID。

普通对局详情、角斗总览和每个角斗回合都通过同一个分组函数生成排序后的 `PlayerRow`，避免前端读取 `rawJson` 或在多个展示入口重复解释上游数据。

## 分组算法

1. 以当前阵营玩家的原始顺序建立稳定位置。
2. 使用当前阵营内存在的 `bnetId` 建立玩家索引。
3. 读取每个玩家的 `friendBnetIds`：
   - 缺失、空值、非数组和无法转换的值按空集合处理。
   - 重复引用去重。
   - 不在当前阵营中的引用忽略，包括敌方玩家和当前切片之外的玩家。
4. 将有效引用视为无向边。单向记录同样建立连接。
5. 求无向图的连通分量。A 关联 B、B 关联 C 时，A、B、C 属于同一小队。
6. 只有成员数至少为二的连通分量获得 `partyGroup`。
7. 按原始顺序扫描玩家：
   - 首次遇到一个小队成员时，立即输出该小队全部成员；
   - 小队内部保持原始相对顺序；
   - 不同小队和单排玩家以首次出现位置为基准，保持稳定相对顺序。

异常重复的 `bnetId` 不得导致崩溃。索引使用首次出现的玩家建立关系，输出仍保留原始行，且不得跨阵营合并。

## 界面设计

`MatchTeamTable` 接收已排序的玩家列表，并按连续且相同的 `partyGroup` 构造视觉组。

- 删除当前贯穿整张队伍表的 `matchTeamTableMarker`。
- 删除每个玩家行的阵营色左边框，恢复中性边框。
- 小队视觉组在玩家卡片外侧、英雄头像左侧绘制一根连续竖条。
- 己方使用既有 `--data-secondary`，敌方使用既有 `--status-danger`。
- 每个小队只有一根竖条；多个小队各自拥有独立竖条并以正常行距隔开。
- 单排玩家不创建小队视觉组，不显示竖条。
- 角斗玩家行展开时，竖条覆盖该小队的完整区域，包括展开内容，避免把小队视觉截断。

视觉采用已确认的“组外连续竖条”方案，不使用逐行分段竖条或括号式新图形语言。

## 可访问性

- 玩家 DOM 顺序与视觉顺序保持一致，键盘与读屏顺序不会偏离画面。
- 竖条为装饰元素并使用 `aria-hidden="true"`。
- 两人及以上的小队容器提供中文无障碍标签，例如“3 人小队”。
- 不在无障碍文本、日志或错误消息中加入原始玩家 ID 或 `friendBnetIds`。

## 独立详情页清理

- 删除 `MatchDetailPage` 及其专属状态、请求和展示实现。
- 从 `App.tsx` 删除 `/matches/:matchId` 路由与对应 import。
- 删除或改写只验证旧独立页面的测试。
- 保留 `/matches` 工作台详情面板、收藏、AI 锐评、角斗回合及玩家汇总能力。
- 复盘后端现存的 `/matches/<id>` 证据链接当前没有前端消费者。后续若恢复“查看比赛”入口，应改为工作台可消费的选中对局链接，不得恢复独立页面。
- QA 路径标签等仅服务旧详情路由的映射一并删除或改为工作台语义。

## 错误处理

分组是详情展示增强，不得成为详情加载的失败条件。任何缺失或异常的 `friendBnetIds` 都回退为无分组；玩家数据仍按稳定规则显示。无效引用被忽略，不向用户显示错误，也不输出原始 ID、路径、行或 payload。

## 测试

### 后端

- 双排得到同一 `partyGroup`。
- 单向关系能够成组。
- A-B、B-C 的传递关系合并为三人小队。
- 多个小队分别编号且成员相邻。
- 单排玩家保持 `partyGroup = null`。
- 缺失、空值、重复值、无效值和敌方引用被安全忽略。
- 小队内部、不同小队和单排玩家的稳定排序符合规则。
- 普通详情、角斗总览与角斗回合都使用相同分组语义。

### 前端

- 每个小队只渲染一根连续竖条。
- 己方与敌方竖条分别使用既有绿色和红色变量。
- 单排玩家不渲染竖条。
- 多个小队形成彼此分离的视觉组。
- 角斗展开内容位于对应小队竖条范围内。
- 普通详情、角斗总览和回合复用 `MatchTeamTable`。
- `/matches/:matchId` 路由、独立详情页 import 和旧页面专属测试已移除。

### 交付验证

- 后端：`cargo fmt --check`、`cargo test --tests`。
- 前端：相关定向测试、`npm test`、`npm run build`。
- 变更检查：`git diff --check`、`git status --short`。
- 本任务不读取真实凭据、本机真实 SQLite 或真实用户数据。
