# 战报概览三项事实带设计

## 目标

精简战报“概览”页面的首屏信息：移除职责与英雄模块之后的“赛季概览 / 稳定表现”与“本季摘要 / 关键表现”，将职责段位与英雄池模块底部改为三项并列赛季事实。

## 范围

- 保留“职责段位与英雄池”主面板及四个职责段位卡。
- 删除概览中的赛季概览面板与本季摘要面板。
- 在职责卡片下方显示三项事实：常用英雄、赛季对局、总胜率。
- 常用英雄按当前赛季使用场次降序取前三名，仅显示三个英雄头像；不显示英雄名称、场次、胜率、提示气泡或其他文字。
- 赛季对局复用当前 `review.summary.totalMatches`；总胜率复用当前 `review.summary.winRate`。
- 保留概览中的地图分析、队友协作、成就、页面级赛季选择和既有 URL 行为。

## 布局与视觉

```text
职责段位与英雄池
[重装职责卡] [输出职责卡] [支援职责卡] [开放职责卡]

常用英雄  [头像] [头像] [头像] | 赛季对局 704 场 | 总胜率 52%
```

- 三项横向均分，使用现有透明弱表面和 `1px` 细分隔线；不新增独立小卡、颜色、字体、圆角或阴影。
- 英雄头像使用已打包的本地英雄资源，并提供中文 `alt` 文本；资源缺失时使用稳定中文文本兜底，不暴露原始标识。
- 宽屏保持单行三列；窄屏按现有响应式规则换为单列或两列，避免横向滚动。
- “常用英雄”是一个整体指标，头像之间采用紧凑的 `8px` 间距；不足三名时仅显示已有头像，不补造占位英雄。

## 数据与边界

- 不修改后端、API、共享类型、数据库、同步逻辑或赛季统计口径。
- 继续使用 `review.heroPool.mainHeroes` 的既有排序结果；前端至多取前三项。
- 不新增全局赛季状态，数据继续来自当前页面已选择的赛季。

## 补充：角斗竞技职责段位

- 职责段位区保留既有的预设竞技重装、输出、支援与开放四张卡片，并在其下新增“角斗竞技”分组。
- 角斗竞技固定显示重装、输出、支援三张卡片，沿用既有卡片中的段位、胜率、场次和 KDA 格式。
- 后端新增独立的 `stadiumRoleSummaries` 返回字段，只聚合当前赛季 `SportFight` 对局；不混入 `LeisureFight` 或预设竞技数据。
- 角斗段位由当前登录账号在对局总计中的 `rankInfo` 读取，并使用已打包的角斗段位资源；预设竞技继续使用原有段位资源与原有 `roleSummaries`。
- 不新增数据库 schema 或持久化 payload；仅查询已脱敏保存的对局详情，且不向 UI、日志或 DTO 暴露账号标识。

## 状态与可访问性

- 数据不足时：常用英雄区域显示“样本不足”，赛季对局与总胜率沿用现有安全格式化与零值行为。
- 三个英雄头像均有中文替代文本；纯展示头像不增加无行为的可点击控件。
- 指标数值使用等宽数字，正文与标签保持设计规范的对比度。

## 验收

- 概览页不再渲染“赛季概览”“稳定表现”“本季摘要”“关键表现”。
- 职责段位卡下方仅有“常用英雄”“赛季对局”“总胜率”三项。
- 常用英雄仅显示最多三个头像，不出现英雄名称、场次或胜率。
- 切换赛季后，三个头像、对局数、总胜率与该赛季数据一致。
- 运行相关前端测试、`npm run build` 和 `git diff --check`；确认未接触真实隐私数据。
