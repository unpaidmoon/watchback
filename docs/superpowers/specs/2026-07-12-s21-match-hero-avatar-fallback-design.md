# S21 对局列表英雄头像兼容设计

## 目标

让已同步的 S21 历史对局在英雄名称缺失、仅保留旧数字英雄标识时，仍能显示已随应用打包的英雄头像；不要求重新同步或修改 SQLite 历史记录。

## 根因

对局卡片把 `heroGuid` 和 `heroName` 交给前端资源解析器。资源清单只以稳定资源 key、英文名和中文名建立索引；旧数字英雄标识不能直接命中图像文件。历史导入记录若没有 `heroName`，候选地址全部失效，卡片显示空头像。

## 方案

`src/shared/assets.ts` 已加载受跟踪、运行时内置的 `ow-lookups.json`。扩展其前端类型并在构造英雄资源查找表时，将 `heroes` 字典中每个数字标识映射到对应中文英雄名，再经现有 manifest 查找表解析为稳定资源 key。

该映射只影响头像 URL 候选生成：

1. 已有资源 key、英文名、中文名和别名的解析保持不变。
2. 旧数字英雄标识解析为同一张已打包的头像。
3. 未知标识仍返回原有的空头像占位，不展示原始 ID。

## 验证

在 `phase6Assets.test.ts` 增加一个运行时字典中的旧数字标识断言。先运行测试观察失败，再实现映射并运行该测试、完整前端测试和生产构建。不会读取真实凭据、浏览器 profile 或玩家数据。
