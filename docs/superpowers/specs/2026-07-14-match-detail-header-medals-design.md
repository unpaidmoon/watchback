# 对局详情头图与奖牌迁移设计

## 目标

重构普通对局的详情首屏，使其以地图预览为背景、结果色斜切块为主视觉；移除“个人摘要 / 本人表现”模块，并将其评级、表现标签和同队奖牌直接放入左侧对局列表行。胜利使用浅绿色结果块，失败与平局均使用浅灰色结果块；不使用橙色或新增品牌色。

## 范围

- 仅覆盖 `/matches` 工作台中的普通对局列表与普通对局详情，包含窄屏下由 `MatchesPage.tsx` 呈现的内嵌详情路径。
- 普通对局详情头部使用现有 `MapPreview` 可访问的地图预览资源；图片加载失败时保持可读的表面和文字对比度。
- 复用 `MatchSummary.evaluation` 与 `MatchSummary.teamAwards`，列表行不新增 Tauri 命令、SQLite 列、网络请求或持久化数据。
- 角斗详情继续保留回合切换、角斗头部和当前内容结构，不移除或迁移其中不存在的“个人摘要”模块。

## 不在范围

- 不改变比赛筛选、排序、上下场切换、得分规则、奖牌规则或比赛详情 DTO。
- 不新增全局赛季状态，不调整其他页面，也不修改玩家、英雄、地图的隐私兜底规则。
- 不引入新的图片文件、字体、圆角、阴影、品牌色或本机绝对路径。

## 视觉与交互

### 详情头图

- `MatchDetailHeader` 改为一层全宽横幅：地图预览铺满背景，叠加现有设计令文字始终可读的低对比遮罩。
- 左侧放置结果文字与英文辅助文字的斜切色块。`win` 为设计令牌派生的浅绿色，`loss`、`draw` 与未知结果为浅灰色；色块只表达结果，不使用红色、橙色或渐变。
- 右侧保持地图名、比分、模式、时长、开始时间，以及“上一场 / 下一场”导航。比分使用等宽数字，窄屏时导航换至横幅底部且不遮挡标题。
- 头图自身不再重复放入个人评分或奖牌，避免与列表行的信息竞争。

### 列表行的表现信息

- `MatchListCard` 在英雄名后的既有表现区域展示 `MatchPerformanceBadges` 的紧凑样式：主标签、评级和由 `teamAwards` 归一化后的奖牌。
- 当没有评分且没有奖牌时，沿用既有“-”占位，不制造空白跳动；每枚奖牌保持当前 `title` 与无障碍名称。
- 评分/奖牌属于该场比赛的扫描信息，因而留在可连续浏览的对局列表；详情选中态、键盘选择和卡片点击行为不变。

### 详情内容

- 普通对局从头图后直接进入“队伍对比”，完全删除 `matchDetailPerformance` 容器及其“个人摘要 / 本人表现 / 评分与同队奖牌”文案。
- 详情的加载、错误、空状态以及前后场导航保持原行为；角斗的 `CompactArenaDetail` 不受影响。

## 组件与数据流

```text
list_match_timeline
  -> MatchSummary(evaluation, teamAwards)
  -> MatchListCard
  -> MatchPerformanceBadges(compact)

get_match_details
  -> CompactMatchDetail（普通对局）
  -> MatchDetailHeader（地图预览横幅）
  -> MatchTeamTable
```

列表端已经从 `list_match_timeline` 获得 `evaluation` 与 `teamAwards`；只在前端复用现有 `normalizeMatchAwards`，不把详情加载变成列表渲染的前置条件。详情仍可返回 `evaluation` 与 `teamAwards` 以保持 DTO 向后兼容，但普通详情不再消费它们。

## 响应式与可访问性

- 宽屏：横幅为左侧斜切结果、右侧地图/比分/导航的单行布局。
- 窄屏：结果、标题与比分优先保留；元信息折行，导航移至下一行，保证 44px 最小可点击高度。
- 地图图像是装饰性背景；文字有遮罩与足够对比度，结果不只依赖颜色表达。
- 奖牌继续提供中文 `title`、`aria-label`，列表卡片现有键盘焦点和 `aria-current` 不变。

## 验收与测试

- 列表行在有评分/奖牌的 fixture 中显示主标签、评级与全部奖牌；缺失数据时显示既有占位。
- 普通详情不再渲染“个人摘要”“本人表现”或 `matchDetailPerformance`；角斗详情的回合与队伍表不回归。
- 胜利头图为浅绿色斜切结果块，失败、平局和未知结果为浅灰色；不出现橙色结果样式。
- 验证内嵌详情和独立详情两条渲染路径、窄屏布局、键盘焦点与图片加载失败回退。
- 运行相关前端测试、`npm run build`、`git diff --check`；实现完成时再按项目约定运行完整前后端验证。
