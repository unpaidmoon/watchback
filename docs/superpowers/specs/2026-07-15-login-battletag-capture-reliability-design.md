# 登录 BattleTag 抓取可靠性改进设计

- 日期：2026-07-15
- 状态：已确认
- 适用范围：`apps/owstats-desktop` 网易大神浏览器登录、BattleTag 自动识别与当前账号目标绑定
- 前置设计：`docs/superpowers/specs/2026-07-14-login-battletag-auto-binding-design.md`

## 背景与诊断结论

浏览器登录后，网易大神页面会显示类似以下内容：

```text
战网昵称: 示例玩家#1234
```

当前桌面端已经能够从浏览器上下文取得 `role_id`，并通过签名接口换取账号 token，但登录结果仍进入“未能自动识别战网昵称”状态。

本次只读诊断得到以下证据：

1. 现有 Rust BattleTag 解析测试 6 项全部通过，完整单行文本可以正确解析。
2. 使用真实 Chromium 构造合成 DOM 后，标签和值位于同一节点时能够解析。
3. 当前置图标、标签和值分属不同内联节点时，`document.documentElement.innerText` 可能在标签前加入其他字符，现有“整行必须以标签开头”规则会漏识别。
4. 当 Flex 布局把标签和值拆到不同文本行时，现有逐行解析无法把两者重新关联。
5. 即使页面 BattleTag 已提取，现有身份状态机仍要求同一页面证据内出现 `role_id`。实际 `role_id` 经常来自 storage 或 resource URL，因此状态机会主动丢弃可见 BattleTag。

因此问题同时存在于两个边界：页面文字到 BattleTag 候选的提取过度依赖 `innerText` 行结构；BattleTag 与已确认凭据角色的配对规则又比实际页面证据更严格。只修复其中一处不能可靠解决真实登录问题。

## 目标

- 可靠识别页面明确显示的“战网昵称”BattleTag。
- 支持标签和值位于同一节点或相邻节点、前面有图标、后面有按钮的页面结构。
- 支持在同一登录轮次内，将连续稳定的可见 BattleTag 与唯一成功换取 token 的 `role_id` 配对。
- 保留账号切换、冲突拒绝、目标确认和同步门禁。
- BattleTag 缺失时仍允许凭据登录成功，但禁止赛季同步。
- 不读取、打印或持久化页面全文、DOM 快照、候选数组或敏感凭据。

## 非目标

- 不恢复手工 BattleTag 输入或任意玩家绑定入口。
- 不使用 OCR 或截图识别。
- 不新增多账号历史、`role_id -> BattleTag` 映射表或全局账号缓存。
- 不修改 `searchBnetAccount`、`queryCard`、赛季抓取、导入或 SQLite schema。
- 不把 token、`customerToken`、cookie、authorization 或原始页面内容返回前端。
- 不承诺读取不可访问的跨域 iframe；无法安全读取时保持未识别状态。

## 方案选择

采用“DOM 标签候选采集 + 同轮次凭据角色配对”的组合方案。

仅放宽身份配对无法解决标签和值被 DOM 节点拆分的问题；仅增强 DOM 解析又会继续被现有同源 `role_id` 门禁丢弃。通过同时修复两个明确边界，可以在不扩大产品入口和隐私面的前提下恢复当前账号自动识别。

不采用 token 换取后的新上游资料接口方案，因为该方案需要重新发现和维护私有协议，并扩大上游请求与隐私范围。

## 浏览器采集契约

`build_collect_candidates_script()` 继续返回现有 `roleCandidates`，并新增最小化的 `battleTagCandidates`。

BattleTag DOM 采集遵循以下规则：

1. 在当前文档与可访问的同源 iframe 中寻找包含“战网昵称”标签的最小文本节点或元素。
2. 优先读取标签节点自身的剩余文本；不足时只组合必要的相邻节点文本，直到得到一个完整候选或越过合理边界。
3. 允许中文冒号、英文冒号、Unicode 空白、标签和值拆分、前置图标以及尾随按钮。
4. 候选必须包含非空名称、单个 `#` 和非空纯数字后缀。
5. 只返回最小候选字符串，不返回页面全文、父级大段文本、DOM HTML 或节点路径。
6. 对候选数量设置小型固定上限；超过上限时标记冲突，不截断后继续猜测。

现有 `pageText` 可以继续作为当前 `role_id` 证据的一部分，但 BattleTag 不再依赖对页面全文逐行执行固定前缀解析。

## Rust 解析与规范化

Rust 接收 `battleTagCandidates` 后负责最终验证：

- 去除首尾空白并统一中文/英文冒号后的值读取。
- 验证 `名称#数字` 结构。
- 多个相同结果去重为一个结果。
- 多个不同有效结果返回 `Conflict`。
- 空数组、无效格式或浏览器采集失败返回 `Missing`。

浏览器脚本只缩小证据范围，不作为最终可信校验层；格式、去重和冲突判定继续由 Rust 控制。

## 登录轮次与身份配对

配对规则调整为：

1. 每次重新登录创建新的捕获轮次，并清空旧 BattleTag 候选和待确认状态。
2. 浏览器连续两次采集到相同的唯一 BattleTag，才视为稳定候选。
3. `role_id` 仍通过现有候选与签名换取流程取得；只有 `getReportToken` 成功返回且返回角色与请求角色一致时，才视为已确认凭据角色。
4. 稳定 BattleTag 与本轮唯一已确认凭据角色形成配对，不再要求 `role_id` 同时出现在页面正文。
5. 凭据角色变化、BattleTag 缺失、BattleTag 冲突或开始新轮次时，未完成配对立即失效。
6. 跳转签名页面前已经稳定且与当前请求角色关联的候选，可以在本轮凭据换取期间保留。
7. 新 token 不得与上一轮或另一角色的 BattleTag 组合。

该规则接受用户确认的安全边界：专用登录浏览器中连续稳定的可见 BattleTag，可以与同一登录轮次唯一成功换取 token 的 `role_id` 配对。

## 后续目标处理

形成 `(role_id, BattleTag)` 配对后，保持现有流程：

```text
稳定 BattleTag + 已确认凭据角色
  -> reconcile_detected_target
  -> searchBnetAccount
  -> queryCard 身份确认
  -> 保存单一当前目标
  -> 解锁单赛季同步
```

- 没有已有目标时自动解析并保存。
- 已有相同目标时保持现状，不重复绑定。
- 已有不同目标时进入切换确认，不自动覆盖。
- 搜索或资料卡失败时保留凭据登录成功状态，并显示可重试的绑定失败状态。
- 未识别 BattleTag 时进入 `unidentified`，同步保持禁用。

## 用户可见行为

- 正常登录后自动显示并绑定当前页面 BattleTag。
- 提取仍未成功时，显示“登录成功，但未能自动识别战网昵称”，提供“重新识别”。
- 不出现 BattleTag 输入框、任意搜索或手工绑定按钮。
- 多账号不一致时继续显示当前目标与检测到的账号，并要求用户确认。
- 页面采集、候选稳定和凭据换取期间不向 UI 暴露原始诊断数据。

## 错误处理与隐私

- DOM 无标签、候选格式无效或跨域内容不可访问：返回未识别，不猜测。
- 多个不同有效候选：返回冲突并禁用同步。
- 浏览器脚本执行失败：保留当前凭据轮询能力，不记录脚本返回的原始内容。
- token 换取成功但 BattleTag 未稳定：保存凭据，目标保持不可用。
- 所有错误消息继续通过现有脱敏函数处理。
- 测试和诊断只记录状态、数量和是否匹配，不记录真实 BattleTag、页面全文或任何 secret。

## 测试策略

### Rust 单元与状态机测试

- 标签和值同节点。
- 标签和值分节点。
- 前置图标、尾随按钮、中文/英文冒号和 Unicode 空白。
- 相同候选去重、不同候选冲突、无效后缀拒绝。
- storage/resource 提供唯一凭据角色时，允许与连续稳定 BattleTag 配对。
- 凭据角色变化、候选缺失、候选冲突和新登录轮次清空旧候选。
- token 返回角色与请求角色不一致时拒绝配对。
- 新 token 不得复用上一轮 BattleTag。

### 浏览器合成验收

使用 Playwright 构造不含真实账号的 DOM：

- 单文本节点。
- 内联图标 + 标签和值。
- 标签和值相邻分离。
- Flex 节点分离。
- 同源 iframe。

验证浏览器只返回最小候选，Rust 解析结果符合预期，且无页面全文进入日志或产物。

### 回归验证

- 登录定向 Rust 测试。
- `cargo fmt --check`。
- `cargo test --tests`。
- `npm test`。
- `npm run build`。
- `git diff --check` 与敏感字段扫描。
- 真实登录仅由用户手工验收，验收记录只写通过或失败，不记录账号值。

## 验收标准

- 页面以截图所示方式显示“战网昵称”时，应用能够自动识别当前 BattleTag。
- DOM 中存在前置图标、尾随按钮或标签/值拆分时仍能识别。
- 连续两次稳定 BattleTag 可以与本轮唯一已确认凭据 `role_id` 配对。
- 缺失、冲突、角色变化和新登录轮次不会复用旧 BattleTag。
- 自动识别成功后沿用现有安全目标解析与确认流程。
- 所有产品界面仍不提供手工 BattleTag 输入或任意目标绑定。
- 自动化测试不读取真实凭据、浏览器 profile 或真实玩家数据。
