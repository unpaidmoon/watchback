# 生涯 MMR 个人表现修正保证上线设计

日期：2026-07-20

## 1. 目标

在只使用当前两个本地账号既有赛季数据的前提下，为生涯 MMR 启用个人表现修正。上线不再以“某一套复杂学习模型必须通过全部原门槛”为前提，而是采用逐级降级的模型体系：优先使用约束学习模型；证据不足时使用强收缩模型；仍不稳定时使用职责内稳健百分位模型。最终必须有一套非零、可解释、受严格上限保护的个人表现修正上线。

本功能继续明确标注为 OWStatsLocal 本地推算，不是暴雪官方隐藏分。胜负与对局强度仍是 MMR 主干，个人表现只能做小幅校准。

## 2. 数据接入修复

普通比赛的当前玩家身份继续来自 `match_players` 中唯一的 `is_current_player=1` 行。角斗比赛不得再依赖 `match_players`，而应使用当前账号 manifest 中的 `battleTag` 在 `arena_match_players.player_name` 中寻找同场唯一匹配行，并取得该行的 `bnet_id`。只有恰好一个匹配时才能将最终有效回合中的玩家统计投影为当前账号数据；零个或多个匹配都必须排除并计入匿名诊断计数。

训练源发现阶段把账号 `battleTag` 作为只读投影参数传入，不得将其写入报告、日志、模型产物或跨账号 DTO。训练仍以查询只读连接打开账号数据库，并验证训练过程没有修改源库。

角斗详情只使用排序后的最后一个结构有效回合，不累计或平均全部回合。修复后预期可恢复现有 1,102 场角斗竞技和 39 场角斗快速的身份投影；实际可训练行数由最终回合完整性、唯一身份匹配和职责映射决定，不能把 1,141 场直接视为全部有效。

## 3. 共享训练组

训练使用两个共享参数组：

1. `ordinary-shared-v3`：职责竞技、职责快速、开放竞技、开放快速共享核心特征系数。
2. `stadium-shared-v3`：角斗竞技、角斗快速共享核心特征系数。

共享参数不代表混合评分。每个实际模式必须独立建立英雄/模式/赛季稳健基线，保留独立样本权重、预期胜率、验证指标、MMR 影响权重与单场上限。普通模式与角斗模式不得共享原始表现基线。

正式胜负基础权重保持：职责竞技 1.0、开放竞技 1.0、职责快速 0.3、开放快速 0.3、角斗竞技 0.5、角斗快速 0.1。竞技基础变化上限保持 +/-30，快速保持 +/-10。

## 4. 三级保证上线模型

### 4.1 一级：约束学习模型

一级模型使用现有完整训练矩阵、逐模式稳健归一化、滚动时间验证、赛季留一、英雄留一、账号留一和聚类 bootstrap。系数必须满足业务方向约束：死亡不得正向；最后一击不得负向；普通击杀参与不得负向；资源债务不得正向。缺失特征不产生奖励或惩罚。

一级门槛调整为：

- 5 个 forward 折至少 3 折 Brier 优于胜负基线。
- 聚合 Brier 点估计必须优于胜负基线，95% CI 上界不高于 `+0.01`。
- ECE 相对基线恶化不超过 `0.02`。
- 赛季留一至少 2 个有效组；英雄留一至少 3 个有效组。
- 赛季、英雄留一的恶化组比例均不超过 40%。
- 账号留一必须覆盖当前全部已登记训练账号。
- bootstrap 完成率至少 80%，受约束关键方向稳定率至少 75%。
- 单一特征的绝对贡献不超过总绝对贡献的 50%。
- 训练 worker 不得出错，所有指标和系数必须为有限值。

满足门槛的职责使用一级模型。门槛按职责判断；同一职责内，共享训练组中的模式复用相同核心系数，但应用各自模式基线和缩放。

### 4.2 二级：强收缩模型

未通过一级门槛的职责必须进入二级模型，而不是退回零修正。二级模型从一级拟合结果中只保留方向稳定率至少 60% 且符号符合业务约束的特征；其余系数设为 0。保留系数统一乘以收缩因子，使训练集与所有有效验证折中的平均绝对修正均不超过 `0.05 MMR`。

二级上线门槛只保留不可取消的正确性要求：所有输出有限；聚合 Brier 不得比胜负基线恶化超过 `0.01`；影子重放不得翻转胜负基础变化方向；修正均值的绝对值不超过 `0.05 MMR`；任何职责/模式的修正封顶率不超过 5%。无法满足时进入三级模型。

二级正式上限为：竞技不超过基础变化绝对值的 5% 且绝对值不超过 `1.0 MMR`；普通快速不超过 5% 且绝对值不超过 `0.25 MMR`；角斗快速不超过 5% 且绝对值不超过 `0.10 MMR`。

### 4.3 三级：职责内稳健百分位模型

三级模型是保证上线的最终模型。它不使用不稳定回归系数，而使用训练集建立的“职责 + 训练环境 + 实际模式 + 英雄”稳健分布。样本不足时依次回退到“职责 + 环境 + 模式”和“职责 + 环境”。普通环境与角斗环境不交叉回退。

只使用覆盖可靠且方向明确的指标：最后一击、非最后一击参与、助攻、死亡，以及各职责已有可靠投影的核心输出。每项先转换为按 10 分钟统计，再转换为截断在 `[-1, 1]` 的稳健百分位分。死亡取反，其余正向指标按等权合成；缺失项不参与分母。至少两个有效指标才允许产生修正，否则使用仅含死亡与击杀参与的最小组合；二者仍不完整时产生固定最小幅度 `+/-0.01 MMR`，符号由已存在的单项稳健百分位决定。没有任何个人统计的比赛不伪造表现，修正为 0，但不影响该职责的模型处于启用状态。

三级模型在训练基线上按职责和实际模式重新居中，使样本加权平均修正为 0。正式上限为：竞技 `+/-0.5 MMR`，普通快速 `+/-0.1 MMR`，角斗快速 `+/-0.05 MMR`。

## 5. 正式评分约束

所有层级统一遵守：

- 个人修正不得让败局最终加分，也不得让胜局最终扣分。
- 平局可以正负微调，但最终变化不得超过对应模式上限。
- 基础变化为 0 时个人修正必须为 0。
- 输入缺失、非有限或无法识别职责时不得猜测。
- 单场总变化仍受竞技 +/-30、快速 +/-10 的硬上限约束。
- 角斗快速可以参与 `stadium-shared-v3` 参数学习和验证，并允许应用极小正式修正，但不得单独决定角斗共享模型是否晋级。
- 模型选择和修正必须完全确定，同一输入重放得到相同事件摘要。

## 6. 模型产物与激活

训练产物按职责记录选用层级、特征/系数或百分位基线、共享训练组版本、逐模式缩放、配置哈希、训练阶段和匿名验证摘要。模型产物不得包含账号标识、BattleTag、比赛 ID、文件路径、原始行或原始 JSON。

新增正式模型版本 `v3`。激活操作必须在同一 SQLite 事务中完成：验证产物结构与配置哈希，重放全部输入，写入 v3 事件与摘要，完成完整性检查后再把 v3 设为唯一 active。任何失败都回滚并保留 v2 完整结果。

v3 的每条事件保存 `performance_adjustment` 和所选模型层级，但解释接口只返回中文可读因素和匿名数值，不暴露模型训练来源。v2 数据不得重写或删除，以便快速回滚。

## 7. 上线与回滚

正式启用前必须用两个账号的只读训练源执行完整投影和影子重放。三个职责都必须选择一级、二级或三级之一；不得存在“未选择模型”的职责。只要不可取消的正确性约束通过，即可激活 v3，不再要求所有职责都达到一级门槛。

回滚通过把 active 模型版本切回 v2，并重新读取 v2 摘要完成，不重新导入、不修改比赛数据、不删除 v3。UI 必须显示当前模型版本，并继续说明这是本地推算。

## 8. 测试与验收

自动测试至少覆盖：

- 角斗比赛在 `match_players` 为 0 行时可通过唯一 BattleTag 从 `arena_match_players` 定位当前玩家。
- BattleTag 零匹配或多匹配时整场排除，不使用插入顺序猜测。
- 普通四模式共享普通参数，角斗两模式共享角斗参数，且两个环境互不共享基线。
- 实际模式权重和单场上限保持独立。
- 一级失败必定选择二级；二级失败必定选择三级；三个职责最终都有激活模型。
- 每个层级都不能翻转胜负方向，不能输出非有限值，不能超过层级和模式上限。
- 相同数据库重复重放完全幂等；中途失败保留 v2。
- v3 查询、历史、模式分解、赛季分解和单场解释只读取 active 版本。
- 报告、模型和日志不包含账号、BattleTag、比赛 ID、路径或原始 payload。

上线验收必须运行职业 MMR 全部 Rust 测试、后端完整测试、前端测试与构建，并执行 `git diff --check`。训练和影子重放只报告阶段、匿名计数、耗时、模型层级和聚合指标，不人工读取真实凭据或原始隐私数据。

## 9. 明确不做

- 不恢复 BattleTag 绑定或 `searchBnetAccount` 旧产品流程。
- 不把表现模型描述为暴雪官方算法。
- 不把其他玩家持久化为长期 MMR 档案。
- 不为通过门槛而修改、删除或补造训练样本。
- 不把普通环境和角斗环境的原始表现基线混用。
- 不删除 v2 或历史 MMR 事件。
