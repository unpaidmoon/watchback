# 安装目录数据存储设计

## 背景

OWStatsLocal 当前通过 Tauri `app_data_dir` 保存账号索引、设置、登录凭据、浏览器 profile、SQLite、赛季 JSON、诊断和备份。在常规 Windows 环境中，这些内容位于 `%APPDATA%\local.owstats.desktop`。

产品目标调整为：继续使用 Windows 安装程序，但将 OWStatsLocal 自有的全部可写业务数据放在安装目录下；静态资产继续随应用正式打包；不再发布 MSI，只发布 NSIS 安装包。

系统组件不属于这一承诺。Windows、NSIS、WebView2 和浏览器可执行文件仍可能使用系统临时目录、运行时缓存或其他系统管理目录。

## 目标

- 数据根目录固定为 `<安装目录>\data`。
- 安装程序允许选择安装路径，包括非 C 盘和包含中文或空格的路径。
- 安装在 `Program Files` 时，普通用户可以修改 `data`，但不能修改程序文件。
- 全新安装不创建或使用 `%APPDATA%\local.owstats.desktop` 存放业务数据。
- 首次升级自动把旧 AppData 数据复制并校验到新数据目录。
- 覆盖升级保留 `data`。
- 卸载默认保留 `data`，用户明确选择后才删除。
- 静态 assets 随程序打包且保持只读，不复制到 `data`。
- 正式 Windows 发布物仅包含 NSIS 安装程序。

## 非目标

- 不保证操作系统、WebView2、NSIS 或外部浏览器在其他目录零写入。
- 不把静态 assets 改造成运行时可写资产。
- 不使用注册表保存业务数据路径。
- 不通过目录链接继续依赖 AppData。
- 不自动删除旧 AppData 副本。
- 不修改现有账号、事件或凭据 schema。

## 目录结构

```text
<安装目录>\
├─ OWStatsLocal.exe
├─ Tauri/WebView 打包资源
└─ data\
   ├─ accounts.json
   ├─ user_settings.json
   ├─ chrome-dashen-profile\
   ├─ .account-operations\
   └─ accounts\
      └─ <account_id>\
         ├─ account.json
         ├─ credentials.json
         ├─ player_target.json
         ├─ player_profile.json
         ├─ owstats.sqlite3
         ├─ seasons\
         ├─ diagnostics\
         └─ backups\
```

运行时从当前可执行文件所在目录解析数据根目录，不依赖当前工作目录、仓库布局、`CARGO_MANIFEST_DIR` 或开发机绝对路径。`SharedAppPaths` 仍是业务模块访问运行时路径的统一入口。

## 静态资源

正式资产仍遵循现有构建链：

```text
仓库根目录 assets\
  -> apps\owstats-desktop\public\assets\
  -> apps\owstats-desktop\dist\assets\
  -> Tauri 前端发布资源
```

应用继续通过 `/assets/...` URL 使用这些资源。安装后不得依赖一个可见的 Windows `assets` 绝对路径；资源可以由 Tauri 嵌入或作为安装资源部署。静态资源不进入可写 `data`。

## 运行时路径解析

应用启动时执行以下步骤：

1. 取得当前可执行文件的规范化父目录。
2. 将该目录下的 `data` 作为唯一业务数据根目录。
3. 确认 `data` 存在且当前用户可写。
4. 由 `SharedAppPaths` 从该根目录派生共享路径和账号路径。
5. 路径初始化失败时停止进入业务界面，显示中文可操作错误，不得静默回退到 AppData。

路径解析需要拒绝无法确定可执行文件父目录、目标不是目录以及目标不可写等异常。不得通过用户可控的相对路径扩大文件操作范围。

## 旧版数据迁移

当新 `data` 尚未初始化且 `%APPDATA%\local.owstats.desktop` 中存在旧数据时，应用在进入业务功能前执行一次迁移：

```text
%APPDATA%\local.owstats.desktop
  -> <安装目录>\data.migrating
  -> 校验
  -> <安装目录>\data
```

迁移规则：

- 只复制，不移动或删除旧目录。
- 先写入同一安装目录下的临时迁移目录，校验成功后原子发布。
- 校验至少覆盖账号索引可解析、账号目录结构有效、SQLite 可打开以及关键文件与目录边界正确。
- 不读取或输出凭据内容；诊断只允许阶段、匿名计数、耗时与文件大小。
- 迁移完成标记保存在新 `data` 内，不包含隐私数据。
- 中断后允许安全重试，不得混用新旧根目录。
- 新 `data` 已经初始化时始终以它为准，不允许旧目录覆盖。
- 目标空间不足、权限失败或校验失败时保留旧数据和可诊断的迁移状态，应用不得把半成品当作有效数据。

## 安装程序

Windows 正式发布目标从全部 bundle 类型收紧为 NSIS，不再生成或发布 MSI。

NSIS 安装流程负责：

- 允许用户选择安装目录。
- 部署程序及只读静态资源。
- 创建 `<安装目录>\data`。
- 只给当前用户授予 `data` 的读取、写入、修改和创建子目录权限，不放宽整个安装目录。
- 完成前验证 `data` 可写；失败时显示明确错误并中止。
- 不把业务数据、凭据或真实用户标识写入注册表或安装日志。

`data` 不属于安装文件清单中的可覆盖程序资源。

## 覆盖升级与路径变更

同一目录覆盖升级时，只更新程序和静态资源，保留整个 `data`。

升级或重新安装期间必须先确认应用已经退出，避免 SQLite、浏览器 profile 或后台同步仍在写入。

如果用户选择新的安装目录，安装流程需要：

1. 定位旧安装目录。
2. 将旧 `data` 复制到新目录的临时位置。
3. 完成与首次迁移等价的结构和 SQLite 校验。
4. 原子发布为新目录的 `data`。
5. 暂时保留旧副本，不自动删除。

新目录已有有效 `data` 时不得静默覆盖；安装程序应停止并给出中文冲突提示。

## 卸载

卸载界面提供“同时删除本地数据”选项，默认不勾选。

未勾选时：

- 删除程序和静态资源。
- 保留 `<安装目录>\data`。
- 提示用户数据仍位于原安装目录，因此该目录可能不会被完全移除。

勾选时：

- 明确提示将删除账号凭据、数据库、赛季数据、备份和浏览器登录状态。
- 只递归删除经过规范化和边界检查的精确 `<安装目录>\data`。
- 不使用模糊环境变量、通配符或未验证的计算路径扩大删除范围。

卸载程序不得删除旧 AppData 迁移副本。

## 错误处理

- 数据目录不可写：停止启动并提示重新安装或修复目录权限。
- 迁移失败：保留旧数据，不启用半迁移目录，提供可重试入口。
- SQLite 校验失败：视为迁移失败，不自动修改源数据库。
- 目标目录冲突：拒绝覆盖并提示用户处理。
- 应用仍在运行：安装、升级和迁移不得继续。
- 删除失败：卸载程序报告未删除的数据目录，不伪报完全清理。

所有用户可见错误使用中文。日志不得包含凭据、ID、文件内容、真实用户数据或完整隐私路径。

## 安全边界

- 运行时原始上游数据仍按现有产品边界保存，不新增脱敏、遮盖或递归清理。
- 不把 token、cookie、authorization、credential 或浏览器 profile 内容复制到新的 DTO、日志、注册表或安装 payload。
- 发布物、构建资源和提交内容不得包含真实凭据、浏览器 profile、真实数据 dump 或本地 SQLite。
- 安装器只修改确定的安装目录及其 `data` 权限。
- 静态资源与可写业务数据分离。

## 测试与验收

自动化测试覆盖：

- 可执行文件目录到 `data` 的稳定解析。
- 中文、空格和非 C 盘路径。
- `data` 不可写和路径类型错误。
- 旧 AppData 迁移成功、幂等重试、中断恢复、空间不足和目标冲突。
- 账号索引、账号目录及 SQLite 校验失败。
- 新 `data` 存在时不被旧数据覆盖。
- 应用路径调用链不再使用 `app_data_dir` 作为业务根目录。
- NSIS 配置只生成 NSIS，不生成 MSI。
- 安装、升级和卸载脚本的保留与显式删除行为。

Windows 安装验收覆盖：

- 全新安装到默认目录、`Program Files`、非 C 盘及中文路径。
- 普通用户能修改 `data`，不能修改程序文件。
- 登录、同步、切换账号、后台同步、备份和诊断均写入安装目录。
- 全新安装不创建业务 AppData。
- 旧版升级自动迁移且旧目录保持不变。
- 覆盖升级完整保留 `data`。
- 默认卸载保留 `data`。
- 勾选删除后只删除 `data`。
- 静态 assets 在安装版中可正常访问。

最终验证执行项目要求的前后端测试、`git diff --check`、NSIS `tauri build` 和发布敏感信息扫描。验证与测试只使用合成数据，不接触真实凭据或真实用户数据。
