# 对局列表参考式卡片设计

## 目标与范围

仅重构 `apps/owstats-desktop` 的对局列表卡片视觉与数字显示，不改变筛选、列表选择、详情打开、数据查询、赛季状态或评价算法。

卡片参考用户提供的对局列表截图，但颜色、字体、间距、状态表达和表面层级以根目录 `design.md` 为准。保留现有英雄头像、地图预览、比赛结果、比分、地图名、模式名、K/A/D、伤害/治疗/抵挡、项目原有主标签和奖牌。

## 推荐尺寸与密度

宽屏单卡固定为 `152px` 高：

- 顶部地图横幅 `64px`。
- 底部数据区 `88px`。
- 相邻卡片间距 `12px`。
- 数据区水平内边距 `16px`，垂直内边距上限 `12px`；`60px` 英雄头像在 `88px` 数据区内垂直居中，总高不能被内容撑大。
- 英雄头像在宽屏使用 `60px × 60px` 方形展示，不重复显示英雄名称。
- 标签文字 `12px`，核心数字 `18px`，比分 `24px`，地图名 `15px`，模式名 `12px`。

该密度优先服务约占页面 `32%` 的列表栏：保持一屏可见对局数量，同时为长地图名、长模式名、主标签和多枚奖牌保留合理空间。

## 地图横幅结构

横幅使用完整的炭黑底板 `--action-primary`。地图预览不是矩形、普通斜切块或铺满背景后再由结果块遮挡，而是独立的六点裁切图层：

```css
clip-path: polygon(
  26% 0,
  100% 0,
  100% 100%,
  58% 100%,
  55% 82%,
  29% 82%
);
```

轮廓含义：

1. 地图左上从横幅宽度约 `26%` 处开始。
2. 左边缘向右下倾斜，在约 `29% / 82%` 处进入第一层底边。
3. 第一层底边水平延伸到约 `55% / 82%`。
4. 轮廓再斜向下落到约 `58% / 100%`。
5. 右半段地图沿横幅最底边延伸至右侧，形成参考图中的两级底部层次。

不再使用结果块 `::after` 三角伪元素。结果区只是横幅底板左侧未被地图覆盖的区域，避免形成箭头尖或错误的单一梯形轮廓。

地图预览保持固定高度与 `object-fit: cover`，轻度降低饱和度以融入灰绿色界面；不添加品牌色渐变、强高光或厚阴影。地图缺失时继续使用项目现有稳定占位，不显示原始 GUID。

## 横幅信息层级

- 左上/左侧显示中文结果与比分，例如“胜利 3-0”“失败 0-3”“平局 1-1”。
- 结果文字和比分使用白色，结果必须保留中文文本，不能只靠颜色区分。
- 右侧在地图图层上显示“地图名称 · 模式名称”，地图名优先、模式次级。
- 模式使用现有 `modeLabel`，例如“预设快速”“角斗竞技”，不恢复原始协议值。
- 地图名和模式名在空间不足时单行省略，并通过可访问名称或标题保留完整内容。
- 不显示对局时间，不在数据区重复地图名或模式。

## 数据区布局

宽屏数据区为单行四列：

1. `60px` 方形英雄头像。
2. `K/A/D` 与对应值，顺序固定为击杀/助攻/死亡。
3. `伤害/治疗/抵挡` 与三个对应值。
4. `对局表现`、项目现有主标签和奖牌。

建议网格：

```css
grid-template-columns: 60px minmax(0, 0.8fr) minmax(0, 1.4fr) minmax(0, 1fr);
gap: 12px;
```

所有核心数字使用等宽数字。标签与奖牌保持现有数据来源和顺序，不显示列表评分；主标签使用透明底、低对比细描边和深灰文字，奖牌使用同尺寸圆形细描边。允许极弱暖金或砖红描边表达奖牌语义，但普通文字和数值只使用 `design.md` 的黑灰文字层级。

无评价时保留稳定的列高，不显示误导性占位评分；可以为空，不能造成其他列横向跳动。

## 数字格式

`伤害/治疗/抵挡` 共用纯格式化函数：

- 原值 `<= 10,000`：显示 `zh-CN` 整数分组格式，例如 `2,066`、`10,000`。
- 原值 `> 10,000`：先按千位四舍五入，再除以 `10,000`，固定显示一位小数并追加小写 `w`。
- 示例：`10,001 → 1.0w`、`10,499 → 1.0w`、`10,500 → 1.1w`、`21,499 → 2.1w`、`21,500 → 2.2w`。
- 不对 K/A/D、比分或其他页面数值扩大该规则。

格式化逻辑保留在 `src/shared/matchListFormat.ts`，组件只负责组合三个格式化结果，避免把阈值和舍入规则散落在 JSX 或 CSS 中。

## 响应式与可访问性

- 宽屏与当前主工作台维持四列单行布局。
- 当列表卡片可用宽度不足以容纳四列时，数据区改为两行网格；头像与 K/A/D 保持第一视觉组，表现标签独占第二行剩余区域。
- 窄屏不得产生横向滚动，地图名、模式名和表现标签按优先级截断或换行。
- 整张卡仍是单一按钮，保持至少 `44px` 命中范围、现有键盘焦点、选中态和 `aria-current`。
- 地图为装饰图时继续使用装饰语义；地图名称由可见文本提供。
- 状态不能只靠胜负色表达，必须同时显示中文结果。
- 不增加装饰动画；现有悬停和选中反馈保持 `160–220ms`，并遵循 `prefers-reduced-motion`。

## 组件与样式边界

预计只触及以下窄范围：

- `src/features/matches/MatchListCard.tsx`：卡片语义结构与信息顺序。
- `src/shared/matchListFormat.ts`：超过一万的 `w` 格式化规则。
- `src/styles/features/matches.css`：卡片尺寸、六点地图裁切、四列数据区和窄屏回退。
- `src/shared/PerformanceBadgesView.tsx`：仅在现有能力不足时保留列表隐藏评分的开关，不修改标签和奖牌算法。
- 对应脚本测试与视觉 fixture：锁定结构、数字边界、尺寸和响应式契约。

不修改后端 DTO、SQLite、同步逻辑、评价算法、地图/英雄 manifest 或详情页。

## 验证与验收

### 自动化验证

- 为 `formatCompactStat` 增加 `10,000`、`10,001`、`10,499`、`10,500`、`21,499`、`21,500` 边界测试。
- 结构测试确认地图预览使用六点 `clip-path`，且不存在结果块三角伪元素。
- 结构测试确认宽屏总高为 `64px + 88px`、四列顺序正确、不显示时间和评分。
- 保持现有对局列表选择、标签奖牌和详情打开测试通过。
- 执行前端单测、组件测试、TypeScript 检查、Vite 构建和 `git diff --check`。

### 视觉验收

使用匿名 fixture 在 `2540×1344`、`1920×1080`、`1440×900` 检查：

- 单卡高度稳定为 `152px`，卡间距 `12px`，列表密度协调。
- 地图底部明确呈现先抬高、再斜落、最后贴底的两级轮廓。
- 胜负比分、地图模式、三组个人数据和表现标签形成清晰的四级扫描路径。
- 长地图名、长模式名、多奖牌和无评价状态均不溢出、不挤压核心数字。
- 选中、悬停、键盘焦点和窄屏回退不引发布局跳动。
- 所有颜色来自现有语义令牌，与 `design.md` 的灰绿画布、炭黑操作色和低饱和状态描边协调。

### 隐私

验证仅使用匿名 fixture，不读取真实凭据、浏览器 profile、真实用户数据 dump 或原始隐私 ID。

## 2026-07-15 结果区白底状态点补充

- 横幅底层由 `--action-primary` 改为 `--action-on-primary`，地图仍使用既有六点分层裁切；左上角及地图下方未覆盖区域自然露出完整白色色块，不额外叠加矩形或三角形。
- 结果文字和比分统一使用 `20px`、`400` 字重与 `--text-primary`，比分继续启用等宽数字。
- 胜利结果前显示 `--status-success` 小圆点，失败结果前显示 `--status-danger` 小圆点；平局与未知结果不显示状态点。
- 圆点通过装饰性伪元素实现，不进入无障碍树；“胜/负”中文文字继续保留，颜色不是唯一的状态表达方式。

## 2026-07-16 上下表面颜色交换

- 地图横幅底层使用原数据区的浅灰表面 `color-mix(in srgb, var(--surface-secondary) 88%, transparent)`。
- 下方数据区使用白色 `--action-on-primary`。
- 仅交换两个表面颜色；地图裁切、状态点、文字、尺寸、响应式和交互状态均保持不变。

- 宽屏核心数字由 `18px` 调整为 `16px`；辅助标题、表现标签和奖牌文字继续保持 `12px`。
- 宽屏表现徽章间距由 `8px` 收紧为 `4px`，不继续缩小标签或奖牌，以保证四枚奖牌完整显示。
- 1401–1500px 专用紧凑规则、窄屏换行规则、卡片高度、奖牌尺寸和内容完整性保持不变。
