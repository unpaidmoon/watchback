# 战报页高胜率选择榜单设计

## 背景

战报页当前已经按赛季展示个人数据，并在页面下部提供地图分析。新增模块需要回答三个更具体的问题：

- 普通对局中，本人选择后表现最稳定的威能是什么。
- 角斗对局中，本人选择后表现最稳定的异能是什么。
- 角斗对局中，本人选择后表现最稳定的装备是什么。

直接按实际胜率排序会放大小样本偶然性。本设计保留最低样本门槛，并使用 95% Wilson 置信区间下限进行后台排序；界面仍展示易理解的实际胜率。

## 范围

本次新增三个赛季榜单：

1. 普通对局威能前三名。
2. 角斗对局异能前三名。
3. 角斗对局装备前三名。

榜单仅统计当前登录账号本人在战报页当前选中赛季中的选择。模块位于地图分析上方。

本次不新增独立详情页，不提供筛选或排序交互，不统计队友或对手，不新增 SQLite 投影表，也不改写历史对局详情。

## 数据口径

### 统计对象

- 普通对局只处理 `bucket='preset'` 的对局。
- 角斗对局只处理 `bucket='stadium'` 的对局。
- 查询必须显式限定当前选中赛季。
- 只提取当前账号本人对应的最终玩家配置。

### 单场计数

- 普通对局从本人最终 `perks` 中提取威能 GUID。
- 角斗对局从本人最终 `traitGuids` 中提取异能 GUID。
- 角斗对局从本人最终 `modGuids` 中提取装备 GUID。
- 同一 GUID 在同一场对局中最多计数一次。
- 角斗逐回合快照中的重复出现不重复累计。
- 胜局计入选取场次和胜场。
- 负局只计入选取场次。
- 平局计入选取场次，但不计入胜场。

### 样本和排序

- 每项至少在 5 场对局中出现才具备排名资格。
- 对每项按 95% Wilson 置信区间下限计算排序分数。
- 排序优先级依次为：
  1. Wilson 下限降序。
  2. 选取场次降序。
  3. 实际胜率降序。
  4. 稳定键升序。
- 每类最多返回前三名。
- Wilson 下限只参与排序，不在榜单行中展示具体数值。

## 后端设计

### 查询方式

扩展现有 `get_season_analysis` 数据流。后端按赛季连接 `matches` 和 `match_details`，查询时解析 `raw_detail_json`，提取本人最终配置并聚合。

采用查询时解析，而不是新增投影表，原因如下：

- 不需要 SQLite schema 迁移和历史回填。
- 不改变当前导入链路与幂等边界。
- 当前只返回三类各三条聚合结果，需求范围有限。
- 后续如性能测量显示查询成本不可接受，可以在保持 DTO 不变的前提下迁移到投影表。

解析和 Wilson 计算应封装为独立、可测试的后端函数，避免 UI 或命令层复制统计规则。

### DTO

`SeasonAnalysis` 新增 `choiceRankings`：

```text
choiceRankings
  minSample: 5
  confidenceLevel: 0.95
  normalPerks: ChoiceRankingEntry[]
  stadiumTraits: ChoiceRankingEntry[]
  stadiumMods: ChoiceRankingEntry[]
```

每条 `ChoiceRankingEntry` 只返回聚合后的安全字段：

```text
key
matches
wins
winRate
```

名称和图标继续由前端使用正式打包的现有资源映射解析。DTO 不包含原始详情、玩家标识、账号信息、路径或其他 payload。

## 前端设计

### 布局

在地图分析上方增加单一“高胜率选择”主面板：

- 宽屏使用三栏并列。
- 三栏依次为“普通对局 · 威能”“角斗 · 异能”“角斗 · 装备”。
- 栏间使用细分隔线，不创建三张嵌套卡片。
- 窄屏改为纵向排列。
- 页面继续只保留一个主滚动容器。

面板辅助说明为：

```text
至少选取 5 场 · 按 95% 置信统计排序
```

不展示每条记录的置信下限数值。

### 榜单行

每行展示：

- 排名序号。
- 正式资源图标。
- 名称。
- 实际胜率。
- 选取场次。

数字使用等宽数字样式。图标缺失时保留固定尺寸占位，避免布局跳动。

资源映射规则：

- 普通威能复用现有威能运行时配置和图标资源。
- 威能映射失败时显示中文稳定兜底，不暴露原始 GUID。
- 角斗异能和装备复用现有角斗 manifest 与图标资源。
- 角斗异能或装备映射失败时，按现有产品例外规则显示原始 GUID。

### 空状态

- 某一类别没有达到 5 场门槛的候选项时，该栏显示“样本不足，至少需要 5 场选取记录”。
- 其他类别不受影响，仍正常展示。
- 整个赛季没有可统计详情时，面板保持原位并显示暂无可统计数据。
- 加载和错误状态沿用战报页现有分析请求边界，避免页面布局跳动。

## 容错与隐私边界

- 缺少详情、本人行或最终配置的单场对局不参与对应类别统计。
- 单场字段缺失或格式异常时，跳过该场相关选择，不影响其他对局。
- 数据库查询失败时沿用现有分析错误面，不返回伪造的空榜单。
- 不新增运行时递归脱敏、遮盖、清理或历史迁移。
- 不记录原始详情、玩家 ID、文件路径、JSON 行或 payload。
- 诊断只允许输出阶段、匿名计数、耗时和文件大小。
- 测试数据全部使用合成值，不接触真实凭据或真实用户数据。

## 测试设计

### 后端

按 TDD 增加合成详情测试，覆盖：

1. 只统计指定赛季。
2. 普通和角斗模式严格分离。
3. 只统计本人，不混入队友或对手。
4. 使用最终配置，不累计角斗逐回合快照。
5. 同场相同 GUID 去重。
6. 胜、负、平局的计数语义。
7. 少于 5 场不参与排名。
8. Wilson 下限优先于表面胜率。
9. 选取场次、实际胜率和稳定键的并列规则。
10. 每类最多三条。
11. 缺失或畸形的单场字段不会破坏其他统计。

### 前端

覆盖：

1. 三栏名称和顺序。
2. 模块位于地图分析上方。
3. 榜单行展示图标、名称、实际胜率和选取场次。
4. 不展示具体 Wilson 下限。
5. 单栏样本不足状态。
6. 整体无可统计数据状态。
7. 威能与角斗资源映射 fallback。

### 视觉验收

使用合成 fixture 检查：

- 宽屏三栏布局和细分隔线。
- `1440×900` 下的紧凑或纵向布局。
- 图标缺失、名称较长和空状态下不发生明显跳动或溢出。
