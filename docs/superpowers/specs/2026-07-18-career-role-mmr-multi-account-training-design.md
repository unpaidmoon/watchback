# 生涯三职责 MMR：多账号全赛季训练设计

日期：2026-07-18

## 1. 文档定位

本文重新定义 OWStatsLocal 生涯 MMR 的训练、验证和模型晋级流程。它是
`2026-07-13-career-role-mmr-design.md` 的训练专项补充；两者冲突时，训练数据范围、
模式划分、多账号联合训练、角斗统计口径和个人表现模型验收以本文为准。既有的三职责
独立评级、0–5000 展示标尺、胜负主干、置信度、历史重放和隐私边界继续有效。

本模型是 OWStatsLocal 的本地推算，不是暴雪官方隐藏分。

## 2. 已确认的产品决定

- 动态发现本地存在的任意赛季，不设置赛季白名单。
- 重装、输出、支援分别维护 MMR，不生成会反向影响三职责的综合评级。
- 多个本地账号共享一套训练权重，但各账号的 MMR 状态、历史轨迹和数据库完全独立。
- 正式训练标签只来自账号本人；队友和对手只用于对局强度、团队环境和统计基线。
- `LeisurePreset` 与职责竞技进入同一职责队列训练组；`Leisure6v6` 与开放竞技进入同一
  开放队列训练组。共享的是模型参数，不合并各模式的统计基线、验证结果或启用状态。
- 职责竞技、开放竞技、`LeisurePreset`、`Leisure6v6` 和角斗竞技参与个人表现候选训练。
- 角斗快速参与胜负主干，但不参与个人表现训练，`performanceAdjustment` 固定为 0。
- 角斗只读取最后一个有效回合。该回合玩家行是整场最终累计数据，按整场总时长换算每
  10 分钟；不得累加或平均前面回合。
- 每个“职责 × 模式”独立验收。未通过的组合自动降级，不阻塞其他组合启用。
- 最终训练报告必须完整呈现每个组合的样本、指标、权重、状态和失败原因。

## 4. 总体训练架构

采用“职责核心 + 训练组偏移”的分层收缩模型：

```text
职责核心表现
+ 职责 × 训练组偏移
+ 英雄、模式、赛季稳健归一化
= 该职责在该模式的个人表现分
```

三个职责分别训练核心模型；职责队列、开放队列和角斗竞技三个训练组分别训练偏移。
`LeisurePreset` 与职责竞技共享职责队列参数，`Leisure6v6` 与开放竞技共享开放队列参数。
训练组数据不足时偏移向 0 收缩。收缩和共享训练都不能代替验收：五种实际表现模式仍须
分别验证，只有“职责 × 实际模式”在自己的验证样本上通过门槛后，才可进入正式 MMR。

不采用 15 套完全独立模型，因为开放竞技和部分职责组合样本不足；也不采用每个职责一套
完全共享权重，因为职责队列、开放队列和角斗的统计结构不可直接等同。

## 5. 多账号训练边界

联合训练协调器只读打开账号目录中 schema 兼容的 SQLite，不合并或复制原始数据库。
每个数据库生成非敏感、可重建的训练投影。训练运行期使用账号序号和稳定比赛分组键；
任何持久化报告均移除这些键。

正式样本单位为：

```text
一个账号 × 一场比赛 × 一个有效职责片段
```

规则如下：

- 同一账号重复同步的同一比赛只保留一份。
- 备份数据库不能作为新增账号数据重复训练。
- 两个账号若出现在同一真实比赛中，可以保留两个当前玩家样本，但必须共享比赛分组键，
  并进入同一训练折或同一 bootstrap 簇。
- 账号本人是正式标签；同场其他玩家只生成临时对局强度、团队环境和群体基线，不建立其
  生涯评级或跨场身份档案。
- 一个账号库失败不能被静默忽略。报告必须说明实际纳入账号数，未完整读取全部目标账号
  时不得宣称“全量训练成功”。

## 6. 动态赛季与时间规则

- 从纳入训练的 SQLite 动态读取全部有效赛季。
- 不固定最小、最大或当前赛季编号；新增赛季不要求改算法代码。
- 生涯 MMR 按真实比赛时间重放，旧赛季不会被硬删除或手工降权。
- 全局权重训练按赛季平衡采样，避免比赛量最大的赛季支配系数。
- 所有验证优先保持时间方向，只允许用过去训练、随后时间验证。
- 英雄基线、缺失值处理、标准化参数和超参数必须在每个训练折内重新拟合，不得引用未来
  或被留出的赛季。

## 7. 模式映射与胜负主干

实际模式族固定为：

```text
role_competitive
role_quick
open_competitive
open_quick
stadium_competitive
stadium_quick
```

训练组映射固定为：

```text
role_competitive + role_quick     → role_queue
open_competitive + open_quick     → open_queue
stadium_competitive               → stadium_competitive
stadium_quick                     → outcome_only
```

共享训练参数不表示模式等价。归一化基线、胜负权重、单场上限、验证指标、状态和最终报告
始终按实际模式分别计算。

共同胜负更新：

```text
baseDelta =
  uncertaintyStep
  × modeWeight
  × roleShare
  × dataQuality
  × (actualResult - expectedWinRate)
```

| 模式 | `modeWeight` | 单场每职责上限 |
|---|---:|---:|
| 职责竞技 | 1.0 | ±30 |
| 开放竞技 | 1.0 | ±30 |
| 角斗竞技 | 0.5 | ±30 |
| 职责式快速（`LeisurePreset`） | 0.3 | ±10 |
| 开放式快速（`Leisure6v6`） | 0.3 | ±10 |
| 角斗快速 | 0.1 | ±10 |

`expectedWinRate` 优先使用双方 `rankScore`，其次使用段位等级、同场段位中位数，覆盖不足
时向 50% 收缩并降低 `dataQuality`。能够确认胜负和职责但缺少个人统计的比赛仍进入胜负
主干。

## 8. 职责与英雄片段

普通模式职责归属顺序：

```text
精确英雄实际时长
→ 可推导的多英雄时长
→ 比赛摘要 roleType
→ 主玩英雄
→ 最终英雄
→ 无法识别则跳过
```

有精确英雄时长时按职责占比拆分。只有最终英雄时允许低质量胜负更新，但不启用英雄专属
表现特征。不得用面板数值反推英雄使用时长。

角斗规则：

1. 过滤缺少有效玩家列表或当前玩家英雄的异常回合。
2. 按回合序号、`startTime`、原数组顺序稳定排序。
3. 只取最后一个有效回合的最终玩家行。
4. 职责取该行英雄职责，`roleShare = 1.0`。
5. 个人统计视为整场最终累计值，按整场总时长换算。
6. 不读取前面回合统计，不累加，不平均，不用前一回合作缺失替代。

## 9. 样本质量

| 等级 | 条件 | 用途 |
|---|---|---|
| A | 精确英雄时长、英雄统计和整场统计完整 | 全部候选特征与胜负主干 |
| B | 职责、胜负可靠，部分表现字段缺失 | 可用特征与胜负主干 |
| C | 只有最终英雄或职责摘要 | 低质量胜负主干 |
| 排除 | 无法确认职责或胜负 | 不更新该职责 MMR |

异常、负数、非有限值、明显不可能的统计关闭对应表现特征；缺少比赛时长时不计算每 10
分钟指标。降级不得阻断可靠的胜负更新。

## 10. 英雄、模式与赛季归一化

所有计数和面板统计先换算为每 10 分钟，再使用中位数和 MAD 建立稳健基线：

```text
英雄 + 模式 + 赛季
→ 英雄 + 模式
→ 英雄 + 训练组
→ 职责 + 模式
→ 职责 + 训练组
```

- 少于 30 条不建立细分基线。
- 至少 100 条才标记为高置信英雄基线。
- 稳健 Z 值截断在 `[-3, 3]`。
- 共享训练组的竞技和快速模式也优先维护各自基线；只有实际模式样本不足时才逐级回退到
  训练组基线。
- 普通与角斗不得直接共享原始统计基线。
- 每个验证折只能使用该折训练窗口建立基线。

## 11. 两层训练目标

第一层是上一节定义的胜负主干。第二层不直接拟合原始胜负，而把赛前预期胜率作为固定
基线：

```text
logit(P(actualResult)) =
  logit(expectedWinRate)
  + roleCorePerformance
  + roleTrainingCohortOffset
```

平局按 0.5 处理。实现采用带正则化、方向约束和训练组偏移收缩的可解释逻辑模型。目标是
解释超出赛前预期的结果，而不是把强队环境或高胜率账号误认为个人表现。

候选训练顺序：

1. 最后一击、非最后一击、死亡；
2. 加入助攻；
3. 加入职责核心产出；
4. 加入目标贡献；
5. 加入训练组偏移；
6. 分别比较五种 `healingTaken` 方案；
7. 加入少量有业务定义的转化交互项。

最终采用满足所有门槛的最简单模型。复杂候选必须在独立验证中稳定优于简单候选，不能仅
凭训练集指标晋级。

## 12. 共同核心特征

```text
finalBlows = final_hit
nonFinalEliminations = max(kill - final_hit, 0)
```

三个职责共同使用最后一击、非最后一击、助攻、死亡、职责时长和数据完整度。

方向约束：

- 最后一击系数大于 0；
- 非最后一击系数大于 0；
- 单次最后一击价值大于单次非最后一击参与；
- 死亡系数小于 0。

最后一击相对倍率在 `1.00、1.25、1.50、1.75、2.00` 中比较；倍率为 1.00 只作为
对照，不能成为正式结果。

## 13. 三职责候选特征

### 13.1 重装

- 最后一击、非最后一击、助攻；
- 英雄内归一化伤害和减伤；
- 承伤、生存、目标贡献；
- 前线转化；
- 资源转化债务。

减伤只能在英雄内部或稳健回退基线中比较，不能因末日铁拳、路霸等英雄机制系统性扣分。

### 13.2 输出

- 最后一击、非最后一击、助攻；
- 英雄内归一化伤害；
- 击杀/伤害转化；
- 死亡、目标贡献；
- 资源转化债务。

高伤害但最后一击和击杀转化不足时，不继续按伤害量线性奖励。

### 13.3 支援

- 助攻、最后一击、非最后一击；
- 英雄内归一化治疗和伤害；
- 生存、死亡和目标贡献；
- 异常承伤；
- 资源转化债务。

支援采用最保守的修正幅度。净化、复活、加速、睡眠、禁疗、免死等未完整记录的能力不
能被当作负分；治疗和伤害只能在英雄内部比较。

## 14. `healingTaken` 与资源转化

`healingTaken` 的业务语义是受到队友治疗，但不能未经验证直接按原始数值扣分。每个职责
依次比较五个互斥方案：

1. 不使用；
2. 直接负向；
3. 英雄内归一化负向；
4. 超额受到治疗；
5. 资源转化债务。

推荐候选定义：

```text
expectedHealingTaken = f(
  hero,
  role,
  mode,
  duration,
  damageTaken,
  deaths,
  availableTeamHealing
)

excessHealing = actualHealingTaken - expectedHealingTaken

resourceDebt =
  max(0, excessHealingZ)
  × max(0, 1 - normalizedRoleConversion)
```

只有明显获得超额治疗且没有转化为职责产出时才产生负向候选。多英雄普通比赛的
`healingTaken` 不得复制给每个英雄片段，也不得按时长线性分摊；第一轮只在单英雄或能
证明归属的样本中研究。资源债务的方向稳定性或区间未通过时，权重必须归零。

## 15. 表现修正与单场限幅

```text
performanceAdjustment = clamp(
  calibratedPerformanceScore,
  -0.10 × abs(baseDelta),
  +0.10 × abs(baseDelta)
)

finalDelta = baseDelta + performanceAdjustment
```

额外上限：

- 竞技类不超过 ±3 MMR；
- 支援竞技不超过 ±2 MMR；
- 普通快速不超过 ±1 MMR；
- 角斗快速固定为 0；
- 单项特征贡献 P95 不超过表现修正总量的 35%；
- 表现不能让胜局最终扣分，也不能让败局最终加分；
- 数据不足、组合未通过或模型不可用时修正为 0。

表现分在每个职责和模式内中心化，避免模型长期无条件制造总加分或总扣分。

## 16. 防泄漏验证

所有候选依次执行：

1. 五折严格向前时间验证；
2. 逐赛季留一验证；
3. 逐英雄留一验证；
4. 逐账号留一验证；
5. 按真实比赛分组的聚类 bootstrap。

同一真实比赛的所有账号样本、职责片段和英雄片段只能位于同一折。训练折的任何基线、
缺失值、正则化强度和超参数不得读取验证折。

当前只有两个账号。逐账号留一若因一个账号某职责样本极少而无法判断，标记“账号覆盖
不足”并保持影子状态，不能把不可评估误报为通过或失败。

## 17. Bootstrap 阶段

- 100 次：开发期快速筛选，只淘汰明显失败方案。
- 1,000 次：候选比较和参数收敛检查。
- 10,000 次：仅对最终入围候选执行，生成正式启用结论。

bootstrap 以真实比赛为簇。训练程序必须持续输出阶段、完成次数、预计剩余时间和聚合
失败原因，不能长时间只显示“运行中”。固定随机种子和模型版本后结果必须可复现。

## 18. 职责 × 实际模式独立验收

个人表现验收矩阵共 15 格：

```text
tank / damage / support
×
role_competitive / role_quick / open_competitive / open_quick / stadium_competitive
```

角斗快速另列为“仅胜负主干”，不属于 15 格表现训练矩阵。职责竞技与职责式快速共享
`role_queue` 参数，开放竞技与开放式快速共享 `open_queue` 参数，但配对模式不得合并验证
指标或状态。共享模型可以在一个实际模式通过、另一个实际模式保持影子运行。

样本与收缩条件：

- 职责核心模型至少 500 条有效表现样本。
- 单独训练组偏移至少 150 条，否则该偏移收缩为 0。
- 样本不足的实际模式可以使用已经验证的职责核心和训练组权重，但仍须在该实际模式的
  验证样本上独立通过。
- 核心权重、训练组权重或实际模式验证不通过时，该格 `performanceAdjustment = 0`。

每格启用门槛：

1. 相对使用同一 `expectedWinRate` 的无表现修正基线，五个时间窗口至少四个 Brier Score
   更低；
2. 10,000 次比赛聚类 bootstrap 的 `Brier(candidate) - Brier(baseline)` 95% 区间上界
   小于 0；
3. 候选的校准误差 ECE 不得比基线高 0.005 以上；
4. 关键系数方向稳定率至少 90%，其 95% 区间不得跨 0；
5. 最后一击、非最后一击稳定为正，死亡稳定为负；
6. 若启用资源债务，其 95% 区间必须完全小于 0；
7. 单项贡献 P95 不超过 35%；
8. 逐英雄和逐赛季无系统性涨分或掉分群体；
9. 每格验证集平均表现修正绝对值不超过 0.10 MMR；
10. 每格触及表现修正上下限的比赛比例分别不超过 5%；
11. 反事实测试中，单独增加伤害或治疗而不改善击杀、助攻、生存或目标转化，不能持续提高
    表现修正；
12. 不形成刷伤害、刷治疗、消极保命等明显可利用策略。

每格只有三种状态：

| 状态 | 正式行为 |
|---|---|
| 已启用 | 表现修正进入正式 MMR |
| 影子运行 | 计算和报告，但不改变正式 MMR |
| 胜负主干 | 表现修正为 0 |

## 19. 训练流水线

```text
发现全部账号数据库
→ 只读生成当前玩家训练投影
→ 动态发现全部赛季
→ 映射模式并建立跨账号比赛分组
→ 数据质量分级
→ 在每个训练折建立英雄基线
→ 训练三职责核心模型
```

长任务按只读审计、100 次筛选、1,000 次候选、10,000 次正式验证、影子重放分阶段执行。
前一阶段失败时停止后续高成本阶段，并保留聚合失败报告。

## 20. 模型版本与回滚

每次训练生成不可变模型版本，至少记录：

- 训练投影和特征 schema 版本；
- 实际纳入账号数、动态赛季、模式和职责样本量；
- 三职责核心权重和训练组偏移；
- 英雄基线回退规则；
- 标准化、缺失值和数据质量配置；
- 15 格实际模式启用状态；
- 单场限幅配置；
- 验证指标、配置摘要哈希和生成时间。

新模型先作为非激活影子版本，分别对每个账号完整重放。切换激活版本必须使用事务；任何
失败都保留上一套完整正式结果，不向前端暴露半套轨迹。旧模型保留用于解释和回滚。

## 21. 最终训练报告

正式报告必须包含：

1. 实际纳入账号数、全部赛季和各模式场次；
2. 职责映射、英雄时长和各统计字段覆盖率；
3. 三职责特征权重、方向稳定率和 95% 区间；
4. 五种 `healingTaken` 方案的结果及采用或拒绝理由；
5. 前向、逐赛季、逐英雄、逐账号和 bootstrap 指标；
6. 15 格职责 × 实际模式验收矩阵，并分别展示共享训练参数的配对模式；
7. 角斗快速“仅胜负主干、未参与表现训练”的明确说明；
8. 每格“已启用、影子运行、胜负主干”的最终状态；
9. 单场修正分布、单项贡献 P95 和上限命中率；
10. 每个未通过组合的原因和需要补充的有效样本；
11. 新旧模型对各账号三职责当前 MMR、峰值和历史曲线的聚合影响；
12. 哪些组合可以上线、哪些组合继续观察的明确结论。

报告只包含聚合指标，不输出账号、玩家、比赛标识、凭据或原始 JSON。

## 22. 自动测试矩阵

至少覆盖：

- 动态赛季发现，不存在固定赛季数组；
- 多账号联合训练、单账号独立 MMR；
- 同场跨账号样本进入同一验证折；
- 重复同步和备份数据库不重复训练；
- 六种实际模式及三个训练组映射正确；
- `LeisurePreset` 与职责竞技共享模型参数，但分别建立基线和验证；
- `Leisure6v6` 与开放竞技共享模型参数，但分别建立基线和验证；
- 角斗快速只进入胜负主干；
- 角斗竞技只读取最后有效回合；
- 角斗最终统计按整场时长换算；
- 普通模式按英雄实际时长拆分职责；
- 最后一击不与普通击杀重复计分；
- 三职责使用不同特征集合；
- `healingTaken` 五种候选和资源债务方向约束；
- 英雄基线只读取训练窗口；
- 前向、留一赛季、留一英雄和留一账号无泄漏；
- 单项贡献 P95 门槛；
- 职责/开放竞技权重 1.0、角斗竞技 0.5、两种普通快速 0.3、角斗快速 0.1；
- 竞技类 ±30、快速类 ±10；
- 个人表现不反转胜负方向；
- 相同权重、输入和种子重放结果一致；
- 模型切换失败回滚；
- DTO、日志和报告不主动扩散凭据或玩家私密标识。

## 23. 执行阶段

1. 全量只读审计两个账号、全部赛季和模式。
2. 修正训练投影：多账号、六种实际模式、三个训练组和角斗最终回合。
3. 执行 100 次快速候选筛选。
4. 执行 1,000 次候选验证。
5. 对最终入围候选执行 10,000 次正式验证。
6. 分别对两个账号执行影子历史重放。
7. 生成最终报告，由用户确认是否激活通过组合。

当前数据预期：职责队列训练组约 2,805 场，开放队列训练组约 293 场，角斗竞技训练组
1,084 场；共享训练将提高职责竞技和开放竞技参数的稳定性，但五种实际表现模式仍须按
职责分别判断。角斗快速仅 39 场，不进入表现训练。以上只是训练前判断，不能代替最终
矩阵结果。

## 24. 完成定义

训练程序成功退出不等于完成。只有以下条件全部满足，才可交付本轮训练：

- 两个目标账号和所有动态赛季已按设计纳入或明确报告失败；
- 普通与角斗输入口径、跨账号分组和防泄漏测试通过；
- 100、1,000、10,000 次阶段按候选晋级规则完成；
- 最终报告给出每个职责和模式的可复核结果；
- 角斗快速保持仅胜负主干；
- 只有通过门槛的组合获得启用资格；
- 影子重放未修改正式模型，激活仍等待用户确认；
- 全程未主动扩散凭据、玩家私密标识或原始训练数据。
