# 生涯三职责 MMR 设计

日期：2026-07-13

## 1. 目标

OWStatsLocal 基于当前账号已经同步到本地 SQLite 的全部历史赛季数据，推算重装、输出、支援三个职责的生涯 MMR。该 MMR 是本地分析模型，不是暴雪服务器内部隐藏分。

产品同时提供：

- 三职责当前 MMR；
- 生涯峰值；
- 历史曲线；
- 模型置信度；
- 模式贡献和赛季变化；
- 可选的次要综合 MMR 摘要。

赛季集合从本地数据动态发现，不固定为 S21/S22/S23。新增或补同步任意赛季后，模型按真实比赛时间重新生成受影响的后续轨迹。

## 2. 产品边界

参与计算的模式包括：

- 职责竞技；
- 开放竞技；
- 角斗竞技；
- 快速比赛。

三个职责分别维护能力均值和不确定性。任何综合分都不得反向影响三职责状态。

页面和接口必须使用“OWStatsLocal 推算 MMR”“本地模型推算，并非暴雪官方隐藏分”等明确文本，不能暗示已经还原暴雪算法。

以下内容不在第一版正式能力内：

- 用表现分直接替代胜负；
- 持久化其他玩家的长期 MMR 档案；
- 固定赛季白名单；
- 全局赛季状态；
- 一键同步全部赛季；
- 未经回测启用学习权重；
- 将角斗所有回合累计或平均后用于个人表现。

## 3. 外部系统调研结论

公开资料只支持借鉴设计原则，不能据此声称复刻其他游戏的专有公式。

### 3.1 英雄联盟

英雄联盟将隐藏 MMR 与可见段位分离，匹配关注双方平均 MMR 和预期胜率。对本项目的启示是：胜负和对局强度必须是主信号，推算 MMR 与可见段位必须分开。

参考：<https://support-leagueoflegends.com/hc/ro/articles/201752954-Alc%C4%83tuirea-echipei-%C8%99i-auto-distribuirea>

### 3.2 无畏契约

无畏契约将隐藏 MMR 与 RR 分离，胜负是主要变化来源，个人表现只用于有限校准。对本项目的启示是：个人表现不能让败局变成加分，也不能鼓励刷面板数据。

参考：

- <https://playvalorant.com/en-gb/news/dev/ask-valorant-rank-rating-edition/>
- <https://playvalorant.com/en-us/news/dev/valorant-ranks-and-competitive-matchmaking/>

### 3.3 Dota 2

Dota 2 采用带 Rank Confidence 的 Glicko 方向。对本项目的启示是：评级必须同时保存能力估计和不确定性；新玩家、久未游玩和跨版本状态需要不同更新步长。

参考：<https://www.dota2.com/newfrontiers>

### 3.4 CS2

CS2 提供直观可见的 CS Rating，但未公开完整更新公式。对本项目的启示是：0–5000 标尺有较强可读性，但 OWStatsLocal 必须明确标注其独立模型身份。

参考：<https://www.counter-strike.net/cs2/features?l=english>

### 3.5 TrueSkill 系

TrueSkill 使用能力均值和不确定性表示玩家水平，适合团队、多玩家和平局。TrueSkill 2 进一步讨论击杀、组队、退出和跨模式信息。对本项目的启示是：以团队结果为主干，并将职责表现限制为小幅、可验证的修正。

参考：

- <https://www.microsoft.com/en-us/research/?p=154591>
- <https://www.microsoft.com/en-us/research/wp-content/uploads/2008/01/NIPS2007_0931.pdf>

### 3.6 守望先锋官方说明

暴雪公开说明 OW2 官方 MMR 的单场变化不使用击杀、伤害、治疗等面板统计，而主要根据胜负、对手强度和近期活跃情况调整。暴雪同时指出，面板统计不能完整代表目标贡献，支援英雄尤为明显。

因此本设计采用：

```text
胜负与对局强度主干 + 极小且经过回测的职责专属表现修正
```

参考：

- <https://overwatch.blizzard.com/en-us/news/23910161/>
- <https://overwatch.blizzard.com/en-us/news/23896785/>
- <https://overwatch.blizzard.com/en-us/news/23801625/>
- <https://overwatch.blizzard.com/en-us/heroes/>

## 5. 评级状态与展示标尺

每个职责维护：

```text
RoleRating {
  role: tank | damage | support
  mu
  sigma
  effectiveMatches
  effectiveHours
  lastPlayedAt
}
```

对外将 `mu` 映射到 0–5000：

```text
MMR = clamp(round(displayScale(mu)), 0, 5000)
```

初始化顺序：

1. 可靠 `rankInfo.rankScore`；
2. `rankName + rankSubTier` 的段位锚点；
3. 2500 中位先验和较大的 `sigma`。

快速比赛可以推动初始估计，但权重和单场变化上限低于竞技模式。

## 6. 共同更新主干

所有职责共享胜负与对局强度主干：

```text
baseDelta =
  uncertaintyStep
  × modeWeight
  × roleShare
  × dataQuality
  × (actualResult - expectedWinRate)
```

```text
actualResult = 胜 1.0 / 平 0.5 / 负 0.0
```

对局预期胜率优先根据双方临时能力估计计算：

1. `rankScore`；
2. `rankName + rankSubTier`；
3. 同场段位中位数；
4. 当前模式宽先验。

双方有效段位覆盖不足时，预期胜率向 50% 回退并降低 `dataQuality`。其他玩家只作为本场临时输入，不持久化长期评级或额外隐私档案。

单场硬限制：

- 职责竞技、开放竞技、角斗竞技：单场每个参与职责的变化不超过 `±30`；
- 快速比赛：单场每个参与职责的变化不超过 `±10`；
- 多职责比赛仍乘以各职责 `roleShare`，不能让每个职责无视时长占比直接吃满上限；
- 表现再好也不能让败局变成加分；
- 表现再差也不能让胜局变成扣分。

## 7. 普通模式职责拆分

职责归属顺序：

```text
英雄实际时长
→ 可推导的多英雄时长
→ 比赛摘要 roleType
→ 主玩英雄
→ 最终英雄
→ 无法识别则跳过
```

有英雄时长时按占比拆分。低于全场 10% 或 60 秒的职责片段并入主职责，避免极短切换制造噪声。

只有最终英雄时：

- 整局归给最终英雄职责；
- `role_source=final_hero`；
- 数据质量建议为 0.55；
- 不启用英雄专属表现修正；
- 仍可执行低质量胜负更新。

## 8. 角斗竞技规则

角斗个人数据只看最后一个有效回合：

```text
全场胜负：比赛最终结果
对局强度：全场或入口级 rankInfo
职责归属：最后有效回合当前玩家英雄
个人表现：最后有效回合玩家数据
roleShare：1.0
```

禁止累加、平均或按全部回合拆分职责。

最后有效回合选择顺序：

1. 过滤缺少玩家列表或有效英雄的异常回合；
2. 按明确回合序号；
3. 无回合序号时按 `startTime`；
4. 再退回原始数组顺序；
5. 取排序后的最后一个有效回合。

最后回合缺失时：

- 可确定胜负和职责：只执行胜负更新；
- 只能确定胜负，不能确定职责：整场不更新职责 MMR；
- 不得使用前一回合作为替代。

实现前必须只读审计最后回合统计是回合局部值还是截至最后回合的累计值：

- 局部值按最后回合时长换算每 10 分钟；
- 累计值按全场总时长换算每 10 分钟；
- 无论口径如何，个人统计来源仍只取最后回合。

## 9. 英雄归一化

原始面板值不能跨英雄直接比较。所有候选指标先换算为每 10 分钟，再按以下层级建立稳健基线：

```text
英雄 + 模式 + 赛季
→ 英雄 + 模式
→ 英雄
→ 职责 + 模式
```

- 30 行以下不建立英雄赛季基线；
- 100 行以上才视为高置信英雄基线；
- 使用中位数和 MAD；
- 标准化值截断在 `[-3, 3]`；
- 角斗只使用同英雄、角斗竞技、相近赛季基线；
- 角斗与普通模式不得共享表现基线。

```text
robustZ = clamp(0.6745 × (value - median) / MAD, -3, 3)
```

## 10. 最后一击与击杀参与

为避免重复计分，将击杀拆为：

```text
finalBlows = final_hit
nonFinalEliminations = max(kill - final_hit, 0)
```

业务约束是单次最后一击价值高于单次非最后一击参与，但具体倍率由回测决定。候选倍率：

```text
1.00、1.25、1.50、1.75、2.00
```

2026-07-13 的初步时间切分测试中，最后一击在三个职责上均为稳定正向信号。该结果只证明字段值得进入候选模型，不构成最终权重。

## 11. 受到治疗与资源转化债务

`healingTaken` 不直接固定扣分。初步测试中原始 `healingTaken` 与胜利存在轻微正相关，可能来自胜方存活更久、团战更完整或字段包含自疗等混杂因素。

实现前必须审计 `healingTaken` 是否包含自我治疗。若包含，需要扣除或按英雄单独建模自疗。

先估算合理资源需求：

```text
expectedHealingTaken = f(
  hero,
  role,
  mode,
  duration,
  damageTaken,
  deaths,
  teamHealing
)
```

```text
excessHealing = max(0, actualHealingTaken - expectedHealingTaken)
```

再根据职责有效产出计算资源转化：

```text
resourceDebt = excessHealingZ × max(0, 1 - normalizedConversion)
```

- 得到大量治疗并转化为击杀、助攻、目标贡献或职责有效产出：不扣或少扣；
- 得到大量治疗但死亡高且有效产出低：负向；
- 受到治疗少不能因分母过小获得异常效率奖励。

## 12. 三职责独立候选模型

以下是待拟合特征集合，不是最终权重。

### 12.1 重装

正向候选：

- 最后一击；
- 非最后一击参与；
- 助攻；
- 英雄归一化伤害；
- 英雄归一化减伤；
- 前线转化；
- 目标时间。

负向候选：

- 死亡；
- 无效承伤；
- 资源转化债务。

```text
frontlineConversion =
  承伤较高
  × 生存正常
  × 击杀/助攻/目标贡献较高
```

减伤只在英雄内部比较。末日铁拳、路霸等低减伤重装不能因为英雄机制被系统性判低。

### 12.2 输出

正向候选：

- 最后一击；
- 非最后一击参与；
- 助攻；
- 英雄归一化伤害；
- 伤害转化；
- 目标时间。

负向候选：

- 死亡；
- 无效伤害；
- 资源转化债务。

```text
damageConversion =
  (最后一击价值 + 非最后一击参与价值)
  / 英雄归一化伤害
```

高伤害但击杀转化低时，不继续奖励伤害。

### 12.3 支援

正向候选：

- 助攻；
- 最后一击；
- 非最后一击参与；
- 英雄归一化治疗；
- 英雄归一化伤害；
- 生存；
- 目标时间。

负向候选：

- 死亡；
- 异常承伤；
- 资源转化债务。

支援模型不能假设治疗量等于全部价值。现有数据没有完整记录增伤、净化、复活、加速、睡眠、禁疗、免死和关键终极技能，因此支援表现修正最保守。

## 13. 表现修正上限

只有离线回测和影子计算通过验收后，表现修正才能进入正式 MMR：

- 竞技类：最多为基础变化的 `±10%`，且不超过 `±3 MMR`；
- 快速比赛：最多为基础变化的 `±10%`，且不超过 `±1 MMR`；
- 支援竞技建议进一步限制为 `±2 MMR`；
- 数据不完整时表现修正为 0。

## 14. 初步统计实验

2026-07-13 使用当前主库进行第一轮只读实验：

- 每项统计换算为每 10 分钟；
- 按英雄和模式进行中位数/MAD归一化；
- 同一场比赛不会同时进入训练集和验证集；
- 前 70% 时间训练，后 30% 时间验证；
- 三职责独立拟合。

结果：

| 职责 | 玩家行 | 验证 AUC | Brier Score |
|---|---:|---:|---:|
| 重装 | 4,035 | 0.901 | 0.136 |
| 输出 | 7,190 | 0.878 | 0.148 |
| 支援 | 7,293 | 0.885 | 0.145 |

固定 50% 预测的 Brier Score 约为 0.250。这些结果说明赛后数据与胜负存在明显关系，但不能证明因果，也不能直接作为正式权重。

稳定初步观察：

- 死亡在三个职责中均为强负向；
- 最后一击在三个职责中均为强正向；
- 英雄归一化后，原始伤害和减伤的独立作用很小；
- 支援助攻比原始治疗量稳定；
- 原始受到治疗不能直接解释为资源浪费。

## 15. 正式权重实验

### 15.1 训练目标

表现模型不能只拟合胜负。先根据双方强度估算赛前胜率，再拟合：

```text
resultResidual = actualResult - expectedWinRate
```

目标是解释超出赛前预期的结果，降低强队和弱队环境造成的混杂。

### 15.2 候选模型

每个职责至少比较：

1. 仅胜负；
2. 胜负 + 对局强度；
3. 加入死亡；
4. 加入最后一击；
5. 加入非最后一击参与；
6. 加入英雄归一化伤害、治疗和减伤；
7. 加入资源转化债务；
8. 完整交互模型。

受到治疗实验比较：

1. 不使用；
2. 直接负权重；
3. 英雄归一化负权重；
4. 超额受到治疗；
5. 资源转化债务。

角斗比较：

1. 只按胜负；
2. 胜负 + 最后回合表现；
3. 全部回合累计，仅作错误对照；
4. 全部回合平均，仅作错误对照。

正式候选只允许前两项。

### 15.3 回测方法

- 5 组滚动时间窗口；
- 按 `match_id` 分组；
- 按赛季留一验证；
- 按英雄留一验证；
- 普通模式与角斗分别验证；
- 1,000 次按比赛聚类的 bootstrap；
- 至少 30 组候选权重；
- 比较无表现修正、固定权重和学习权重。

约束：

- 最后一击系数大于 0；
- 非最后一击参与系数大于 0；
- 死亡系数小于 0；
- 资源转化债务系数小于 0；
- 单项指标不超过表现修正总量的 35%。

### 15.4 启用门槛

- 比仅胜负模型的验证指标稳定改善；
- 5 个时间窗口至少 4 个改善；
- 1,000 次 bootstrap 中方向稳定率至少 90%；
- 不造成特定英雄系统性涨分；
- 不造成某职责平均变化显著更高；
- 三职责长期平均表现修正接近 0；
- 不鼓励刷伤害、刷治疗或消极保命。

未通过时，正式产品只使用胜负、对局强度和不确定性；表现数据只展示分析结果。

## 16. 置信度、峰值与综合分

置信度由：

```text
模型确定性 60%
数据完整度 25%
样本覆盖度 15%
```

建议展示：

| 置信度 | 状态 |
|---:|---|
| 0%–29% | 定位中 |
| 30%–59% | 初步估计 |
| 60%–79% | 较稳定 |
| 80%–100% | 高置信度 |

久未使用职责或跨越大版本只扩大 `sigma`，不直接扣减 `mu`。

生涯峰值要求：

- 置信度至少 60%；
- 至少 10 场有效职责比赛；
- 采用 7 日滚动中位数最高值，避免单场尖峰。

次要综合 MMR 根据三个已经完成定位的职责，结合最近 180 天时长、生涯时长和置信度加权。综合分只作摘要。

- `career_role_mode_summary`：模式样本、时长、胜负、累计影响；
- `career_role_season_summary`：动态赛季的开始、结束、峰值和净变化；
- `mmr_model_versions`：算法和配置版本。

所有新表通过前向兼容、幂等迁移创建，并提供升级库测试。

## 18. 重算与幂等

所有比赛按以下稳定顺序重放：

```text
begin_ts ASC
season ASC
match_id 的非敏感稳定哈希 ASC
```

新增最新比赛可从检查点继续。补入、修改或删除历史比赛时，从最早受影响时间点重放。

要求：

- 重复同步不重复加分；
- 乱序导入结果一致；
- 同一输入和模型版本结果一致；
- 失败事务保留上一套完整结果；
- 不向前端暴露半套轨迹。

## 19. Tauri 接口

只读接口：

```text
get_career_mmr_overview()
get_role_mmr_history(role, season?, from?, to?, granularity?)
get_role_mmr_mode_breakdown(role)
get_role_mmr_season_breakdown(role)
get_mmr_match_explanation(matchId, role)
```

维护接口：

```text
rebuild_career_mmr()
get_career_mmr_build_status()
```

返回 DTO 只包含 MMR、变化、置信度、模式、赛季、中文解释和非敏感统计值，并递归脱敏 token-like 字段。

## 20. 页面信息架构

新增独立一级页面“生涯 MMR”：

```text
生涯 MMR
├─ 综合摘要与三职责卡片
├─ 职责历史趋势和置信区间
├─ 模式贡献
├─ 动态赛季对比
└─ 最近 MMR 变化记录
```

页面赛季筛选只改变展示范围，不改变后台生涯计算范围，也不新增全局赛季状态。

单场解释由后端实际因子生成，例如：

```text
本场输出 MMR +8
胜负基础变化 +7
对手强度影响 +2
最后一击表现 +1
资源转化债务 -1
数据完整度 82%
```

## 21. 异常与降级

- 负数、非有限或明显异常统计关闭表现修正；
- 比赛时长缺失时不计算每 10 分钟表现；
- 同场玩家不全时预期胜率回退并降低质量；
- 无法识别职责时不更新职责 MMR；
- 中途退出和补位只有在上游能可靠识别时才调整参与质量；
- 不根据低时长主观推断并惩罚退出；
- 缺少表现数据不阻断胜负主干；
- 角斗最后回合缺失时不得借用前一回合表现。

## 22. 验证矩阵

必须覆盖：

- 三职责独立、不串分；
- 动态赛季发现；
- 普通模式职责时长拆分和降级；
- 角斗只取最后有效回合；
- 角斗最后回合局部/累计口径；
- 最后一击拆分不重复计分；
- `healingTaken` 自疗审计；
- 资源转化债务符号和上限；
- 英雄基线样本回退；
- 竞技单场每个职责不超过 `±30`；
- 快速单场每个职责不超过 `±10`；
- 多职责比赛的实际变化与各职责时长占比一致；
- 表现修正不反转胜负方向；
- 重复同步和历史补入幂等；
- 升级库和空库；
- 模型版本切换；
- 事务中断回滚；
- DTO、错误和诊断递归不含 token-like 字段或原始隐私 ID。

## 23. 分阶段交付

### 阶段一：字段与训练数据审计

- 补全英雄职责映射；
- 建立非敏感训练投影；
- 审计普通模式英雄时长；
- 审计 `healingTaken` 自疗语义；
- 审计角斗最后回合统计口径；
- 输出覆盖率和异常聚合报告。

### 阶段二：基准 MMR

- 三职责 `mu/sigma`；
- 动态赛季；
- 胜负、对局强度和置信度；
- 历史重放；
- 单场上限；
- 角斗最后回合职责。

### 阶段三：离线权重实验

- 三职责独立拟合；
- 最后一击倍率；
- 资源转化债务；
- 时间、赛季和英雄回测；
- 1,000 次比赛级 bootstrap；
- 候选权重报告。

具体执行、数据防泄漏、1,000 次比赛聚类 bootstrap 与影子晋级门槛见
`docs/superpowers/plans/2026-07-13-career-role-mmr-weight-study.md`。在该计划全部门槛通过前，正式模型的 `performance_adjustment` 保持为 `0`。

### 阶段四：影子模型

正式显示基准模型，后台并行计算实验模型，比较预测校准、波动、英雄偏差和模式偏差。

### 阶段五：启用表现修正

只有通过验收门槛后才创建新 `model_version`、完整重放历史并启用表现修正。

## 24. 隐私与发布要求

- 不读取、输出或持久化 token、customerToken、cookie、authorization、credential；
- 不把其他玩家原始 ID 或 GUID 写入 MMR DTO、日志和报告；
- 训练投影和事件只保存非敏感数值；
- 训练与诊断输出只包含聚合数据；
- 不新增开发机绝对路径依赖；
- 数据库通过 Tauri `app_data_dir` 解析；
- 模型配置和必要字典必须正式打包；
- 发布前执行后端、前端、Tauri 构建、干净 checkout 和安装烟测。

## 25. 完成定义

该功能只有在以下条件全部满足后才可称为完成：

- 三职责基准 MMR 可从全部动态赛季确定性重放；
- 普通模式和角斗输入规则符合本设计；
- 角斗只使用最后有效回合个人数据；
- 单场上限严格生效；
- 置信度、峰值、模式和赛季汇总可解释；
- 学习权重通过规定回测后才进入正式模型；
- 数据库迁移、幂等、隐私和发布验证通过；
- UI 明确声明该分数不是暴雪官方隐藏分。
