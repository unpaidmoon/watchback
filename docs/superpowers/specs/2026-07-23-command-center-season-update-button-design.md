# 指挥台单赛季更新按钮视觉增强设计

## 背景

指挥台“已同步数据”表格中的单赛季“更新”按钮使用通用 `ghostButton`。当前按钮背景与表格行背景接近，且指挥台样式只设置了 `border-color`，没有形成可见边框，导致按钮与背景融为一体。

## 目标

- 让每行“更新”按钮在常态下可被快速识别为可操作控件。
- 保持次级操作层级，不与“同步一个赛季”等主操作竞争。
- 沿用现有颜色、圆角、间距与焦点规范，不引入新的视觉语言。
- 不改变表格布局、按钮文案、同步逻辑或可用性判断。

## 方案

仅增强 `.syncedSeasonUpdateButton`，不修改全局 `ghostButton`：

- 保持现有 `80px` 宽度、`44px` 最小高度和内边距。
- 使用 `var(--surface-control)` 作为浅灰绿背景。
- 增加 `1px solid var(--border-subtle)` 细边框。
- 使用 `var(--text-primary)` 作为文字颜色。
- 悬停时在现有表面上混入少量主文字色，使反馈清晰但克制。
- 禁用时使用不可点击光标与降低透明度，同时保留可读文案。
- 保留现有 `2px` `var(--data-primary)` 键盘焦点外环。
- 交互过渡只作用于背景、边框、颜色和透明度，持续时间遵循现有规范。

## 初始按钮改动范围

单赛季更新按钮的初始改动仅涉及：

- `apps/owstats-desktop/src/styles/features/command-center.css`
- 对应的前端样式回归测试

后续设置按钮和健康标签扩展会增加同一页面组件与样式测试；赛季目标步进器扩展会进一步修改 React 组件、Tauri 后端 DTO、赛季选择逻辑和同步请求测试。所有扩展均不修改 SQLite schema，也不读取真实凭据或真实隐私数据。

## 验证

- 回归测试确认按钮具有浅灰绿背景与完整细边框。
- 回归测试确认悬停和禁用状态存在。
- 运行前端测试与构建。
- 运行 `git diff --check`，并核对工作树只增加本任务预期改动；用户原有未提交修改保持不动。

## 设置工具按钮扩展

指挥台“本地应用与支持”中的“版本号”“日志文件”“数据存放路径”和“Github地址”按钮存在相同的层级问题：通用按钮基础样式将边框设为 `0`，页面级样式只覆盖 `border-color`，因此按钮与工具区背景缺少清晰分隔。

本次扩展仅增强 `.phase6SettingsPlaceholderAction`：

- 复用单赛季更新按钮的 `var(--surface-control)` 背景、`1px solid var(--border-subtle)` 边框和 `var(--text-primary)` 文字。
- 保持现有图标、文案、按钮高度、四列布局以及窄屏两列布局。
- 悬停时在表面中混入少量主文字色；禁用时降低透明度并显示不可点击光标。
- 键盘焦点使用现有 `2px` `var(--data-primary)` 外环。
- 不扩大到工具区其他按钮或指挥台全部 `ghostButton`，避免改变登录、同步和 DeepSeek 设置操作的视觉层级。

扩展验证包括设置按钮常态、悬停、禁用和焦点样式的回归断言，并继续执行完整前端测试、构建与差异检查。

## 数据健康标签扩展

指挥台账号面板中的四项数据健康标签当前使用内容自适应宽度和五列网格，标签长度不同时难以形成稳定对齐；页面级样式还将既有状态色覆盖为透明底，无法快速区分正常和异常。

调整方案：

- 宽屏使用 `repeat(4, minmax(0, 1fr))`，四项固定等宽单行排列。
- 每项统一最小高度、内边距、控件圆角和居中文字；标签占满网格列，不再由内容长度决定宽度。
- 正常状态使用低饱和浅绿背景与绿色细边框，异常状态使用低饱和浅红背景与红色细边框。
- 状态文字保持深灰并保留明确的中文正常/异常文案，颜色不是唯一状态信息。
- 移除健康标签内的勾选图标，不增加叉号图标。
- 窄屏切换为两列，避免四列文本被压缩或溢出。
- 健康判断条件保持不变：登录凭证、数据库可读性、本地赛季数据和待处理失败仍使用现有布尔值。

实现会将异常项从警告外观明确为错误外观，但不会改变上游状态、同步逻辑或错误传播。验证覆盖四列布局、窄屏两列布局、正常/异常表面、无图标结构和原有中文文案。

## 赛季目标步进器扩展

现有同步选择器由后端 `MIN_SYNC_SEASON = 15` 和 `CURRENT_SEASON = 23` 生成固定的 S15–S23 列表。未来赛季上线后，即使前端增加选项，后端范围校验和当前赛季特殊请求仍可能阻止同步，因此不能只修改下拉框。

### 交互

- 将下拉框替换为 `减少 / Sxx / 增加` 三段式数字步进器。
- 最低赛季固定为 S15；目标为 S15 时禁用减少按钮。
- 不设置前端最高赛季，用户可以手动增加到未来赛季。
- 使用“目标赛季”而非“当前赛季”，辅助文字改为“最低支持 S15”。
- 两个按钮与中间数值区保持至少 `44px` 高度，支持键盘焦点和清晰禁用态。

### 初始值与持久化

- 不保存用户临时选择。
- 每次首次加载指挥台时，选择本地 SQLite 中最高的有效赛季。
- 本地没有有效赛季时使用安装包默认兜底 S23。
- 用户手动切换但未成功同步的赛季，在刷新或重启后不会保留。
- 未来赛季同步成功并写入本地数据库后，下次加载会自然选中该最高赛季。

### 后端边界

- 保留 `MIN_SYNC_SEASON = 15`，请求只校验 `season >= MIN_SYNC_SEASON`，不再使用 S23 作为可选上限。
- 将 `CURRENT_SEASON = 23` 的职责收窄并重命名为默认兜底赛季，不再向 UI 声称它是运行时当前赛季。
- 指挥台 DTO 不再提供固定 `syncableSeasons` 列表或误导性的“当前赛季”语义；改为提供最低支持赛季、默认目标和本地可用赛季。
- S23 保留既有当前赛季请求兼容路径。
- S24 及以后的目标只发送明确赛季号；上游无数据或拒绝时保留原始错误，不得回退到无赛季参数，也不得将其他赛季数据写入所选赛季。

### 验证

- 后端测试覆盖 S15 下限、S14 拒绝、未来赛季请求保留和本地最高赛季默认选择。
- 同步请求测试覆盖未来赛季只使用显式参数且不回退。
- 前端测试覆盖加减行为、S15 禁用、无上限增加、中文文案和无下拉框。
- 完整运行前端测试与构建；后端运行格式检查和测试。
