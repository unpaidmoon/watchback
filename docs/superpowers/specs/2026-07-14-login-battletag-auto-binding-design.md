# 登录时自动识别并绑定 BattleTag 设计

- 日期：2026-07-14
- 状态：已确认
- 适用范围：`apps/owstats-desktop` 指挥台的网易大神浏览器登录与当前目标玩家绑定流程

## 背景

当前桌面端通过浏览器登录网易大神，从页面上下文识别 `role_id`，再调用签名接口取得账号 token。BattleTag 仍由用户在指挥台手工输入，后端通过 `searchBnetAccount` 解析目标 `customerToken`，并使用 `queryCard` 确认目标可读取。

网易大神守望先锋页面在登录并选择游戏角色后，会显示带有稳定中文标签的文本：

```text
战网昵称：玩家名称#数字
```

现有 CDP 页面采集脚本已经读取 `document.documentElement.innerText`，因此可以在同一登录轮次中提取当前页面所选角色的 BattleTag，并自动完成原有绑定步骤。产品不再提供手工 BattleTag 输入；无法可靠提取时只能重试识别或重新进入正确页面。

## 目标

- 登录时从带“战网昵称”标签的页面文字中提取当前 BattleTag。
- 将同一登录轮次得到的 `role_id`、账号 token 和 BattleTag 作为一个整体处理。
- 没有当前目标时，自动执行 `searchBnetAccount`、`queryCard` 和目标保存。
- 已有相同目标时保持现状，不重复绑定。
- 已有不同目标时不自动覆盖，由用户确认是否切换。
- 支持用户在浏览器页面切换网易大神账号或守望先锋角色。
- 只保存一个当前登录账号和一个当前目标，不建立多账号历史或映射表。
- 移除 BattleTag 手工输入和任意目标绑定入口。

## 非目标

- 不允许手工输入或绑定任意 BattleTag。
- 不保存多个账号、多个目标或账号到目标的历史映射。
- 不从整个页面无锚点地匹配第一个 `名称#数字`。
- 不使用 OCR 识别 BattleTag。
- 不新增同步全部赛季、全局赛季状态或目标历史列表。
- 不向前端、日志、错误或业务 JSON 暴露 token、`customerToken`、页面全文或原始上游响应。

## 提取方案

采用现有页面文字采集路径，在带“战网昵称”标签的文本中提取 BattleTag。匹配需同时满足：

- 标签为 `战网昵称`。
- 标签和昵称之间允许中文或英文冒号及空白。
- 昵称非空，并包含 `#` 与非空数字后缀。
- 结果经过首尾空白清理和现有 BattleTag 规范化。

概念匹配形式为：

```text
战网昵称\s*[:：]\s*(非空昵称#数字)
```

实现不得把全页面第一个形似 BattleTag 的文本当作当前账号。若同一轮采集出现多个不同的带标签结果，应视为结果不明确，不自动绑定。

## 登录数据流

```text
浏览器登录或切换账号
  -> 开始新的登录识别轮次
  -> 采集同一轮页面候选信息
  -> 提取 role_id
  -> 按“战网昵称”标签提取 BattleTag
  -> 使用 role_id 换取账号 token
  -> 形成同一轮登录结果
  -> 保存当前登录凭据
  -> 比较已保存目标与识别到的 BattleTag
  -> 自动绑定、保持原目标或等待用户确认切换
```

`role_id`、token 和 BattleTag 必须来自同一登录轮次。开始重新登录、页面切换账号或角色后，上一轮尚未完成的 BattleTag 候选立即失效；不得将新 token 与旧 BattleTag 组合。

BattleTag 提取不是凭据登录成功的必要条件。只要现有 `role_id/token` 凭据流程成功，登录状态就应成功；BattleTag 缺失时同步目标不可用，用户只能重试识别或重新进入带“战网昵称”的正确页面。

## 目标处理规则

登录成功并取得 BattleTag 后，按以下顺序处理：

1. 当前没有目标：自动调用现有 `searchBnetAccount`，解析 `customerToken`，调用 `queryCard` 确认可读取，然后保存当前目标。
2. 当前目标与识别到的 BattleTag 相同：保持原目标，不重复搜索或保存。
3. 当前目标与识别到的 BattleTag 不同：不自动覆盖，记录一个不含 secret 的待确认切换状态，由用户选择“切换到此账号”或“保留原目标”。
4. 用户确认切换：使用本轮已识别 BattleTag 执行现有搜索、确认和保存流程，成功后替换唯一当前目标。
5. 用户保留原目标：不修改目标文件。本轮登录凭据仍然有效，但界面需明确当前登录账号与同步目标不同，并禁用赛季同步。用户只有切回原账号，或确认切换到本轮识别账号后，才能继续同步。

产品不提供手工 BattleTag 输入。这样可以从交互和协议入口上保证目标只能来自当前浏览器页面识别结果，不允许用户借助 `searchBnetAccount` 绑定任意其他玩家。

## 指挥台交互

### 自动绑定成功

- 显示“已识别并绑定当前账号：{BattleTag}”。
- 当前目标和登录凭据均可用时，允许同步。

### 已绑定同一目标

- 显示正常登录与当前目标状态。
- 不显示额外确认。

### 检测到不同目标

- 显示“检测到当前登录账号：{BattleTag}，是否切换当前目标？”
- 提供“切换到此账号”和“保留原目标”。
- 在用户作出选择前，不自动覆盖已有目标。
- 等待选择以及选择“保留原目标”后均禁用赛季同步，避免使用新账号凭据同步旧目标。

### 提取成功但自动绑定失败

- 登录保持成功。
- 显示脱敏错误摘要和“重新绑定”操作；重试使用本轮已识别 BattleTag。
- 不把搜索或资料卡失败伪装为凭据登录失败。

### 无法提取 BattleTag

- 显示“登录成功，未能自动识别战网昵称”。
- 不显示 BattleTag 输入框或手工绑定按钮。
- 提供“重新识别”操作，并提示用户进入显示“战网昵称”的守望先锋页面后重试。
- 在成功识别并绑定当前账号前禁用赛季同步。

### 清除目标

- 清除只删除当前目标，不删除登录凭据。
- 如果本轮仍有可靠的已识别 BattleTag，可提供重新绑定当前账号的操作，不展开手工输入框。
- 如果本轮没有可靠 BattleTag，则要求重新识别，不提供手工输入。

## 状态边界

登录结果需要向产品层提供非敏感的 BattleTag 识别状态，但不得把账号 token、`customerToken`、页面候选数组或页面全文返回前端。

建议区分以下非敏感状态：

- 已识别并自动绑定。
- 已识别且目标相同。
- 已识别但等待确认切换。
- 已识别但绑定失败，可重试。
- 未识别，需要重新进入正确页面或重试识别。

待确认切换只在当前应用运行期内有效。重新登录、退出登录或开始新的浏览器识别轮次后必须清除，避免旧 BattleTag 在新账号上下文中被使用。

## 错误处理

- 页面没有“战网昵称”标签：凭据登录成功，但同步目标不可用；提示进入正确页面后重试识别。
- 标签存在但昵称为空或格式无效：视为未识别，不猜测、不自动绑定。
- 同一轮出现多个不同结果：视为结果冲突，不自动绑定。
- `searchBnetAccount` 失败：保留登录成功状态，允许使用已识别结果重试。
- `queryCard` 失败：不保存新目标；保留原目标和登录状态。
- 保存目标失败：不修改 UI 中的已绑定状态，返回脱敏错误。
- 账号切换或新登录开始：清除上一轮候选、失败重试和待确认切换状态。

## 隐私与持久化

- BattleTag 是允许显示的当前目标名称，但不得与 token-like 字段共同进入诊断 JSON。
- 页面全文、DOM 快照、storage 内容和原始接口响应不得持久化或写入日志。
- 账号 token 继续只保存在凭据存储中。
- `customerToken` 继续只保存在当前目标存储中。
- 赛季 JSON、SQLite raw JSON、前端响应、错误和测试输出继续递归脱敏 token-like 字段。
- 不新增多账号凭据文件或 `role_id -> BattleTag` 映射文件。
- 不向前端暴露可直接调用任意 BattleTag 搜索或绑定的产品命令。

## 测试

### BattleTag 解析单元测试

- 中文冒号和英文冒号。
- 标签与值之间不同空白。
- 中文、英文和混合字符昵称。
- 不同长度的数字后缀。
- 无标签、空昵称、缺少 `#`、非数字后缀。
- 页面存在其他无标签 BattleTag 时不得误识别。
- 多个相同带标签结果可归一化为一个结果。
- 多个不同带标签结果必须判为冲突。

### 登录轮次测试

- 同一轮提取的 `role_id/token/BattleTag` 可以形成登录结果。
- 新轮次开始时旧 BattleTag 立即失效。
- 新 token 不得与旧 BattleTag 组合。
- BattleTag 提取失败不影响 `role_id/token` 登录成功。

### 自动绑定测试

- 没有目标时自动搜索、确认并保存。
- 已是相同目标时不重复请求。
- 不同目标时只生成待确认状态，不覆盖。
- 用户确认后才替换目标。
- 用户保留后目标不变。
- 搜索、资料卡或保存失败均不破坏登录状态和旧目标。

### 前端测试

- 所有状态下均不存在 BattleTag 输入框或手工绑定按钮。
- 不同目标时显示切换确认。
- 提取成功但绑定失败时显示“重新绑定”。
- 提取失败时显示“重新识别”和进入正确页面的提示。
- 不存在允许任意搜索、更换或绑定目标玩家的入口或文案。

### 集成与隐私测试

- 录制 HTTP 服务覆盖 `searchBnetAccount -> queryCard -> 保存目标`。
- 覆盖首次登录、同账号重新登录、浏览器切换账号、确认切换和保留原目标。
- 检查前端 DTO、错误、日志和持久化业务 JSON 不包含账号 token、`customerToken`、页面全文或原始响应。
- 测试仅使用合成角色、BattleTag 和凭据，不读取真实浏览器 profile 或真实凭据。

## 手工验收

由用户在真实浏览器环境完成一次不回显凭据的验收：

1. 清除当前目标后登录，确认应用自动识别并绑定页面显示的 BattleTag。
2. 同账号重新登录，确认不重复绑定且输入框不出现。
3. 在浏览器页面切换账号或角色，确认应用识别到不同 BattleTag 并要求确认。
4. 选择保留原目标，确认目标未被覆盖。
5. 再次切换并确认更换，确认目标更新为新 BattleTag。
6. 模拟或等待一次自动绑定失败，确认登录仍成功、输入框不出现且可以重试。
7. 在无法提取“战网昵称”的页面完成登录，确认同步禁用、没有手工输入框，并可重新识别。
8. 对当前目标同步一个赛季，确认抓取、落盘和 SQLite 导入仍使用既有流程。

## 验收标准

- 正常网易大神守望先锋页面登录后无需手工输入 BattleTag。
- 自动绑定只使用同一登录轮次识别到的当前账号 BattleTag。
- 不自动覆盖不同的已有目标。
- 不保存多账号历史。
- 产品在任何状态下都不显示 BattleTag 输入框或手工绑定入口。
- 搜索和绑定只能由当前登录轮次自动识别的 BattleTag 触发。
- BattleTag 自动识别或绑定失败不会导致凭据登录失败。
- 所有自动化验证通过，真实验收过程中不打印或暴露任何 secret。
