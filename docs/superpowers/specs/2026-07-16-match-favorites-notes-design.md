# 对局收藏与备注设计

## 目标

在对局详情中增加账号级本地收藏与备注能力：

- 用户可以收藏单场普通对局或整场角斗对局。
- 收藏时备注可选，收藏后可以新增或修改备注。
- 对局筛选器可以只显示收藏过的对局。
- 对局列表显示收藏状态，但不显示备注摘要。
- 收藏与备注只属于当前登录账号，不跨账号共享，也不发送到上游。

## 范围

本设计覆盖：

- SQLite 收藏表及 schema 迁移。
- Tauri 收藏写入和删除命令。
- 对局列表、详情 DTO 与收藏筛选。
- 普通详情、角斗详情、独立详情页和列表右侧嵌入详情中的收藏交互。
- 对局列表收藏标记、URL 筛选状态、前端缓存一致性。
- 错误、未保存内容、隐私和验证规则。

本设计不包含：

- 收藏排序、置顶、批量收藏或批量取消。
- 按备注内容搜索。
- 多标签、收藏分组或云同步。
- 收藏单个角斗回合。
- 在对局列表中编辑或展示备注。

## 已确认的产品规则

- 备注可选；首次点击收藏立即创建空备注收藏。
- 取消收藏不弹确认，直接删除收藏及备注。
- 收藏与备注按当前账号隔离。
- 普通对局详情在全部内容最底部显示收藏操作条。
- 角斗对局只在“角斗汇总”底部显示收藏操作条；单回合不显示。
- 对局列表只显示收藏标记，不显示备注摘要。
- 备注使用显式保存，不逐字自动写入 SQLite。
- 有未保存修改时，切换对局、离开详情或从角斗汇总切换到单回合需要提示。

## 数据模型

### SQLite schema v8

新增独立表，不向 `matches` 混入用户编辑字段：

```sql
CREATE TABLE IF NOT EXISTS match_favorites (
    match_id TEXT PRIMARY KEY
        REFERENCES matches(match_id) ON DELETE CASCADE,
    note TEXT NOT NULL DEFAULT ''
        CHECK(length(note) <= 500),
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_match_favorites_updated
    ON match_favorites(updated_at DESC);
```

设计理由：

- `matches` 是同步得到的上游对局实体，`match_favorites` 是用户本地编辑数据，两者分表可避免重复同步覆盖备注。
- 收藏存在性由表行表达；取消收藏删除整行，不保留“未收藏备注”。
- 外键级联保证对局被正式删除后不会留下孤儿收藏。
- 当前账号拥有独立 SQLite 文件，因此该表天然遵循账号隔离边界，不需要额外存储 `account_id`。
- 时间戳使用 UTC ISO 8601 字符串；本期不在 UI 展示，仅用于稳定更新与后续维护。

迁移要求：

- `CURRENT_SCHEMA_VERSION` 从 7 升至 8。
- v8 迁移必须可从现有数据库前向升级。
- 初始化与重复运行迁移保持幂等。
- 不读取、复制或修改其他账号数据库。

## 后端接口

### 写入命令

新增两个 Tauri 命令：

```text
save_match_favorite(request: {
  matchId: string,
  note: string
}) -> MatchFavoriteView

delete_match_favorite(matchId: string) -> void
```

`save_match_favorite` 同时负责首次收藏和备注更新：

1. 验证 `match_id` 对应的对局存在。
2. 按 Unicode 字符数校验备注不超过 500 字。
3. 首次写入时设置 `created_at` 与 `updated_at`。
4. 已存在时只更新 `note` 与 `updated_at`，保留 `created_at`。
5. 返回数据库中的最终收藏视图。

`delete_match_favorite`：

1. 按 `match_id` 删除收藏行。
2. 已不存在时视为幂等成功。
3. 不返回备注内容，也不将备注写入日志或错误。

对不存在的对局执行收藏时返回稳定中文错误：“未找到对应对局，无法收藏。”

### DTO

新增：

```text
MatchFavoriteView {
  note: string
}
```

`MatchSummary` 新增：

```text
isFavorite: boolean
```

列表 DTO 不包含备注，避免无用数据扩散到列表缓存。

`MatchDetailView` 新增：

```text
favorite: MatchFavoriteView | null
```

`MatchFilters` 新增：

```text
favoriteOnly?: boolean
```

### 查询

对局列表查询：

- `LEFT JOIN match_favorites f ON f.match_id = m.match_id`。
- 通过 `f.match_id IS NOT NULL` 生成 `isFavorite`。
- `favoriteOnly` 为真时追加 `AND f.match_id IS NOT NULL`。
- 收藏条件与赛季、模式、英雄、地图、胜负、复盘标签、玩家和日期条件使用逻辑与。
- 收藏连接不得造成普通对局或角斗对局重复。

对局详情查询：

- 在现有详情装配过程中读取该 `match_id` 的收藏。
- 普通详情和角斗详情返回相同的整场收藏对象。
- 不为角斗回合创建独立收藏键。
- 不增加前端第二次“读取收藏”请求。

## 前端筛选

“更多筛选”增加：

```text
收藏状态
全部
仅看收藏
```

行为规则：

- 选中“仅看收藏”时写入 `filters.favoriteOnly = true`。
- URL 使用 `favorite=1`；只接受 `1` 为真，缺失或其他值按未启用处理。
- 启用后“更多筛选”计数增加 1。
- 活动筛选标签显示“收藏：仅看收藏”。
- 单独移除该标签只清除收藏条件。
- “清除筛选”清除收藏条件，但保留当前页面已有的赛季保留规则。
- 收藏条件参与 `matchFiltersKey`，从而正确区分页面缓存。

## 详情交互

### 组件边界

新增复用组件 `MatchFavoriteEditor`，职责仅包括：

- 展示当前收藏状态。
- 发起收藏、保存备注和取消收藏。
- 管理备注草稿、保存状态、错误和未保存状态。
- 向父级暴露是否存在未保存修改以及放弃修改保护。

父级负责：

- 决定组件在详情底部的渲染位置。
- 在切换对局、路由离开或角斗页签切换前调用未保存保护。
- 收藏状态变化后更新对局列表和页面缓存。

独立详情与列表右侧嵌入详情必须使用同一组件和同一交互规则，不能分别复制状态逻辑。

### 未收藏状态

详情内容最底部只显示一个次级按钮：

```text
☆ 收藏此对局
```

点击后：

1. 调用 `save_match_favorite({ matchId, note: "" })`。
2. 按钮进入保存中状态并禁止重复点击。
3. 后端成功后才切换为已收藏状态并展开备注区。
4. 失败时保持未收藏，显示内联中文错误和重试入口。

### 已收藏状态

独立操作条包含：

- “★ 已收藏”按钮。
- 最多 500 字的多行备注输入框。
- 字数提示。
- “保存备注”按钮。
- 保存成功状态或内联错误。

保存规则：

- 允许保存空备注。
- 保留用户输入的换行。
- 备注草稿与最后一次成功保存值不同时视为未保存。
- 保存中禁用收藏、备注和保存操作。
- 成功后以返回值覆盖已保存基线并显示“已保存”。
- 失败时保留草稿，继续标记为未保存，并提供重试。

点击“★ 已收藏”立即调用删除命令：

- 不弹取消确认。
- 成功后收起备注区并清空本地备注状态。
- 失败时保留收藏、备注和草稿，显示内联中文错误。

### 显示位置

普通对局：

- 在队伍数据、对比数据等全部详情内容之后显示。

角斗对局：

- 仅当 `selectedArenaKey === "summary"` 时，在汇总内容最底部显示。
- 单回合页签不显示收藏按钮或备注。
- 收藏键始终是整场 `match_id`。

独立详情与嵌入详情都遵循上述规则。窄详情栏允许操作条由“备注 + 右侧操作”回退为纵向排列，不产生横向滚动。

### 未保存保护

备注存在未保存修改时，以下动作先提示：

```text
备注尚未保存，是否放弃修改？
```

覆盖动作：

- 在列表中选择另一场对局。
- 返回对局列表或离开详情路由。
- 从角斗汇总切换到任意单回合。

选择继续编辑时取消原动作；选择放弃时恢复最后保存值并继续原动作。

## 对局列表收藏标记

收藏对局在列表卡片头部显示小型星标和可访问文本“已收藏”：

- 星标是状态展示，不是列表内收藏按钮。
- 不在卡片按钮内部嵌套另一个按钮。
- 不显示备注内容或备注摘要。
- 不改变现有卡片高度和数据区布局。
- 使用既有黑灰文字与低对比表面；不引入新品牌色、厚阴影或彩色胶囊。

## 写入后的页面一致性

### 收藏成功

- 更新当前详情的 `favorite`。
- 更新当前列表对应 `MatchSummary.isFavorite`。
- 同步写入 `MatchesPageCache`，避免返回页面后星标回退。
- 不重新加载整份列表。

### 保存备注成功

- 更新当前详情收藏对象和已保存基线。
- 列表 DTO 不含备注，因此无需重新加载列表。

### 取消收藏成功

- 未开启“仅看收藏”时，只更新当前详情、列表行和缓存中的收藏状态。
- 开启“仅看收藏”时，重新执行当前筛选查询：
  - 已取消收藏的对局从列表移除。
  - 使用现有选择规则选择下一场可用对局。
  - 没有剩余收藏时显示“暂无符合条件的对局”。
  - 更新页面缓存、选中项和详情状态。

重复赛季同步不得清空或覆盖收藏表。

## 错误与状态

- 所有写操作成功前不做乐观状态切换。
- 同一编辑器只允许一个写操作进行。
- 写入错误显示在收藏操作条内部，不使用全页错误状态。
- 错误文案使用中文，不包含备注、原始 SQL、数据库路径、账号 ID 或对局原始隐私 ID。
- 对局详情加载失败时不单独尝试加载或显示收藏编辑器。
- 收藏筛选查询失败沿用现有列表错误与重试界面。

## 隐私

- 收藏和备注仅写入当前账号的本地 SQLite。
- 不发送给上游，不进入同步请求。
- 不写入 `raw_entry_json`、`raw_detail_json`、`rawJson`、诊断 JSON 或日志。
- 测试和视觉验收只使用匿名 fixture，不读取真实账号备注或真实隐私数据。
- 前端错误与后端错误不得回显用户备注。

## 测试

### 后端迁移与存储

- schema v7 数据库可升级到 v8。
- 重复初始化保持幂等。
- 收藏表、长度约束和外键存在。
- 删除对局会级联删除收藏。
- 两个账号数据库的收藏互不影响。

### 后端命令

- 首次收藏创建空备注。
- 保存非空、多行和空备注。
- 更新备注保留 `created_at` 并更新 `updated_at`。
- 删除收藏同时删除备注，重复删除幂等成功。
- 不存在的对局返回稳定中文错误。
- 500 字成功，501 字失败。
- 错误和日志不包含备注内容。

### 后端查询

- 列表正确返回收藏与未收藏状态。
- `favoriteOnly` 只返回收藏对局。
- 收藏筛选可与所有现有筛选条件组合。
- 普通对局和角斗对局都能命中。
- 收藏连接不产生重复行。
- 详情返回收藏对象或 `null`。

### 前端筛选

- `favorite=1` URL 解析与序列化正确。
- 非法或缺失值不启用收藏筛选。
- “更多筛选”计数、活动标签、单项移除和清除行为正确。
- 收藏条件参与缓存键。

### 前端交互

- 未收藏时只显示收藏按钮。
- 收藏成功后展开备注编辑器；失败时保持未收藏。
- 备注保存失败时保留草稿。
- 取消收藏直接执行，失败时保留原状态。
- 有未保存备注时，切换对局、离开详情和切换角斗回合会拦截。
- 普通详情底部显示编辑器。
- 角斗仅汇总显示，单回合不显示。
- 独立详情与嵌入详情行为一致。
- 仅看收藏状态下取消收藏会移除该行并选择下一场。
- 对局列表只显示收藏标记，不显示备注。
- 收藏状态写入和移除后页面缓存保持一致。

### 视觉验收

使用匿名 fixture 在以下视口检查：

- `2540×1344`
- `1920×1080`
- `1440×900`

覆盖：

- 未收藏、已收藏、空备注、500 字备注。
- 保存中、保存成功、保存失败。
- 普通详情、角斗汇总、角斗单回合。
- 独立详情与列表右侧窄详情。
- 列表收藏标记不改变卡片高度。
- 底部操作条不产生嵌套卡片、横向滚动或额外滚动容器。

## 验收标准

- 用户能收藏普通对局和整场角斗对局，并可选填、修改或清空最多 500 字的备注。
- 取消收藏无需确认，并同时删除备注。
- 收藏与备注严格按当前账号隔离，重复赛季同步不覆盖。
- “仅看收藏”能与现有筛选组合，并通过 URL 和缓存稳定恢复。
- 对局列表只显示收藏标记，不显示备注。
- 收藏操作条只出现在普通详情底部或角斗汇总底部。
- 独立详情、嵌入详情、缓存和筛选结果在写入后保持一致。
- 备注不进入上游请求、日志、诊断 JSON 或 raw JSON。
- 所有定向测试、完整后端测试、完整前端测试、生产构建和差异检查通过。
