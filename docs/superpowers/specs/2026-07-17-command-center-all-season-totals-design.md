# 指挥台全赛季总数设计

## 目标

指挥台顶部“本地对局”和右侧“数据覆盖度”表达当前账号所有已同步赛季、全部六种模式的本地数据总量，不再表达当前赛季的预设/开放对局数量。

## 已确认契约

- 总对局数为 `seasonStatuses` 中每个已同步赛季 `matchCount` 的总和。
- 总详情数为 `seasonStatuses` 中每个已同步赛季 `detailCount` 的总和。
- 覆盖率按 `总详情数 / 总对局数` 计算并四舍五入，分母为零时显示 `0%`。
- 顶部“本地对局”、顶部“覆盖率”、右侧覆盖率与“详情数/对局数”使用同一组汇总结果。
- 赛季同步工作台仍逐赛季展示和操作；不新增全局赛季状态，也不改变同步、复盘准入或后端 DTO 语义。

## 实现边界

在前端增加一个纯函数，将后端已经返回的 `seasonStatuses` 汇总为总对局数、总详情数和覆盖率；`OnboardingPage` 只消费该结果。这样不需要新增 SQL、Tauri command 或持久化字段。

## 验证

先用多个赛季、普通与角斗数量不同的输入建立失败测试，确认旧代码没有全赛季汇总能力；再实现最小纯函数并运行前端完整测试和构建。最终检查 `git diff --check` 与 `git status --short`，确保没有触碰用户现有登录改动。
