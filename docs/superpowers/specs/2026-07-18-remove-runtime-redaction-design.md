# 取消运行时脱敏设计

日期：2026-07-18

## 背景

当前桌面端在同步、导入、SQLite 持久化、赛季快照、错误文本、查询 raw JSON 和历史隐私迁移等多个位置执行递归脱敏。脱敏会删除 token、customerToken、cookie、authorization、credential、storage 等字段，或替换错误文本中的对应值。

用户已明确调整本项目的产品约束：运行时不再执行任何脱敏。新抓取的数据中自然存在的字段应原样保留，但系统不得主动把登录凭据复制到原本不包含它们的文件、DTO、事件或日志中。

本次调整同时服务于赛季快照性能目标。当前快照链路会多次遍历和克隆完整 JSON；取消运行时脱敏后，应移除这些遍历，而不是将脱敏函数改成名称误导的空操作。

## 决策

采用“删除运行时脱敏调用、原始数据直通”的方案。

不采用以下方案：

- 不把脱敏函数改成简单返回原值。该做法会保留误导性 API，并可能继续产生完整 JSON 克隆。
- 不增加可切换的“原始数据模式”。产品已明确不需要脱敏，双模式会增加设置、迁移和测试成本。

## 产品边界

### 原始数据直通

以后新抓取的数据按以下链路处理：

```text
上游响应
  -> 解析业务索引字段
  -> 原始 JSON 写入 SQLite
  -> 原始 JSON 生成赛季快照
  -> 查询或错误结果按现有结构返回
```

具体要求：

- 列表、详情、资料卡和同步错误中的原始 JSON 不再删除或替换敏感字段。
- 快照组装完成后直接序列化，不再递归扫描、克隆或修改 JSON。
- 上游错误、解析错误和请求错误不再经过文本遮盖。
- 详情请求失败时，现有错误记录保存实际错误文本，不统一替换成固定脱敏文案。
- 查询和设置接口中原本存在的 raw JSON 不再执行显示脱敏。
- 已经脱敏的历史数据保持原状，不自动重新抓取或恢复。

### 禁止主动扩散

取消脱敏不等于主动收集或复制凭据：

- 不给账号索引、后台事件、普通 DTO、日志或赛季快照新增凭据字段。
- 不主动把登录凭据文件中的 token、cookie 或 authorization 复制到业务数据中。
- 结构化 DTO 继续只返回其现有字段；只有 DTO 已经包含的 raw JSON 才按原内容返回。
- 后台事件继续只发送账号作用域、赛季、阶段、状态和匿名计数，不新增 match/player id、请求 URL 或 raw JSON。

### 继续保留的发布边界

以下机制不属于运行时脱敏，继续保留：

- `prepareAssets` 对发布资源中敏感字段的拒绝检查。
- 运行时配置、账号索引和安装包资源的凭据防泄漏检查。
- 不提交真实凭据、浏览器 profile、真实用户数据 dump 或本地 SQLite。
- 英雄、地图和玩家名称等业务显示兜底规则。

## 组件改动

### 导入与 SQLite

- `importer` 不再调用 JSON 或文本脱敏函数。
- 快速列表写库不再为 `raw_entry_json` 创建脱敏副本。
- 详情和错误持久化直接使用收到的原始内容。
- 业务索引字段仍按现有方式提取，赛季隔离、幂等性和派生索引行为不变。

### 赛季快照

- `rebuild_complete_season_payload` 从 SQLite 解析并组装完整 payload 后直接返回。
- `rebuild_snapshot_for_revision` 直接序列化该 payload，不再进行第二次处理。
- `write_season_payload` 不再创建脱敏副本。
- 临时文件、`sync_all`、revision 稳定性检查和原子替换语义保持不变。

### 错误、查询和前端返回值

- 删除运行时对 `safe_error_message`、`redact_sensitive_text`、`redact_sensitive_json` 的依赖。
- 原错误只在现有错误传播或日志位置出现，不新增额外日志。
- 查询 raw JSON 和资料卡 raw JSON 按数据库内容返回。
- 前端不新增展示凭据的专用组件或字段。

### 历史隐私迁移

- 停止自动执行 `privacy_migration` 对赛季 JSON 和 SQLite 的清理。
- 不删除既有备份、完成 marker 或已经清理后的数据。
- 新安装和升级均不再主动修改历史业务 JSON 中的敏感字段。

### 文档约束

实现时同步更新 `AGENTS.md`、`README.md` 和 `docs/maintenance.md`：

- 删除“运行时必须递归脱敏”的旧规则。
- 写明原始数据直通和禁止主动扩散的边界。
- 保留发布资源、凭据文件、版本控制和真实用户数据的防泄漏规则。

## 错误处理

- 原始错误文本可以包含上游自然提供的 URL、token-like 字段或响应片段。
- 不主动拼接登录凭据到错误消息。
- 错误传播失败时仍遵守现有事务边界：列表、详情、快照和 revision 不得因取消脱敏而破坏幂等性或恢复能力。
- 快照序列化或替换失败时继续保留旧文件。

## 测试

### 原始数据保留合同

使用合成凭据字段验证：

- SQLite 的 `raw_entry_json`、`raw_detail_json`、`sync_errors.raw_json` 原样保留字段和值。
- 赛季快照原样保留自然出现的 token、customerToken、cookie 和 authorization。
- 错误文本不再替换合成敏感片段。
- 查询 raw JSON 按数据库内容返回。

### 禁止主动扩散合同

- 账号索引、后台事件和不含 raw JSON 的普通 DTO 不新增凭据字段。
- 运行时配置、资源准备和安装包检查继续拒绝敏感字段。
- 测试只使用合成值，不读取或输出真实凭据。

### 历史与同步回归

- 隐私迁移不再修改旧赛季文件或 SQLite，既有备份与 marker 保持不变。
- 保留五个第一页请求、前台短事务、后台分页恢复、详情十条批次、revision 快照和全量抓取测试。
- 重复同步继续保持列表、详情、错误和派生索引幂等。

## 性能验收

使用同一份本地 S22 数据库的只读副本或临时输出目录，分别记录修改前后的：

- SQLite 读取与 JSON 解析/组装耗时；
- 快照序列化耗时；
- 文件写入与同步耗时；
- 总耗时、条目数和输出文件大小。

计时输出不得包含原始字段、玩家 ID 或凭据。不预设固定提速比例，以实测结果说明移除递归遍历和 JSON 克隆后的收益。

## 验收条件

- 运行时代码不再删除、替换或遮盖自然出现的敏感字段。
- 运行时代码不再为了脱敏递归遍历或克隆完整 JSON。
- 系统不主动把凭据复制到新的存储或输出面。
- 构建资源与共享配置防泄漏检查保持有效。
- 历史数据不重抓，隐私迁移不再主动清理。
- 同步、恢复、快照和多赛季行为保持原有正确性。
- Rust、前端、生产构建和 Tauri 安装包验证通过。
