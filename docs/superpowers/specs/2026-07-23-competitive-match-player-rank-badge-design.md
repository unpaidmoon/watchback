# 竞技对局玩家段位徽标设计

## 目标

在对局详情的预设竞技和开放竞技中，于玩家名称右侧显示该玩家的标准竞技段位图标与分段数字。视觉布局与现有角斗竞技段位徽标一致。

## 范围

- 覆盖预设竞技与开放竞技的紧凑对局详情和独立对局详情。
- 角斗竞技继续使用现有角斗段位图标和布局。
- 快速模式不新增段位展示。
- 不新增 SQLite 字段、迁移或历史数据回填。
- 不改变上游原始 JSON 的保存方式。

## 数据映射

普通竞技对局从玩家对象的 `rankInfo` 读取段位：

- 段位名称兼容 `rankName` 与 `rank_name`。
- 分段兼容 `rankSubTier` 与 `rank_sub_tier`。
- 已识别的段位名称规范化为标准竞技资源键。
- 中文显示文本由段位名称与有效的正整数分段组成。

未知段位、缺失 `rankInfo` 或缺失可识别段位名称时，`rankLabel` 与 `rankKey` 保持为空。不得用“未定级”图标或文字代替。

## 前端展示

玩家段位徽标根据对局类型选择资源：

- 角斗竞技使用现有角斗段位资源。
- 预设竞技与开放竞技使用标准竞技段位资源。
- 徽标继续位于玩家名称右侧，并沿用现有尺寸、文字和换行规则。
- 徽标中的数字取中文段位文本末尾的分段数字。
- 没有有效段位图标时不渲染徽标，名称行不保留空白占位。

紧凑详情与独立详情共用同一段位解析和展示规则，避免两处行为分叉。

## 错误与回退

- 上游缺少段位字段属于正常数据缺失，不产生页面错误。
- 无法识别的段位键不得回退为“未定级”图标。
- 段位资源缺失时保持为空，不影响玩家的其他统计数据。
- 不向 DTO、日志或事件增加凭据、隐私标识或额外原始 payload。

## 测试与验收

按测试驱动方式实施：

1. 后端测试先证明预设竞技和开放竞技玩家的标准段位字段尚未映射。
2. 前端测试先证明普通竞技仍无法选择标准段位资源。
3. 最小实现后验证：
   - 预设竞技显示标准段位图标与分段数字。
   - 开放竞技显示标准段位图标与分段数字。
   - 角斗竞技仍显示角斗段位图标。
   - 无段位、未知段位或缺失资源时名称右侧为空。
   - 紧凑详情与独立详情行为一致。
4. 运行相关前后端测试、完整前端测试与构建，并执行 `git diff --check`。

## 非目标

- 不展示段位完整中文名称或新增悬浮提示。
- 不调整段位图标资产。
- 不新增段位统计、筛选或排行功能。
- 不改变快速模式、赛季同步或数据库投影。
