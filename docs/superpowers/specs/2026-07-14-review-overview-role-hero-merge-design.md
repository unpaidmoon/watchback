# 战报概览合并职责与英雄设计

## 目标

让战报的“概览”承载完整的赛季复盘信息，消除“职责与英雄”“地图”独立标签造成的信息分散与首屏留白。

## 范围

- 删除战报页内的“职责与英雄”“地图”标签。
- 将现有完整职责段位、胜率、KDA 与英雄池分析区放到“概览”顶部。
- 将现有赛季概览与关键表现放到职责分析之后。
- 将现有完整地图分析区放到概览底部。
- 保留“队友协作”“成就”标签、每页独立赛季状态、既有请求与数据模型。
- 旧 URL 的 `view=roles` 与 `view=maps` 都解析为 `overview`，避免历史链接呈现空内容。

## 布局与视觉

概览按“职责与英雄 → 赛季概览与关键表现 → 地图”连续排列。职责与英雄、地图各自横跨概览内容宽度；中段保持当前宽屏的赛季概览（主列）与关键表现（辅列）结构。三个区域均复用现有组件、设计令牌与状态呈现，不新增颜色、字体、圆角或卡片语言。在窄屏下，摘要与分析区均按现有单列响应式规则排列。

## 代码边界

- `PersonalReviewPage.tsx` 仅调整标签集合、视图分支与概览组合关系；地图分析继续使用已加载的同赛季 `SeasonAnalysis`。
- `reviewNavigation` 的视图类型、标签解析和 URL 构建移除 `roles`、`maps`；解析旧值时回退为 `overview`。
- `review.css` 仅将概览网格的职责与地图分析区设为跨列显示，保留既有面板与响应式规则。
- 不改动 API、共享类型、后端、数据库或同步逻辑。

## 验证

- 扩展战报导航回归测试，断言不再存在 `roles`、`maps` 标签，概览按职责与英雄、赛季摘要、地图的顺序渲染完整分析，旧 `view=roles`、`view=maps` 均回退概览。
- 运行相关前端回归测试、前端构建、`git diff --check`，并检查工作树只包含本切片文件。
