# 第八阶段指挥台赛季同步设计

## 目标

第八阶段把指挥台从“登录和同步设置页”升级为赛季数据抓取与本地多赛季状态管理入口。

核心目标：
- 固定支持 S21、S22、S23 三个赛季。
- 指挥台负责登录状态、单季同步、本地赛季数据健康度展示。
- 对局、战报、排行、好友分析等页面继续保留各自的赛季筛选，不引入全局当前赛季。
- 同步、失败、健康状态全部用中文展示，并且不暴露 token、cookie、customerToken、raw 玩家隐私 ID 或原始请求参数。

## 已确认决策

- 赛季列表固定为 `21`、`22`、`23`。
- 不做“同步全部赛季”按钮。
- 不做全局当前赛季状态。
- 每个功能页自己保留独立赛季筛选。
- 第七阶段角斗资产校对留下尾巴；后续需要真实数据时再做资产覆盖报告和人工校对。

## 非目标

- 不重做网易大神登录流程。
- 不改变凭据存储格式。
- 不读取或显示 `data/.dashen_credentials.json`、浏览器 profile、cookie 或 token 原文。
- 不新增动态赛季发现接口。
- 不在第八阶段第一轮重做对局、战报、排行、好友分析页面布局。
- 不把角斗装备、异能、地图资产校对并入第一轮。

## 指挥台信息架构

指挥台保留当前账号区和登录操作，但同步区改为固定三张赛季卡片：

- `S21`
- `S22`
- `S23`

每张赛季卡片显示：
- 本地对局数。
- 本地详情数。
- 普通对局数。
- 角斗对局数。
- 失败详情数。
- 最近同步或导入时间。
- 数据覆盖状态。
- 单季同步按钮：`同步 S21`、`同步 S22`、`同步 S23`。

卡片状态建议：
- `可同步`：登录凭据可用，当前没有该赛季同步任务。
- `同步中`：该赛季正在同步，显示进度。
- `需要登录`：没有可用凭据，同步按钮禁用。
- `有失败详情`：同步完成但存在失败详情，显示失败数量和最近错误摘要。
- `无本地数据`：该赛季尚未导入或同步过。

## 同步交互

用户点击某个赛季卡片的同步按钮后：

1. 前端调用现有 `sync_season` Tauri 命令，传入对应赛季号。
2. 指挥台只把该赛季卡片标记为同步中。
3. 同步进度事件继续使用现有 `sync-progress`，但前端要能把进度归属到当前同步赛季。
4. 同步完成后刷新 S21、S22、S23 三个赛季的数据状态。
5. 同步失败时只显示脱敏中文错误；如果像凭据失效，应提示重新登录。

不做并发多赛季同步。第一轮可以禁用其他赛季同步按钮，避免两个同步任务同时写库和混淆进度。

## 后端状态模型

现有 `get_onboarding_status(season)` 适合单个输入赛季，但第八阶段需要指挥台一次拿到固定三季状态。

建议新增或扩展一个指挥台状态 DTO，包含：

- 凭据状态。
- 本地数据库健康状态。
- 固定赛季状态列表。
- 最近同步总体时间。
- 可进入产品页面的基础判断。

每个赛季状态字段：
- `season`
- `matchCount`
- `detailCount`
- `normalMatchCount`
- `arenaMatchCount`
- `failedDetailCount`
- `lastSyncedOrImportedAt`
- `coveragePercent`
- `latestErrors`

`latestErrors` 只允许包含脱敏后的中文错误摘要，不包含 URL 查询参数、token、cookie、customerToken 或原始响应体。

## SQLite 多赛季兼容

第八阶段优先保持同一个 SQLite 数据库承载多赛季。

原则：
- 同步 S21 不删除 S22/S23。
- 重复同步同一赛季应幂等更新，不让对局、详情、玩家投影重复膨胀。
- 所有页面查询必须按各自页面选择的 season 过滤。
- 后端测试要覆盖至少两个赛季同时存在时的隔离行为。

需要重点检查：
- 对局列表和详情查询。
- 战报查询。
- 排行查询。
- 好友分析查询。
- 本地 overview/status 查询。
- 筛选项生成逻辑。

## 页面兼容策略

不做全局当前赛季。

各页面策略：
- 对局页：保留自己的赛季筛选；筛选项兼容 S21/S22/S23。
- 战报页：保留自己的赛季选择。
- 排行页：保留自己的赛季选择。
- 好友分析页：保留自己的赛季选择。
- 指挥台：只展示和同步赛季数据，不驱动其他页面的筛选状态。

如果某页面当前默认 S22，第一轮可以保持默认行为，但后端必须支持 S21/S22/S23 查询隔离。

## 隐私和安全约束

硬性约束：
- 不在 UI、日志、测试输出、报告中打印 `OW_DASHEN_TOKEN`、`customerToken`、cookie、浏览器 storage 或本地凭据内容。
- 不读取 `data/.dashen_credentials.json` 和 `data/chrome-dashen-profile/` 做人工审计。
- 后端错误消息必须继续走脱敏逻辑。
- 指挥台只能展示凭据是否可用、保存时间、角色 ID 的安全摘要，不能展示 token 值。
- 同步失败详情只展示用户可操作原因，不展示原始请求 URL、请求参数或响应体。

## 第一轮切片

第一轮只做“固定三赛季状态 + 单季同步入口”。

范围：
- 后端提供 S21/S22/S23 的本地数据状态。
- 指挥台展示三张赛季卡片。
- 每张卡片可以单独触发同步。
- 同步时显示该季进度。
- 同步完成刷新三季状态。
- 现有页面不做大改，只补必要测试确认多赛季不混。

验收标准：
- 新安装或空库时，三张卡片都显示无本地数据。
- 已有 S22 数据时，只 S22 卡片显示数据，S21/S23 不伪造数据。
- 点击 `同步 S22` 只同步 S22。
- 同步完成后 S22 卡片的对局数、详情数、最近同步时间更新。
- 没有登录凭据时，三个同步按钮禁用并显示需要登录。
- 对局、战报、排行、好友分析仍按各自页面的 season 选择读取数据。
- 所有新增可见文本为中文。

## 第二轮切片

第二轮做多赛季兼容回归。

范围：
- 导入或构造 S21/S22 两季测试数据。
- 确认各查询不会混赛季。
- 补齐筛选项生成逻辑。
- 修正默认赛季和空状态文案。

验收标准：
- S21 查询不返回 S22 数据。
- S22 查询不返回 S21 数据。
- 多赛季存在时，各页面筛选结果稳定。
- 重复导入同一赛季不会造成重复膨胀。

## 第三轮切片

第三轮做同步失败和部分失败体验。

范围：
- 每季卡片显示失败详情数。
- 展示最近错误摘要。
- 凭据类失败引导重新登录。
- 网络或上游失败提示稍后重试。

验收标准：
- 详情部分失败不阻塞已成功数据进入 SQLite。
- 失败摘要脱敏。
- 用户能明确知道是重试同步还是重新登录。

## 第七阶段尾巴

第七阶段剩余的角斗资产校对不阻塞第八阶段启动。

尾巴包括：
- 角斗地图真实数据校对。
- `modGuids` / `traitGuids` 装备和异能映射校对。
- `assets/stadium/manifest.json` 覆盖率补齐。
- 角斗段位图标 resolver 的真实数据复验。

这些工作依赖更多真实同步数据。第八阶段把赛季同步和多赛季状态做稳后，再开启真实角斗资产覆盖报告会更合适。
