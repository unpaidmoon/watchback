# 生涯三职责 MMR：本地大样本权重研究与影子模型计划

日期：2026-07-13

## 1. 目标与不可越过的边界

本阶段只研究重装、输出、支援三套独立表现修正模型。正式 MMR 继续使用已上线的胜负、对局强度、不确定性与单场上限主干；在本计划全部晋级门槛通过前，`performance_adjustment` 必须保持为 `0`。

研究数据来自本地 SQLite 的非敏感数值投影。训练、诊断和报告只允许输出聚合计数、覆盖率、分布、系数与验证指标，不输出玩家 ID、比赛 ID、GUID、姓名、原始 JSON 或凭据。备份库不作为独立样本重复训练。

当前只读聚合审计基线为 2,363 场、5 个动态发现赛季、1,808 场普通模式、18,658 条普通模式玩家投影；`final_hit` 与 `healing_taken` 覆盖充足。该结论仅说明可以开展研究，不代表任何候选权重已经可用。

## 2. 研究数据投影与语义审计

为每个比赛、职责片段生成一行版本化、可重建的训练投影，至少包含赛季、时间、模式、职责、英雄类别、时长、胜负、赛前预期胜率、数据质量和候选统计。只保存稳定哈希或内部替代键用于同场聚类，导出报告时移除这些键。

普通模式先审计精确英雄时长是否存在及覆盖率：有精确英雄时长时按职责片段拆分；仅有最终英雄时保留低质量胜负样本，但不启用英雄表现特征。英雄时长缺失不能靠面板数值猜职责。

角斗仅取排序后的最后一个真实有效回合。分别统计 `RoundLocal`、`Cumulative`、`Ambiguous`：局部值按最后回合时长换算，累计值按全场时长换算，口径不明时只保留胜负主干并关闭表现特征。全部回合累计/平均只作为证明错误的对照实验，绝不进入正式候选。

`healingTaken` 的产品数据语义确认为受到队友治疗量。由于它是整场当前玩家统计，第一轮资源债务研究只使用单英雄比赛；多英雄比赛不得复制到各英雄片段，也不得按时长线性分摊。

所有计数先换算为每 10 分钟，再按以下顺序做中位数/MAD 稳健标准化并截断到 `[-3, 3]`：

```text
英雄 + 模式 + 赛季
→ 英雄 + 模式
→ 英雄
→ 职责 + 模式
```

少于 30 行不建立英雄赛季基线，至少 100 行才标记为高置信基线。普通模式与角斗不共享表现基线。

## 3. 三职责候选特征

共同拆分击杀，避免重复计分：

```text
finalBlows = final_hit
nonFinalEliminations = max(kill - final_hit, 0)
```

最后一击系数必须为正，且单次价值高于非最后一击参与。固定其他处理后网格搜索倍率 `1.00、1.25、1.50、1.75、2.00`，同时报告按英雄、模式、赛季的稳定性。

- 重装：最后一击、非最后一击参与、助攻、英雄内伤害/减伤、前线转化、目标时间、死亡、无效承伤、资源债务。减伤只能在英雄内部比较，避免末日铁拳、路霸等英雄因机制被系统性压低。
- 输出：最后一击、非最后一击参与、助攻、英雄内伤害、伤害转化、目标时间、死亡、无效伤害、资源债务。高伤害但击杀转化低时不得继续获得等比例奖励。
- 支援：助攻、最后一击、非最后一击参与、英雄内治疗/伤害、生存、目标时间、死亡、异常承伤、资源债务。由于净化、复活、加速、睡眠等价值缺失，支援修正采用三者中最保守的上限。

## 4. 受到治疗与资源债务实验

依次比较五个互斥方案：不使用、直接负权重、英雄内归一化负权重、超额受到治疗、资源转化债务。后两项定义为：

```text
expectedHealingTaken = f(hero, role, mode, duration, damageTaken, deaths, teamHealing)
excessHealing = max(0, actualHealingTaken - expectedHealingTaken)
resourceDebt = excessHealingZ * max(0, 1 - normalizedConversion)
```

`normalizedConversion` 按职责使用击杀/助攻/目标贡献、前线转化、伤害转化或支援有效产出。获得大量治疗且完成高产出时不扣或少扣；高额超额治疗、死亡高且产出低时才产生负向债务。受到治疗少不得因为分母小获得奖励。资源债务系数必须为负，但需通过验证后才具备候选资格。

## 5. 训练目标、切分与防泄漏

训练目标为 `actualResult - expectedWinRate`，而非直接拟合胜负。每个职责分别训练并至少比较：仅胜负、加对局强度、逐步加入死亡/最后一击/非最后一击/英雄内指标/资源债务，以及完整交互模型。

验证采用五个严格向前滚动的时间折：每折只用过去训练、用随后时间段验证。任何同一 `match_id` 的玩家行和职责片段只能处于同一折；英雄/赛季基线、缺失值处理、标准化参数和模型超参数必须只由训练窗口拟合，再应用到验证窗口。

除五个时间折外，分别执行逐赛季留一和逐英雄留一验证。赛季、英雄、模式和角斗口径的任何汇总统计不得引用被留出的验证样本。若同一原始比赛因重复同步出现多份记录，先按稳定业务键去重，禁止跨折重复。

## 6. 稳定性与偏差评估

对每个候选执行 1,000 次按比赛聚类的 bootstrap，同一比赛的所有玩家行和职责片段整簇重采样。报告系数方向稳定率、置信区间、AUC、Brier Score、校准误差，以及相对仅胜负主干的增益。

同时检查：

- 五个时间折是否至少四折改善；
- 留一赛季、留一英雄是否出现系统性恶化；
- 每英雄、每职责、每模式平均修正及长尾；
- 三职责长期平均表现修正是否接近 0；
- 高伤害、高治疗、低死亡策略是否可被刷分；
- 数据质量下降或英雄基线回退时是否自动收缩到 0。

约束最后一击和非最后一击系数为正、死亡和资源债务系数为负，且单项贡献不超过表现修正总量的 35%。

## 7. 影子模型存储与运行

通过离线门槛的候选创建新的非激活 `model_version`，保存算法名、规范化配置、特征版本、训练窗口、权重摘要哈希和创建时间。影子事件与基准事件分版本存储，完整历史确定性重放；正式页面仍读取激活的基准版本。

影子诊断只存聚合指标：按职责/英雄/模式/赛季的校准、平均修正、上限命中率和数据降级率。不得把原始面板 JSON、其他玩家标识或凭据复制进模型表。导入失败时保留上一套完整影子结果，不影响基础比赛数据和正式 MMR。

竞技表现修正最终上限为基础变化的 `±10%` 且绝对值不超过 `±3 MMR`；快速为 `±10%` 且不超过 `±1 MMR`；支援竞技建议进一步限制为 `±2 MMR`。修正不得反转胜负方向，最终总变化仍受竞技 `±30`、快速 `±10` 单场职责上限约束。

## 8. 晋级门槛与交付物

只有同时满足以下条件才允许提议激活新模型版本：

1. 相对仅胜负主干的验证指标稳定改善，五个滚动时间折至少四折改善；
2. 1,000 次比赛聚类 bootstrap 中关键系数方向稳定率至少 90%；
3. 赛季留一和英雄留一没有系统性涨分/掉分群体；
4. 三职责、各模式长期平均表现修正接近 0，且不存在显著职责偏差；
5. 角斗最终回合规则、英雄基线回退、数据质量降级和单场上限全部通过自动测试；
6. 未发现刷伤害、刷治疗、消极保命或吃资源却无转化的可利用路径；
7. 影子期预测校准、波动和偏差均优于或不劣于基准模型。

若任一门槛失败，生产 `performance_adjustment` 继续为 `0`，候选只保留在离线报告或影子版本。交付物包括聚合字段审计、数据字典、五折/留一/bootstrap 报告、候选权重表、偏差报告、影子模型配置与明确的晋级/拒绝结论。
